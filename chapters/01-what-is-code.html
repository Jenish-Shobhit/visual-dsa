01 / WHAT IS CODE?

What does it mean
to run code?

Forget the computer for a moment. You can do its job with a pencil, a little paper, and three instructions.

Be the machine.

Write down the number 2. Add 3 to it. Then say the result out loud.

You probably said “five.” But notice that you did two different things: you remembered a number, and then you showed it to someone. A number sitting in your notebook isn’t the same as a number spoken aloud.

Our small machine has a notebook called memory, and a place to show results called output. Here are its instructions. What will it show?

    A line can read before it writes. The two moments are separated so you can see both.

    Change the instructions yourself

    The equals sign is a small action.

    Look at total = total + 3. In a maths equation, that would be impossible: a number can’t equal itself plus three.

    Here, = means replace what you remember. Read the old total on the right, add three, and write the result under the name on the left.

    Read 2→Calculate 2 + 3→Remember 5

    The machine doesn’t remember the equation. It remembers the new number. That is why we separate “read” and “write” in the experiment.

    Now make it say the wrong thing.

    What if we ask the machine to show total before we add three?

    Explain what happened

    show(total) copies the value that exists at that moment. It shows 2. The later addition changes memory to 5, but it cannot change an output already produced. A program is a sequence of actions, and their order matters.

    This is the first useful way to read code: ask “What exists now, and what will this instruction change?” You don’t have to guess what the author meant. Follow the rules.

    But there is no paper inside a computer.

    Right. The notebook is a model. A physical computer stores information using things that can be told apart—such as two different electrical states. We can label those states 0 and 1.

    One switch gives you two possibilities. Four switches give you sixteen different patterns. Try making the number 9 below.

    Our letter agreement is A = 0, B = 1, …, P = 15. It is invented for this experiment; real text encodings use their own rules.

    When you change from “number” to “letter,” the switches don’t change. Only our agreement about how to read them changes. The pattern 1001 can mean the number 9 or the letter J in our little alphabet.

    Instructions work the same way: a machine is built to respond to particular patterns. An interpreter or compiler connects the rules of a programming language to operations a machine can perform. A source line may require many smaller operations.

    You can inspect those smaller operations in the instruction machine. Treat it as a magnifying glass on this lesson, and return here when you’re ready.

    Can you make the idea work somewhere new?

    Without running this program, write down both the remembered value and the output at the end:

    score = 4
show(score)
score = score * 2

    Walk through the answer

    The first line stores 4. The second copies 4 to output. The last reads 4, doubles it, and stores 8. So memory ends at 8 and output remains 4. Remembering and showing are different actions.

    Explain it to someone who hasn’t coded.

    This is for your own thinking. Your explanation stays on this device.

    Compare your explanation

    A useful explanation says when each number is remembered and when it is shown. It distinguishes the current notebook from what someone already saw. If you can explain why the later addition cannot change an earlier output, you have the central idea.

    We won’t score your wording. Try explaining it aloud, then change your example and see whether your explanation still works.

    TAKE THIS WITH YOU

    Code gives rules for changing a state. To understand a program, follow what it remembers, what it does next, and what it shows.

    One more turn of the idea

    2. Put show(total) before total = 2. What information is missing? Try it in the editor.
