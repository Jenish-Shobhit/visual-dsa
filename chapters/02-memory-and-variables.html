02 · Keep a result for later

Memory and variables.

A program needs to remember what happened earlier. Watch what survives when one instruction gives a value to another name.

About 9 minutes · Predict, then trace two small programs

Imagine counting tickets at a door. You have 2 now, but a later instruction will need that count. A variable gives the current value a name so the program can find it again. In this little program, show displays values:

let tickets = 2;
let spare = tickets;
tickets = tickets + 1;
show(tickets, spare);
Before tracing: what will appear?

Choose a pair. Think about what the second line saves before the third line runs.

Keep that choice in mind. To trace an assignment, read the right side using the state you have now, calculate its value, then write that value under the name on the left. The third line reads 2 before writing 3.

Now the count is a collection of two prices. In JavaScript, square brackets create an array, and [0] selects its first item:

let prices = [4, 7];
let alsoPrices = prices;
alsoPrices[0] = 9;
show(prices[0]);
Before tracing: what will appear?

Does the second line make another array, or another way to reach one array?

Trace / One line at a time

Use Next through each program. Pause after line two: which value, or which object, did it copy?

What changed?

For the ticket count, the second line copies the number 2. After the last assignment, tickets holds 3 and spare still holds 2. The names do not stay linked. This table is the same trace without pictures:

The price program has a different result because the value copied on line two is a reference to one array. Both names reach that array. alsoPrices[0] = 9 changes its first item, so prices[0] is 9 too. No second array was created by alsoPrices = prices.

Try changing only the third line to alsoPrices = [9, 7]. Now a new array is created and only alsoPrices is made to reach it. The old array still starts with 4. This is the difference between changing an object and changing what one name refers to.

Where the drawing stops.

The boxes and arrows describe JavaScript behavior, not literal boxes in a RAM chip. Real memory stores bits at addresses. A JavaScript engine decides how to represent values, may keep some in registers, and may move objects. The rule you can rely on here is that numbers are copied as numbers, while assigning an array copies a reference to the same mutable array.

This matters when an algorithm says it leaves an input array alone. Editing an array through a second name still changes the caller's array. Making a separate copy first prevents that shared edit, but costs extra memory and work.

TRY

Transfer the rule

  1. Trace let a = [1]; let b = a; b = [2]; show(a[0]);. Which array does a still reach?
  2. Change only b = [2] to b[0] = 2. Predict the new output, then draw the names and arrays.
  3. Starting with left = 1 and right = 2, use a third name temp to swap their values. What would be lost if you wrote left = right first?
Reveal worked answers

1. The third line creates a new array and changes only b. a still reaches the original [1], so the output is 1.

2. The new third line edits the one shared array. Both names still reach it, so the output is 2.

3. temp = left; left = right; right = temp;. Copying 1 into temp first preserves it before left is overwritten.
