Memory and
variables.

A name lets the next instruction find a value left by an earlier one.

About 6 minutes · Use ← → in the figure

Suppose you count two tickets. Later, you need that count again. You can store 2 under the name tickets. The name is a way to refer to a value the program remembers.

tickets = 2
spare = tickets
tickets = tickets + 1

After the first line, tickets holds 2. The second line reads that 2 and stores it under spare. The third reads tickets, adds 1, and puts 3 back under tickets. Now spare still holds 2.

That is the useful surprise: copying a simple number copies its current value. It does not tie the two names together. Changing tickets afterward does not change the number stored under spare.

Think in snapshots.

A variable can hold different values at different moments. To understand a line, look at the snapshot just before it runs. Read every value on the right, work out the result, then update the name on the left. The figure does exactly this.

Memory is the computer's place to keep these values while the program runs. For now, a labeled cell is enough of a model. Later chapters will use many positions together.
