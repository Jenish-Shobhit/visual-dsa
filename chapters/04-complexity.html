07 · After correctness

Complexity.

When the input grows, what work grows with it? Count operations before you compare seconds.

About 9 minutes · Three growth patterns

Suppose you need to check whether a row of names contains Jin. The names are unsorted, so start at the left and compare one at a time. If Jin is missing from 8 names, how many comparisons must the scan make? What if there are 16 names? Make a prediction before reading on.

for each name in names:
    if name == target:
        return true
return false

If Jin is absent, the loop reaches every name: 8 comparisons for 8 names, 16 for 16. We chose a cost model: count name comparisons. The number of seconds on a real machine also depends on factors such as memory and the cost of comparing names. Counting lets us see how the algorithm's work changes when the input grows.

Three ways the work can grow.

The scan touches each of n names once. That is linear work. Now imagine comparing every name with every name, including itself and both orders. There are n × n ordered pairs: quadratic work. Finally, imagine a sorted row where each round discards half the remaining candidates. The number of halving rounds grows logarithmically. We are counting rounds to reach one candidate; a real search can require an additional final comparison.

Predict before using the figure: With 8 names there are 64 ordered pairs. How many are there with 16 names?

What doubled?

At 16 names, the scan makes 16 comparisons. Ordered pairs jump from 64 to 256 because both sides of the pair grew from 8 to 16. Halving takes only one more round: 8 → 4 → 2 → 1 takes three; 16 → 8 → 4 → 2 → 1 takes four. The shapes are n, n², and about log₂ n. These expressions summarize work as the input grows; they are not stopwatch predictions.

Bounds are not cases.

For the scan, finding the target first takes one comparison. Finding it last takes n. “Best case” and “worst case” describe different inputs of the same size. By contrast, O, Ω, and Θ describe kinds of mathematical bounds. They are not synonyms for best, worst, and average.

NotationMeaningExample claim
O(f(n))Eventually at most a constant times fWorst-case scan is O(n)
Ω(f(n))Eventually at least a constant times fWorst-case scan is Ω(n)
Θ(f(n))Both bounds matchWorst-case scan is Θ(n)

A linear algorithm is also technically O(n²), because a quadratic function is an upper bound on it. Saying Θ(n) is more informative when the tight growth is known. Always state the input and the case: “worst-case comparisons for a scan over n items” is a meaningful claim.

Ignore constants carefully.

Suppose one algorithm uses 3n + 8 simple operations. Another uses n². We write the first as Θ(n) and the second as Θ(n²) because for sufficiently large n, the fastest-growing part controls the shape. That does not say the linear algorithm is faster on every small input. Constants, memory access, and implementation can reverse the practical result for sizes you actually use.

Space has growth too. A scan may use a few variables regardless of n: Θ(1) extra space. Making a copy of the input needs Θ(n) extra space. If an algorithm calls itself, its active calls also consume space. We count these separately from the input storage.

The reusable idea: Specify the input size, the operation, the case, and whether you mean time or extra space. Then count. The notation is a summary of that reasoning.

One expensive step can still be affordable.

Sometimes an operation is occasionally expensive, yet a long sequence is cheap per operation. A growing array may copy all its elements during a resize, but if it doubles capacity each time, most appends do no copying. The deeper amortized analysis study proves the total cost across many appends. That is a different question from asking how expensive one unlucky append is.

Transfer the idea

  1. A scan of [8, 3, 5, 1, 9] seeks 9. Count comparisons on this input. Then give the best and worst counts for any target.
  2. At n = 10 and n = 100, compare 2n + 5 with n². At which small positive values of n is the quadratic count lower? Why does that not change the growth classes?
  3. A program loops over all n items and, for each one, scans the first ten items only. Give its growth when n ≥ 10, and name the operation you counted.
Reveal worked answers

1. It compares with all five values before finding 9: five comparisons. If the target is first, one comparison; if it is last or absent, five.

2. At 10, the counts are 25 and 100; at 100, they are 205 and 10,000. At n = 1, 2, 3, n² is smaller than 2n + 5. A small-input crossing does not change which expression grows faster for large n.

3. Count inner comparisons: ten per outer item, so 10n. With a fixed ten, this is Θ(n).
