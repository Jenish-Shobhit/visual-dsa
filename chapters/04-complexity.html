07 · After correctness

Complexity.

When the input grows, what work grows with it? Count operations before you compare seconds.

9 minute lesson · Three growth patterns

Suppose you need to check whether a row of names contains Jin. With four names, a scan may read four. With forty, it may read forty. If the target is last or absent, there is one comparison per item. For an input of length n, that is n comparisons.

for each name in names:
    if name == target:
        return true
return false

We have chosen a cost model: count comparisons, and pretend each comparison has a fixed cost. That model ignores file loading, caching, processor speed, and many other real effects. It is still useful because it exposes how work changes as n changes. Always ask what an operation costs before treating it as one step; comparing two enormous strings is not necessarily constant work.

Three shapes of growth.

A scan can touch each of n values once: linear work. A double loop that pairs every item with every item makes n × n comparisons: quadratic work. If a step can discard half of the candidates, there are only about log₂ n halving rounds before one candidate remains: logarithmic work. The figure shows these three counts for inputs whose size doubles each step.

Predict first: At n = 8, a scan uses 8 checks and all ordered pairs use 64 comparisons. What happens at n = 16? How many halvings take 16 candidates down to one?

Logarithms answer a simple reverse question: “How many times must I divide by 2 to get down to one?” From 16: 16 → 8 → 4 → 2 → 1, so four halvings. Binary search will use this idea, though the exact number of comparisons may include a final check. The exact count depends on the algorithm; the logarithmic shape is the point.

Bounds are not cases.

For the scan, finding the target first takes one comparison. Finding it last takes n. “Best case” and “worst case” describe different inputs of the same size. By contrast, O, Ω, and Θ describe kinds of mathematical bounds. They are not synonyms for best, worst, and average.

NotationMeaningExample claim
O(f(n))Eventually at most a constant times fWorst-case scan is O(n)
Ω(f(n))Eventually at least a constant times fWorst-case scan is Ω(n)
Θ(f(n))Both bounds matchWorst-case scan is Θ(n)

A linear algorithm is also technically O(n²), because a quadratic function is an upper bound on it. Saying Θ(n) is more informative when the tight growth is known. Always state the input and the case: “worst-case comparisons for a scan over n items” is a meaningful claim.

Ignore constants carefully.

Suppose one algorithm uses 3n + 8 simple operations. Another uses n². We write the first as Θ(n) and the second as Θ(n²) because for sufficiently large n, the fastest-growing part controls the shape. That does not say the linear algorithm is faster on every small input. Constants, memory access, and implementation can reverse the practical result for sizes you actually use.

Space has growth too. A scan may use a few variables regardless of n: Θ(1) extra space. Making a copy of the input needs Θ(n) extra space. If an algorithm calls itself, its active calls also consume space. We count these separately from the input storage.

The reusable idea: Specify the input size, the operation, the case, and whether you mean time or extra space. Then count. The notation is a summary of that reasoning, not a substitute for it.

One expensive step can still be affordable.

Sometimes an operation is occasionally expensive, yet a long sequence is cheap per operation. A growing array may copy all its elements during a resize, but if it doubles capacity each time, most appends do no copying. The deeper amortized analysis study proves the total cost across many appends. That is a different question from asking how expensive one unlucky append is.

Practice without peeking

  1. A scan of [8, 3, 5, 1, 9] seeks 9. Count comparisons in this input, then give best and worst case counts for any target.
  2. At n = 10 and n = 100, compare 2n + 5 with n². At what small values might the quadratic formula be lower? Why does that not change the asymptotic classes?
  3. A program loops over all n items and, for each one, scans the first ten items only. Give its time growth if n ≥ 10, and state your counted operation.
