Decisions
and loops.

A program can choose one path, then keep choosing whether to take it again.

About 9 minutes · Try a new starting value

Suppose you have three tickets to hand out. You want a program to show each ticket count as you hand one out, then show 0 when none remain. Before reading the code, predict the output if you begin with zero tickets: does the program hand one out, or go straight to the final 0? Keep that prediction in mind while you trace the instructions.

let tickets = 3;
if (tickets > 0) {
  show(tickets);
}

Read the condition aloud: “Is the current value of tickets greater than zero?” With three tickets it is true, so the instruction inside the braces runs and shows 3. With zero tickets it is false, so that instruction is skipped. The braces mark the instructions controlled by the decision. We use show as the same simple output command from the first lesson; in JavaScript you would usually use console.log.

An if makes a choice once. It does not wait for tickets to change, and it does not return to check again. An else can provide a different path when the condition is false, but exactly one of the two paths runs. That is enough for one ticket decision; it cannot handle a changing count on its own.

Let the decision repeat.

A while loop returns to its condition after running the body. As long as the condition is true, it enters the body again. Here is the complete ticket program:

let tickets = 3;
while (tickets > 0) {
  show(tickets);
  tickets = tickets - 1;
}
show(tickets);

Do the first trip by hand: the test reads 3 > 0, so the body shows 3 and changes the stored count to 2. Now pause. The next thing the program does is test 2 > 0, not show 2 automatically. Continue the same steps and predict where it exits before opening the figure.

Notice the order. The loop tests before every trip through the body, including the first. The subtraction changes the value used by the next test. Without it, a start of 3 would leave the condition true forever: an infinite loop. The loop does not “know” that three trips were intended. It simply follows the condition and updates you wrote.

What changes, and what stays true?

The figure shows 3, 2, 1, 0 when you start at 3: three visits to the body, followed by the instruction after the loop. The final 0 is shown outside the loop. At the top of each trip, the count is a positive whole number. Each trip reduces it by one, so it cannot keep passing the test forever. The count stays a nonnegative whole number throughout; that repeated truth is a simple loop invariant.

If you tried 0, the first test was false and the body ran zero times. The final instruction still showed 0. Compare that with a start of 1. Changing only the starting value reveals exactly where the loop begins and ends.

A loop can also count upward. If you start at i = 0, test i < 4, and add one each trip, the body sees 0, 1, 2, 3. It never sees 4: the condition is false when i reaches 4. That “one past the last position” boundary will matter when we visit every position in an array.

Misconception check: A while condition is not a background monitor. The program reaches the test at a specific point, computes true or false from the state at that moment, and either enters or exits. Any update made in the body is only considered at the next visit to the test.

Keep the mental picture: condition → perhaps enter → do one body → update state → return to condition. The condition controls whether another trip begins; it is not an instruction that runs only at the start.

TRY / 03

Practice on paper

  1. Start with n = 4. Trace the output of while (n > 1) { show(n); n = n - 2; }. What is n when the loop ends?
  2. A loop starts at i = 0 and adds 1 each trip. Write a condition that lets the body run exactly five times. List the values of i the body sees.
  3. The ticket loop accidentally says tickets = tickets + 1. For a start of 2, explain why it does not stop. Give one change that repairs it.
Reveal worked answers

1. The body sees 4, then 2. It stores 2, then 0; 0 > 1 is false, so the final n is 0.

2. Use i < 5. The five body values are 0, 1, 2, 3, and 4.

3. Starting at 2, each trip makes tickets larger, so tickets > 0 remains true. Change + to -, or change the loop’s intended state and condition together.
