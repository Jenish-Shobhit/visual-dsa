Functions
and references.

A call pauses one task to do another. What travels into that task matters.

About 10 minutes · Two connected experiments

Suppose a ticket desk must double a price for several orders. We could repeat the multiplication wherever we need it, but giving that small job a name lets us call it again. In this example, show displays values:

function double(n) {
  return n * 2;
}

let price = 4;
let total = double(price);
show(price, total);
Predict before tracing

After the call, which pair will show display? Choose, then step through the number experiment below.

A call pauses the caller at double(price). The value of price is read, and a new local name n receives that value. return sends a result to the waiting caller, which stores it in total. The caller then continues at show. That is the whole trip to watch in the trace.

Now use the same call idea with a collection. Read [4, 7] as a two-item array and [0] as its first item:

function touch(items) {
  items[0] = 9;
  items = [1, 2];
}

let first = [4, 7];
touch(first);
show(first[0]);
Predict before tracing

What appears after touch returns? Decide whether each line changes an array or changes a local name.

    Follow the return trip.

    Defining double does not run it. At the call, the caller has price = 4 and waits for total. The value 4 is copied into local n. The function calculates 8 and return sends it back. The local name is finished; the caller saves 8 in total and continues. That explains the displayed pair: 4, 8.

    Caller pausesprice = 4
    Local namen = 4
    Return8
    Caller resumestotal = 8

    In the second call, first contains a reference to array A1. The argument value copied into local items is that reference, so both names reach A1. items[0] = 9 edits A1. Then items = [1, 2] creates A2 and makes only the local name reach it. The caller still reaches A1, now [9, 7], and displays 9.

    That second line in touch cannot undo the earlier edit. When the function returns, its local name goes away. A2 has no surviving reference in this example and can be reclaimed later; JavaScript does not promise exactly when.

    Where this model stops. The caller and local cards describe which names are usable during a call. A JavaScript engine can store or optimize them in different physical places. JavaScript passes argument values; for an array, that value is a reference. This is why the function can edit a shared array but assigning a new array to items does not change the caller's first.

    A useful function promise says what it reads, what it returns, and what it may change. double returns a new number. touch also changes an array that its caller can see. Later, an algorithm that calls a helper must account for both kinds of effect.

    Change one step

    1. Call double twice: let x = double(3); let y = double(x);. At the second call, what is the argument? What are x and y afterward?
    2. In touch, move items = [1, 2] before items[0] = 9. Predict first[0] before revealing the answer. Which array receives the edit?
    3. Suppose function change(n) { n = 9; return n; } and let x = 4; let y = change(x);. Draw the caller and local names. What do they hold after return?
    Reveal worked answers

    1. The first call returns 6, so the second call receives 6 and returns 12. The caller has x = 6 and y = 12.

    2. The local name first switches to new array A2, then edits A2. first still reaches A1, whose first item remains 4.

    3. The local n starts at 4, changes to 9, and returns 9. The caller's x remains 4; y receives 9.

    Check the idea in your explanation

    A call binds argument values to local names and remembers where to resume. A returned value resumes the caller’s expression. Editing an object reached through a copied reference can affect the caller even when that object is not returned. Reassigning the local name does not reassign the caller’s name.
