Functions
and references.

A call pauses one task to do another. What travels into that task matters.

About 10 minutes · Two connected experiments

The ticket program repeats one action. What if you need the same calculation in several places? Give that task a name. A function is a reusable group of instructions; calling it runs those instructions and then returns to where the call was made.

function double(n) {
  return n * 2;
}

let price = 4;
let total = double(price);
show(price);  // 4
show(total);  // 8

Defining double does not run its body. The run begins at double(price). The expression in parentheses supplies an argument, the current value of price. The function creates a local name, the parameter n, and gives it that value: 4. Inside the function, return n * 2 sends 8 back to the waiting call. The caller stores 8 in total.

Imagine two work surfaces. The caller has price and total. While the call runs, a fresh surface holds n. The caller pauses; the function uses its own local names. When it returns, that temporary surface disappears and the caller continues. This is a call frame. Later, when functions call themselves, many frames can wait at once.

Changing local n does not rewrite price. The argument's numeric value was copied into a new local name. If double omitted return, the call would finish without producing the number 8; in JavaScript its result would be undefined.

Now share a collection.

A number like 4 fits in a name's value. A collection has its own place in memory. We will study indexed collections fully in the next chapter; for now, read [4, 7] as a two-slot collection and [0] as its first slot. A name can hold a reference that locates that collection. Copying the reference gives another name a route to the same collection.

function touch(items) {
  items[0] = 9;
  items = [1, 2];
}

let first = [4, 7];
touch(first);
show(first[0]);  // 9

The call copies the reference in first into local items. Both names now locate one collection, shown as A1 in the figure. items[0] = 9 changes A1 itself, so the caller can see the change through first. Then items = [1, 2] makes a new collection, A2, and changes only the local name to point there. It does not undo the edit to A1, and it does not change where first points.

    The distinction that prevents many bugs.

    There are two different actions here. Mutating a collection changes the thing at the end of a reference; every name that still reaches it sees the change. Rebinding a name changes which thing that one name reaches. The second action does not move every other name. In JavaScript, arguments are passed as values. For a collection, the value being copied is a reference. Saying “the whole collection was copied” would predict the wrong result.

    Misconception check: “JavaScript passes objects by reference.” The precise rule is pass-by-value: the value in this case is a reference. That is why a function can mutate the shared object, yet cannot make the caller’s variable point at a new object by rebinding only its parameter.

    This memory picture is deliberately simple. A real engine manages objects, addresses, and storage in more complicated ways. A local frame is a language-level account of a call, not a promise that a particular engine uses one physical stack slot for every source variable; optimization can change the layout. The useful contract for ordinary JavaScript code is stable: two names may refer to one mutable object, and assigning a new object to one name does not retarget the other.

    Try changing First slot and Replace it with in the lab. The exact numbers change, but the relationship does not. The caller's first still points to A1 after touch returns. A2 was created during the call and no surviving name points to it in this example. It becomes eligible for garbage collection, but the language does not promise the exact instant storage is reclaimed.

    Functions make a program easier to reason about when each has a clear promise: what inputs it reads, what value it returns, and what shared objects it may change. A function like double only returns a value. A function like touch also changes an input object. When you read a call, ask which kind of effect to expect.

    TRY / 03

    Practice on paper

    1. Write a function triple(n) that returns three times its input. Trace let x = 2; let y = triple(x);. What does each name hold afterward?
    2. Suppose a = [2, 5] and b = a. After b[1] = 8, draw the two names and the collection. What is a[1]?
    3. In touch, move items = [1, 2] before items[0] = 9. Which collection changes now? What will first[0] be?
    Reveal worked answers

    1. triple can return n * 3. The call binds local n to 2, returns 6, and leaves the caller with x = 2 and y = 6.

    2. Both names reach the same collection, now [2, 8], so a[1] is 8.

    3. The rebinding first makes items reach the new collection. The following write changes that new collection, so the original collection reached by first is still [4, 7]; first[0] is 4.
