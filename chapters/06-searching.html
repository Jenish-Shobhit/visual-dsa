After sorting · A new use for order

Searching.

If the values are ordered, one comparison can tell you where an answer cannot be.

About 12 minutes · Try missing values and duplicates

Find 23 in this row: [3, 8, 12, 17, 23, 29, 35]. A left-to-right scan will work. It checks 3, then 8, and keeps going until it reaches 23. But the row is sorted. If you look at the middle value, 17, you immediately know that 23 cannot be at the middle or anywhere to its left. Four positions disappear after one comparison.

middle of [3, 8, 12, 17, 23, 29, 35] → 17
23 > 17, so keep [23, 29, 35]
middle of [23, 29, 35] → 29
23 < 29, so keep [23]
middle of [23] → 23

This is binary search: keep a range of positions where the answer might still be, look at its middle, and discard the half that has become impossible. The word might matters. We do not need to know where the answer is yet; we need to know which positions are still plausible.

The promise behind each discard.

Let low and high mark the first and last plausible indices. The invariant is: if the target occurs and has not already been found, at least one occurrence lies between low and high. Initially the whole array is plausible. If the middle value is smaller than the target, sorted order proves that every value at or left of the middle is too small; set low = mid + 1. If the middle value is larger, set high = mid - 1. The + 1 and − 1 exclude the middle we just disproved and guarantee progress.

let low = 0, high = values.length - 1;
while (low <= high) {
  let mid = Math.floor((low + high) / 2);
  if (values[mid] === target) return mid;
  if (values[mid] < target) low = mid + 1;
  else high = mid - 1;
}
return -1;

The result -1 means “not found”; it is not a valid array index. If the range becomes empty (low > high), the invariant says no possible location remains. An empty array starts with low = 0 and high = -1, so its loop runs zero times. A one-item array needs at most one comparison.

The sorted precondition is essential. If you run this on [23, 3, 17], seeing 3 in the middle does not justify discarding everything to its left: 23 is there. A trace that happens to work on one unsorted row does not repair the missing reason.

    Why this range is safe

    Use 1, 4, 4, 4, 9 with target 4 to see why “any” and “first” are different questions.

    When “found” is not specific enough.

    Try [1, 4, 4, 4, 9] with target 4. The basic search may stop at index 2, because that middle value matches. If the task asks for the first matching index, index 2 is insufficient: an earlier 4 may remain on the left. Remember index 2 as a provisional answer, then continue searching left. Each later match replaces it with an earlier one. When the range empties, return the remembered index. If no match was ever seen, return -1.

    For this version, the invariant changes slightly: the first occurrence is either the remembered answer or still inside the possible range. Every position below low has been proved smaller than the target. Notice how changing the question changes the loop's stopping rule, even though the same middle comparisons are used.

    Why the work grows slowly.

    After each unsuccessful comparison, at most half the previous range remains. A million positions take at most about twenty halvings because 2²⁰ exceeds one million. That is O(log n) time and O(1) extra space for the iterative code above. The first-match version still halves its range, even when it remembers an answer.

    Two requirements make this possible: the values must be ordered, and the structure must let us reach its middle quickly. An array supports direct indexed access. A linked list, which we will build next, has to follow links to reach its middle; a “binary search” over a linked list loses much of the advantage.

    For one search in an unsorted array, scanning O(n) items is usually a better plan than sorting O(n log n) first and then searching. If you will perform many searches over data that changes rarely, paying once to sort can be worthwhile. Choose the method for the whole workload, not just the one operation that looks fast in isolation.
