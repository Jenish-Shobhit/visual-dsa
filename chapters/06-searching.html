Searching.

Order gives a clue: every comparison can rule out part of the search.

About 7 minutes · Use ← → in the figure

You are looking for 23 in a sorted row: [3, 8, 12, 17, 23, 29, 35]. You could start at the left and read each value. That works even if the row is unsorted, but it can take seven reads.

look at the middle: 17
23 is larger, so ignore 17 and everything left of it
look at the middle of what remains: 29
23 is smaller, so ignore 29 and everything right of it
look at 23

Only three comparisons were needed. The order made each rejected half impossible: if 23 is larger than 17, no value to the left of 17 can be 23. Step the figure and watch the candidate range shrink.

Keep a valid range.

Binary search tracks a low and high index. While low ≤ high, inspect the middle index. If its value is too small, make low = middle + 1. If too large, make high = middle - 1. If equal, the target is found. When low passes high, the target is absent.

Each comparison leaves at most half the previous candidates, so the worst case is O(log n) comparisons. A linear scan is O(n). Binary search needs sorted data and direct access to the middle, which arrays provide. Sorting just to answer one search may cost more than a scan; the benefit grows when many searches share the sorted data.

Decide what “found” means.

If values repeat, a basic binary search may return any matching index. To find the first match, remember a match and keep searching left. Be explicit about this requirement before writing the loop. Also test an empty array, a missing target, and a one-item array.

Practice

  1. Search [2, 5, 8, 11, 14, 17, 20] for 13. Which indices are inspected, and when does the search stop?
  2. A sorted array contains [1, 4, 4, 4, 9]. Adapt the binary search rule to return the first index holding 4.
  3. You must answer one search in an unsorted array of 100 values. Would you scan or sort then search? Explain the work each choice needs.
