Chapter 07 · After searching

Linked lists.

Order can live in links between nodes instead of neighboring positions.

About 7 minutes · Use ← → in the figure

You have a chain with values 4 then 9. You want 7 between them. In an array, you may need to shift later values to make a neighboring slot. A linked list keeps a different kind of order:

head → [4 | next] → [9 | next] → null

Each node has a value and a link named next. The head points to the first node. To reach 9, follow the first node's link; its physical memory location does not have to sit beside 4.

To insert 7, first make its next point to the 9 node. Then change 4's next to point to 7. This order keeps the old path available while you reconnect it. Step through the figure to see which links exist at each moment.

What gets cheaper, and what does not?

Once you already hold a reference to the node before the insertion point, reconnecting a few links takes O(1) work. Finding that node can still take O(n): you may need to follow links from the head one by one. There is no direct “jump to index 50” as with an array.

Removing a node is similar: change the previous node's next to skip it. Handle the head separately because it has no previous node. The last node points to null, marking the end.

Keep the chain intact.

A lost link can make the rest of the list unreachable. Draw the old and new arrows before changing them. Lists trade fast indexed access for easy local rewiring; which matters depends on the operations your program performs.
