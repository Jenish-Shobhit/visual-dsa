Stacks and
queues.

The same arrivals produce different histories when you change which end may release an item.

About 12 minutes · Build your own sequence of operations

Three cards arrive in order: A, then B, then C. If you place each on top of a pile, the first card you can take back is C. If you put each at the back of a line, the first you can take out is A. The cards are the same; only the rule for access changed.

arrivals:       A, B, C
stack removal: C   (latest arrival)
queue removal: A   (earliest arrival)

A stack adds and removes at one end, the top. Its operations are push and pop; its rule is last in, first out. A queue adds at the back and removes at the front. Its operations are enqueue and dequeue; its rule is first in, first out. You cannot remove an arbitrary middle item through either interface without changing the rules.

These are abstract data types: promises about permitted operations and the order of results. They do not specify whether the items live in an array, a linked list, or something else. That distinction is useful. You can reason about an undo stack or a waiting queue before choosing how to store it.

Run the same history through both.

In the lab, every “Add” operation sends one card to both structures. Every “Remove” calls pop on the stack and dequeue on the queue. Build an interleaved sequence, then predict the next exits before stepping. After a removal the structures may contain different cards, even though they have received the same operations.

For example, add A and B, remove once, then add C. The stack first removes B and now contains A, C, with C at the top. The queue first removes A and now contains B, C, with B at the front. A second removal will therefore return C from the stack and B from the queue. The difference persists; it is not only a trick about the first removal.

Access promise

Try removing before any arrival. This lab returns undefined for an empty structure.

The empty case is part of the promise.

What should pop or dequeue do when there is no item? A library may return a special result or throw an error. Our lab chooses undefined and leaves the structure empty. The caller must be prepared for that result. If a queue removes its last item, both its logical front and back must again describe an empty queue; stale references should not pretend an old node is still waiting.

Duplicate labels do not change the rule. If two A cards arrive, a stack still removes the one that arrived later and a queue the one that arrived earlier. Their labels happen to look the same; the order is about item identity and arrival history.

How can the promised operations be fast?

An array can implement a stack by using its end as the top. Appending and removing the last entry are constant work most of the time. If the underlying storage grows by doubling when full, an individual append may copy many entries, but a long sequence of appends has amortized O(1) work per append. Pop is O(1) when it removes the last entry without shifting others.

A queue needs both ends. In a simple contiguous array that physically shifts every surviving entry left after each removal, a dequeue can take O(n). A better array implementation keeps a front index and a back index. In a fixed-size ring buffer, those indices wrap around to the start when they reach the end. For capacity five, front at slot 3 and items A, B, C might occupy slots 3, 4, 0. The physical layout wraps, but the logical order is still A, B, C. Adding D uses slot 1. Track a count, or another full/empty rule, because equal front and back indices alone may be ambiguous. With available capacity, each enqueue and dequeue changes a few positions: O(1).

A linked queue can instead keep references to both head and tail. Enqueue links a new node after the tail; dequeue moves the head forward. Both are O(1) if those references are maintained correctly. The total storage is O(n) for n waiting items, regardless of whether the representation is an array or nodes.

Why choose one?

Undo uses a stack because the most recent edit is the first to reverse. A depth-first exploration can use a stack to continue from the most recently discovered place. A printer queue serves jobs in arrival order. Breadth-first graph exploration uses a queue to visit earlier discoveries before later ones. The access rule shapes the algorithm's behavior; the implementation determines the cost of keeping that rule.
