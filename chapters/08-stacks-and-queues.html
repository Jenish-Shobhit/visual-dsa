A stack permits push at its top and pop from that same end: last in, first out. A queue permits enqueue at its back and dequeue from its front: first in, first out. Step the figure after each arrival, then compare the one removal.

Why restrict access?

The rule makes behavior predictable. An undo history uses a stack because the latest change should be undone first. A waiting line uses a queue because older requests should leave first. Recursion also uses a call stack: each unfinished call waits beneath the one it started.

Both can be built from arrays or linked nodes. With a suitable implementation, adding and removing at the allowed ends takes O(1) work. A queue backed by a plain array should not repeatedly shift every item left; keep front and back positions or use linked nodes instead.

Know the empty case.

What should pop or dequeue do when nothing is there? Choose an explicit result or error. For a queue, also track the front correctly when the last item leaves. These cases are small but reveal whether the access rule is truly implemented.
