Chapter 09 · After stacks and queues

Hashing.

Turn a key into a location, then decide what happens when two keys land together.

About 8 minutes · Use ← → in the figure

You need to find a value by key, perhaps a student's ID. Scanning every entry works, but a table can use the key to suggest a slot. For a small demonstration with five slots, use slot = key % 5, the remainder after dividing by 5.

12 % 5 = 2  → put 12 in slot 2
 7 % 5 = 2  → slot 2 is occupied

Both keys want slot 2. That is a collision, and it is normal: many possible keys must share a limited number of slots. Our figure uses linear probing: try the next slot until an empty one appears. So 7 goes into slot 3.

Look up with the same rule.

To find 7, hash it to slot 2. That slot holds 12, so continue to slot 3 and find 7. If you stop at the first different key, the lookup fails. If you reach an empty slot, 7 is absent, provided deletion has preserved the probe chain.

A real hash function aims to distribute keys evenly. With enough space and a good distribution, insertions and lookups are often O(1) on average. A bad distribution or a very full table can make a long probe chain, up to O(n) work. The load factor is entries divided by slots; growing and rebuilding the table keeps it manageable.

Keys need one stable identity.

Equal keys must hash to the same starting slot. A lookup must compare keys as it probes, because sharing a slot does not make two keys equal. Some tables keep a list at each slot instead of probing; either strategy must handle collisions deliberately.

Practice

  1. With seven slots and slot = key % 7, where do keys 15, 22, and 8 start? Which collide?
  2. Using linear probing, insert 6, 11, and 16 into five empty slots. Draw the final table and trace a lookup for 16.
