Recursion.

What must each call remember while it waits for the smaller call to return?

About 10 minutes · Choose a number and follow every call

Count waiting frames

To multiply the whole numbers from 1 through 4, you could write 4 × 3 × 2 × 1. Notice that the part after 4 is the same kind of task, just smaller: multiply 1 through 3. Name that task factorial(3), and the larger answer becomes 4 × factorial(3).

function factorial(n) {
  if (n === 0) return 1;
  return n * factorial(n - 1);
}
show(factorial(4));  // 24

This is recursion: a function calls itself. It has two essential pieces. The base case answers a small input directly: factorial(0) is 1, the empty product. The recursive case reduces every positive input by one. For nonnegative integers, repeated subtraction must reach zero. Without the base case, or if the recursive input moves away from it, calls continue until the machine runs out of stack space.

Why is factorial(0) = 1 useful rather than 0? It lets factorial(1) compute 1 × factorial(0) = 1. A product of no factors has the value that leaves multiplication unchanged. This choice makes the rule work cleanly at the boundary.

A call does not vanish while it waits.

When factorial(4) asks for factorial(3), the call for 4 is unfinished. It must remember its own n = 4 and the multiplication it still owes. A new call frame holds n = 3. Frames collect on a stack: 4 waits for 3, which waits for 2, then 1, then 0. The most recent call runs first.

At zero, the base case returns 1. Then the waiting frames finish in reverse order: 1 returns 1 × 1; 2 returns 2 × 1; 3 returns 3 × 2; 4 returns 4 × 6. The lab shows the descent and the unwind separately. Moving down creates obligations; moving up pays them.

Each frame remembers a separate local n. The n in the call for 4 does not change to 3 when it calls factorial(3); instead, a new frame is created with its own parameter. This is the same local-name rule from functions and references, repeated at several depths. The call stack is last-in-first-out: the last frame created must return before an older waiting frame can resume.

Why this rule is correct.

Assume factorial(n - 1) correctly multiplies 1 through n - 1. Multiplying that result by n gives the product 1 through n. The base case is correct for zero, so the argument climbs from 0 to every nonnegative integer. This is an inductive proof that mirrors the returning calls. The progress argument explains why the calls reach the base; the inductive argument explains why the returned answer is right.

Two obligations: every non-base call must move toward a base case, and the returned smaller answer must be enough to build the current answer.

Each call does a constant amount of work besides its one smaller call. There are n + 1 calls, so the total time is O(n). At the deepest point, n + 1 frames wait on the stack, so extra space is O(n). An iterative multiplication loop can use O(1) extra space for this particular task. Recursion expresses structure; it is not automatically faster.

Some recursive definitions branch into more than one smaller call. A tree traversal naturally calls itself on each child subtree. A naïve Fibonacci function asks for overlapping smaller values repeatedly, which can waste enormous work; dynamic programming will save those repeated answers. A recursion tree describes all calls made, while the call stack shows only the calls waiting at one moment. Keep those two pictures distinct.

Recursion can also consume a sequence one piece at a time. To sum an array, you might define sumFrom(i) as the value at index i plus sumFrom(i + 1), with zero when i reaches the array length. The measure that moves toward the base case is now “positions remaining,” rather than n itself. This broader view is useful: find a quantity that strictly shrinks on every path through the recursive calls, then show that the smallest case can be answered without another call.

For a branching recursion, termination needs that progress argument on every branch. Correctness then needs a contract for the smaller calls. If a function merges two sorted halves, for example, assume both recursive calls return sorted halves and show the merge produces one sorted whole. The shape of the proof follows the shape of the computation.

Our input control stops at 7 to keep the trace readable. The mathematical definition works for all nonnegative integers, but large recursive inputs can exceed JavaScript's call-stack limit, and ordinary JavaScript numbers eventually lose integer precision. A correct mathematical recurrence still needs an appropriate machine representation.

The accepted input domain is part of the contract. With the code above, a negative input such as -1 moves to -2, then -3, never reaching the base case at zero. A production function should reject such an input before recursing. State the domain whenever a termination proof depends on it.
