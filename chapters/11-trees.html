Trees.

Branching links turn one starting point into many paths.

About 8 minutes · Use ← → in the figure

Suppose you keep the numbers 8, 3, 10, 1, 6, and 14 so that each node has up to two children. Put smaller values to a node's left and larger values to its right:

        8
      /   \ 
     3     10
    / \      \ 
   1   6      14

To find 6, compare with 8: go left. Compare with 3: go right. The next node is 6. This is a binary search tree. The rule narrows the path in the same spirit as binary search, but links rather than array indices lead to the next candidate.

Use the family words precisely.

The top node is the root. A node immediately below another is its child; the one above is its parent. A node without children is a leaf. A tree has one path from the root to each node, unlike a general graph that can contain cycles.

To visit every node, choose an order. Preorder visits a node before its children. Inorder visits left subtree, node, then right subtree; in a binary search tree this reads values in order. Postorder visits children before their parent. A recursive function fits because each child roots a smaller tree.

Shape decides speed.

A fairly balanced search tree has height near log n, so a search follows about O(log n) links. Insert already sorted values into a plain unbalanced tree and it may become a chain: search can take O(n). The search rule alone does not guarantee balance.
