Heaps.

How can one value rise to the top without sorting every other value?

About 11 minutes · Try inserting and removing priorities

Predict the repair path

Enter 9, 5, 8, 2, 4, 6, 7, choose insertion, and set the new value to 10. Predict the array indices it will visit before tracing. Then choose removal on the same heap and predict which child each sift-down step must compare first.

Imagine a task queue where the largest number means the most urgent task. You do not need every task sorted; you need the largest one now, and then the largest among those left. A priority queue is the behavior we want. A binary max heap is one way to build it.

A max heap keeps two independent promises. Its shape rule says the tree is complete: every level is filled before the next, and the final level fills from left to right. Its order rule says each parent is at least as large as each child. By repeatedly following parent links upward, every node is at most the root. So the maximum is always at a known position.

index:  0  1  2  3  4  5
value:  8  5  7  2  4  6

Read this as a tree: 8 is the root, with children 5 and 7; 5 has children 2 and 4; 7 has child 6. The shape rule lets us store it in an array without explicit pointers. For index i, the children are 2i + 1 and 2i + 2; except at the root, the parent is floor((i - 1) / 2). These formulas are consequences of filling levels left to right.

Heap invariant: the array represents a complete tree, and for every child index i > 0, heap[parent(i)] ≥ heap[i].

Repair only the path you disturbed.

To insert 9, append it at the next free array slot. This preserves the complete shape, but 9 is larger than its parent 7, breaking one order relation. Swap them. Now 9 is above 7 but still larger than its new parent 8, so swap once more. At the root, the rule is restored everywhere. This is sift up. Each swap moves one level closer to the root; no other branch needs repair.

To remove the maximum, save the root value, move the last array value to the root, and shorten the array. The shape remains complete. Only the moved value might violate parent-child order. Compare it with both children and swap it with the larger child if that child is bigger. Repeat until the value is large enough or reaches a leaf. This is sift down. Choosing the smaller child could leave the larger child above its parent and fail to repair the heap.

Partial order is enough.

A max heap is not a sorted array or a binary search tree. The root is guaranteed largest, but the left and right subtrees have no less-than or greater-than relationship with each other. For example, both [9, 5, 8, 2, 4, 6, 7] and [9, 8, 5, 7, 6, 4, 2] can satisfy the heap rule. You cannot find an arbitrary value by choosing left or right as in a BST. An arbitrary search may need to inspect many nodes.

The complete shape has height proportional to log n. Peeking at the maximum reads index 0 in O(1). Insertion and removal repair at most one root-to-leaf path, O(log n) comparisons and swaps. The array itself stores n values; the sift loop needs only a fixed number of extra variables. If the backing array grows, an occasional append may also trigger a resize, as in the arrays chapter.

Building a heap from an arbitrary array can be faster than inserting values one by one. Start at the last internal node and sift down, working backward to the root. Many nodes are leaves and need no work; the more expensive sifts occur at fewer nodes near the top. Adding those costs gives O(n) total work for bottom-up heap construction, even though a single sift can take O(log n).

It is tempting to multiply n nodes by the worst possible log n sift and conclude that construction takes O(n log n). That overcharges nearly every node. About half the nodes are leaves and move zero levels; about a quarter can move at most one; about an eighth can move at most two. The weighted sum is proportional to n(0/2 + 1/4 + 2/8 + 3/16 + …), and the parenthesized series has a fixed bound. Counting how many nodes can pay each height cost reveals the linear result.

Repeatedly removing the maximum yields a sorted sequence, which is the idea behind heapsort. In a scheduling system, you instead remove one urgent task, let new tasks arrive, and keep the next urgent task easy to reach. The structure is useful precisely because it maintains only the order your next question needs.

A min heap flips the inequality: each parent is at most its children, so the smallest priority is at the root. The same complete shape, index formulas, and sift paths still work. A shortest-path algorithm will use a min-priority queue to choose the next nearest candidate. If equal priorities must leave in arrival order, the heap rule alone does not supply that stability; store an arrival number alongside each priority and compare the pair.

Check edge cases explicitly. A single-value heap is valid and removal leaves it empty. Equal priorities are valid because the invariant uses ≥. A parent with only a left child is normal on the final level. If you insert into an empty heap, the new value simply becomes the root. The lab accepts an empty starting heap for insertion and requires a nonempty one for removal.
