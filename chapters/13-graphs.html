Chapter 13 · After heaps

Graphs.

When connections can branch, meet, and circle back, track where you have already been.

About 8 minutes · Use ← → in the figure

Think of rooms connected by doors. Room A opens to B and C. Those rooms lead to others, and two routes may reach the same room. A tree has one route down to each node; this network is a graph.

A: B, C
B: A, D, E
C: A, D, F
D: B, C, F

Each room is a vertex; each door is an edge. To explore nearest rooms first, put A in a queue. Remove the front room, then add its unseen neighbors to the back. The queue makes this a breadth-first search (BFS). Step through the figure and watch the queue.

Mark before adding.

Mark a vertex seen when you enqueue it, not only when you later remove it. Otherwise two neighbors may enqueue the same room. A graph can also contain cycles; without a visited set, the search may keep circling. BFS reaches vertices in layers of edge distance, so it finds a path with the fewest edges in an unweighted graph.

A depth-first search (DFS) follows one route as far as it can before backing up. A stack, explicit or through recursion, produces that order. Both BFS and DFS inspect each reachable vertex and edge at most a constant number of times: O(V + E) work with an adjacency-list representation.

Decide what edges mean.

Some edges have directions, like a one-way street. Some have weights, like travel time. BFS's fewest-edge path is not necessarily the least-weight path. State whether the graph is directed or weighted before choosing a search. Disconnected vertices also need a new starting point if you want to visit the whole graph.

Practice

  1. Run BFS from A on the figure. At what visit distance from A does F first appear? Write one shortest path.
  2. Start DFS at A and visit alphabetically named unseen neighbors first. Write the visit order and mark where you backtrack.
