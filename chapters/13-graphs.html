16 · After heaps

Graphs.

Connections can branch, meet, and circle back. A visited set turns a walk into an algorithm.

9 minute lesson · Then compare two kinds of shortest path

Think of rooms connected by doors. Room A opens to B and C. Those rooms lead to others, and two routes may reach the same room. A tree has one route down to each node; this network is a graph. A room is a vertex; a door is an edge. A graph does not promise a root, a unique path, or even that every vertex is connected.

A: B, C
B: A, D, E
C: A, D, F
D: B, C, F
E: B
F: C, D

The list above is an adjacency list: each vertex names its neighbors. It stores about one entry per vertex and per edge, O(V + E) space. An adjacency matrix instead has a row and column for every possible pair. It lets you test whether one particular edge exists in O(1) time, but uses O(V²) space even when almost no pairs connect. This is another representation choice driven by the queries you need.

To explore nearest rooms first, put A in a queue. Remove the front room, then add its unseen neighbors to the back. The queue makes this a breadth-first search (BFS). Before stepping the figure, predict whether D or F enters the queue first and why.

Mark before adding.

Mark a vertex seen when you enqueue it, not only when you later remove it. Otherwise B and C might both enqueue D before either copy is processed. A graph can also contain cycles; without a visited set, A → B → A could continue indefinitely. Once marked, a vertex is never enqueued again.

The queue gives BFS a useful invariant: before processing distance d + 1, it has processed all discovered vertices at distance d. A vertex first discovered from a distance-d vertex gets distance d + 1. If a shorter route existed, its earlier layer would already have discovered the vertex. That is why recording the predecessor when you first enqueue a vertex reconstructs a path with the fewest edges.

A depth-first search (DFS) follows one route as far as it can before backing up. A stack, explicit or through recursion, produces that order. DFS does not promise a shortest route, but its enter and exit order help find cycles, connected components, and topological order in a directed acyclic graph. Both BFS and DFS inspect each reachable vertex and edge at most a constant number of times: O(V + E) work with an adjacency-list representation. They also need O(V) memory for visited information and a queue or stack in the worst case.

Decide what edges mean.

Some edges have directions, like a one-way street. Some have weights, like travel time. BFS's fewest-edge path is not necessarily the least-weight path. State whether the graph is directed or weighted before choosing a search. Disconnected vertices also need a new starting point if you want to visit the whole graph.

Try the graph route lab: A direct edge can be one hop and still be expensive. Compare BFS with Dijkstra on the same weighted graph ↗. Change the start and target, then trace the queue or priority frontier backward and forward.

For non-negative weights, Dijkstra repeatedly finalizes the unsettled vertex with the smallest known distance. For negative edges, that finalization argument fails; the shortest paths study derives alternatives and their assumptions. Before choosing any algorithm, write down what “shortest” actually measures.

The reusable idea: A graph algorithm is a rule for what enters the frontier, which frontier item comes out next, and when a result becomes final. Those rules are the proof of its behavior.
