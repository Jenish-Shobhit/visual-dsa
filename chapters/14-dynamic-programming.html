Dynamic
programming.

If smaller questions repeat, save each answer once and build from there.

About 9 minutes · Use ← → in the figure

You can climb a staircase by taking one or two steps at a time. How many different step sequences reach stair 4? Start with a smaller question: to reach stair 4, your last move came from stair 3 or stair 2.

ways(4) = ways(3) + ways(2)
ways(0) = 1
ways(1) = 1

There is one way to be at stair 0: take no steps. There is one way to reach stair 1. From there, ways(2) = 2, ways(3) = 3, and ways(4) = 5. Step through the table to see every answer come from two earlier ones.

Name the state and rule.

The state ways(i) means “number of step sequences that reach stair i.” The transition is ways(i-1) + ways(i-2). The base cases are the first answers we can state without asking anything smaller. These three choices make the computation precise.

A direct recursive version would ask for ways(3) and ways(2), and calculating ways(3) would ask for ways(2) again. Those are overlapping subproblems. Store each result in a table and every state is computed once: O(n) time and O(n) table space.

Build up or remember on demand.

Filling from 0 upward is tabulation. Recursing while caching answers is memoization. Both reuse the same state and transition. If you only need the final count, keep the last two answers instead of the whole table, reducing extra space to O(1). If you must reconstruct a chosen path, you may need to keep more information.

Dynamic programming is useful when a problem breaks into smaller states whose answers are reused. It is not a separate algorithm to memorize; it is a way to prevent repeated work once the state and recurrence are clear.
