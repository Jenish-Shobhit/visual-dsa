# Visual DSA: chapter plan

The path starts with one instruction changing a state. Each chapter reuses an idea the reader has already seen. Figures should allow a reader to predict the next step before pressing Next. Problems are prompts only; solutions belong elsewhere.

| # | Chapter | One idea to land | Interactive figure | Three practice problems | Depends on |
|---|---|---|---|---|---|
| 01 | What is code | A program is an ordered set of precise instructions that changes a starting state. | Step through `total = 2; total = total + 3; show(total)` and watch state and output. | Predict the output of three assignments; put three instructions in an order that prints 7; find the instruction that changes an expected output. | None |
| 02 | Memory and variables | A variable names a place for a value; assignment replaces the current value, while reading a variable uses the value it holds now. | Trace two named memory cells through assignment and copying. | Trace `a` and `b` after a copy and update; choose assignments that swap two values using a temporary variable; explain why changing `x` after `y = x` leaves `y` alone. | 01 · What is code |
| 03 | Arrays and strings | An array gives one ordered collection of positions, and an index selects exactly one position; a string can be read as an ordered sequence of characters. | Move an index through an array and update a running total. | Read values at given indices; find the first repeated character in a short word; trace a loop that totals an array. | 02 · Memory and variables |
| 04 | Complexity | Work grows with input size; count that growth separately from clock time. | Increase input size and compare one pass with all ordered pairs. | Count reads in a scan; compare `2n + 5` with `n²` at two sizes; count all-pairs comparisons. | 03 · Arrays and strings |
| 05 | Sorting | Sorting repeatedly puts items into an order; different methods make different comparisons and moves. | Preserve the six existing animated visualisers: bubble, selection, insertion, merge, quick, heap. | Sort four values by hand with insertion sort; identify where bubble sort can stop early; compare the extra space used by merge and insertion sort. | 04 · Complexity |
| 06 | Searching | Sorted order lets each comparison discard half the remaining candidates. | Trace binary search for 23, showing the low/high range and midpoint. | Search for a missing value; find the first duplicate; choose scan versus sort-then-search for one query. | 05 · Sorting |
| 07 | Linked lists | Order can live in links; insertion changes references rather than shifting array slots. | Rewire two `next` links to insert 7 between 4 and 9. | Trace a list from its head; insert after a referenced node; remove the head safely. | 06 · Searching |
| 08 | Stacks and queues | Restricting the removal end produces last-in-first-out or first-in-first-out order. | Give a stack and queue the same arrivals, then remove once from each. | Trace push/pop; trace enqueue/dequeue; choose a structure for three real tasks. | 07 · Linked lists |
| 09 | Hashing | A key suggests a slot, and collisions require a lookup rule. | Insert keys using modulo five and linear probing, then find a collided key. | Compute hash slots; trace linear probing; reason about load factor. | 08 · Stacks and queues |
| 10 | Recursion | A call can wait for a smaller call if a base case guarantees an answer. | Expand and unwind the call stack for `factorial(4)`. | Trace a recursive sum; repair a nonterminating call; design a countdown base case. | 09 · Hashing |
| 11 | Trees | Branching parent/child links create paths; a search rule chooses one branch. | Follow a value through a binary search tree. | Identify root, parent, and leaves; trace inorder and preorder; insert a value. | 10 · Recursion |
| 12 | Heaps | A parent priority rule keeps the maximum at the root without fully sorting every value. | Append 9 to a max heap and sift it up. | Insert a value; validate a max heap; remove the root and sift down. | 11 · Trees |
| 13 | Graphs | General connections can cycle; a visited set prevents repeat work. | Run breadth-first search with a visible queue and visit order. | Find a shortest unweighted path; trace depth-first search; handle a disconnected vertex. | 12 · Heaps |
| 14 | Dynamic programming | Save overlapping smaller answers and reuse them through a state transition. | Fill a table of stair-climbing counts from base cases to stair six. | Extend the table; count unique and repeated states; define a three-step transition. | 13 · Graphs |

All fourteen chapters are live. Chapter 05 preserves the six original sorting visualisers.
