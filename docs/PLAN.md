# Visual DSA: chapter plan

The path starts with one instruction changing a state. Each chapter reuses an idea the reader has already seen. Figures should allow a reader to predict the next step before pressing Next. Problems are prompts only; solutions belong elsewhere.

| # | Chapter | One idea to land | Interactive figure | Three practice problems | Depends on |
|---|---|---|---|---|---|
| 01 | What is code | A program is an ordered set of precise instructions that changes a starting state. | Step through `total = 2; total = total + 3; show(total)` and watch state and output. | Predict the output of three assignments; put four instructions in an order that prints 7; find the instruction that changes an expected output. | None |
| 02 | Memory and variables | A variable names a place for a value; assignment replaces the current value, while reading a variable uses the value it holds now. | Trace two named memory cells through assignment and copying. | Trace `a` and `b` after a copy and update; choose assignments that swap two values using a temporary variable; explain why changing `x` after `y = x` leaves `y` alone. | 01 · What is code |
| 03 | Arrays and strings | An array gives one ordered collection of positions, and an index selects exactly one position; a string can be read as an ordered sequence of characters. | Move an index through an array and reveal the value at each position. | Read values at given indices; find the first repeated character in a short word; trace a loop that totals an array. | 02 · Memory and variables |
| 04 | Complexity | Count how work grows with input size, rather than timing one run. | Change array length and compare one pass with nested passes. | Count reads in a linear scan; compare two growth tables; identify the dominant work in two nested loops. | 03 · Arrays and strings |
| 05 | Sorting | Sorting repeatedly puts items into an order; different methods make different comparisons and moves. | Preserve the six existing animated visualisers: bubble, selection, insertion, merge, quick, heap. | Sort five values by hand with insertion sort; identify where bubble sort can stop early; compare the extra space used by merge and insertion sort. | 04 · Complexity |
| 06 | Searching | Ordered data lets each comparison rule out more possibilities. | Step through linear and binary search on the same values. | Trace binary search for a missing target; find the first matching index in duplicates; count comparisons on a sorted set. | 05 · Sorting |
| 07 | Linked lists | A node stores a value and a link; following links creates order without neighboring array slots. | Rewire links to insert and remove a node. | Trace a list from its head; insert after a named node; find a broken link in a diagram. | 06 · Searching |
| 08 | Stacks and queues | Restricting which end can be used gives useful order: last in first out or first in first out. | Switch between push/pop and enqueue/dequeue on the same items. | Trace a stack of calls; trace a queue of arrivals; choose a structure for undo history. | 07 · Linked lists |
| 09 | Hashing | A hash maps a key to a slot; collisions require a plan. | Insert keys into a small table and follow a collision. | Compute slots with a simple modulo hash; trace linear probing; explain what happens when two keys share a slot. | 08 · Stacks and queues |
| 10 | Recursion | A function can solve a smaller version of the same problem if it has a stopping case. | Expand and unwind calls for a small sum. | Trace `sum(4)`; find a missing base case; write the next smaller input for three tasks. | 09 · Hashing |
| 11 | Trees | Parent and child links organize data into branching paths. | Step through a tree traversal and highlight the visit order. | Name the parent and leaves in a diagram; trace preorder; insert values into a binary search tree. | 10 · Recursion |
| 12 | Heaps | A heap keeps a parent priority rule, making the top item quick to access. | Insert and remove the top item while swaps restore the heap rule. | Repair a max heap after insertion; trace one removal; identify whether an array represents a valid heap. | 11 · Trees |
| 13 | Graphs | Vertices and edges model general relationships; a visit rule prevents repeated work. | Walk breadth first and depth first from one vertex. | Trace a breadth first visit order; find a path through a small graph; mark visited vertices in a cycle. | 12 · Heaps |
| 14 | Dynamic programming | Save answers to overlapping smaller problems and reuse them. | Compare repeated recursive calls with a filled table. | Fill a Fibonacci table; count unique subproblems; choose state and transition for a small stair problem. | 13 · Graphs |

Chapters 01–03 and the preserved sorting visualisers in 05 are live. The rest remain listed as soon until their explanations and figures exist.
