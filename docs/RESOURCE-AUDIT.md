# Computer Science resource audit

The local `Computer-Science/` collection contains 31 paths: 24 DSA lectures, two standalone HTML lessons, one README, three books in `books/`, and a duplicate copy of the Martin EPUB at the top level. The DSA HTML files total about 140,000 extracted words. Their extracted text and section inventories were used to map all 24 topics, and the published pages were checked for study entry points, navigation, and selected high-risk examples. The 24 published `studies/` pages are adaptations of those lectures. This is a curriculum and targeted correctness audit, not a line-by-line certification of every proof, code fragment, and numerical example.

## What the DSA course teaches

| Studies | Learning progression | Central question |
|---|---|---|
| 00–03 | Cost model, memory layout, amortized analysis, divide and conquer | What work does code perform, and how does representation change the bill? |
| 04–06 | FFT, probability, sorting bounds | When can a change of representation or model beat the obvious algorithm? |
| 07–10 | Balanced trees, hashing, heaps, range structures | Which invariant keeps queries and updates cheap? |
| 11–15 | Traversal, MST, shortest paths, dynamic programming | Which graph structure and weight assumptions make an answer final? |
| 16–19 | Greedy proofs, flow duality, text matching and indexes | How do we certify local choices or reuse prior structure? |
| 20–23 | NP completeness, approximation, randomization, frontier models | What can be guaranteed when exact general solutions are expensive? |

The lecture set is strongest when it explains an invariant and then tests its boundary: the difference between average and amortized cost, Dijkstra's nonnegative weight assumption, a cut certificate for spanning trees, and residual edges that undo earlier flow. It also offers exercises in every lecture. The new field notes let readers identify the invariant and test one consequence before entering a long proof.

## Corrections to published studies

- **00, cost of computation:** `2^100` is about `1.27 × 10^30`, far fewer than the roughly `10^80` atoms often estimated for the observable universe. At a billion operations per second it still takes roughly 40 trillion years. The hook now uses that calculation.
- **02, amortized arrays:** With capacity doubling from one, the largest copy among the first million appends moves 524,288 elements. The former one million copy would occur at a later resize.
- **04, FFT:** The polynomial multiply pseudocode evaluated `FFT(A)` and `FFT(B)` inside each iteration of a comprehension. It now computes each transform once, preserving the stated `Θ(n log n)` cost, and trims the padded output to the product length. A follow-up removed another unsupported fixed speedup and qualified floating-point rounding and modular reconstruction. The lesson's claims that roots of unity are the *unique* suitable evaluation points were narrowed to the property actually used by this FFT. The recap now describes the quadratic **direct convolution algorithm**, not a quadratic lower bound on multiplication. Its million-digit comparison now uses consistent arithmetic and avoids a precise speed ratio that operation counts alone cannot support.
- **13, shortest paths:** A figure caption said one negative edge mandates Bellman–Ford. A DAG with negative edges can use topological order. The caption now states the actual Dijkstra precondition and Bellman–Ford's role.
- **Practice navigation:** The published studies do not have the source collection's private `/learn` answer command or the advertised answer files. Command instructions were removed in the published copies; each published lecture now has a self check with an answer on the page. The longer practice problems remain open exercises.

## Reading design decisions

A study page contains a long derivation, diagrams, worked examples, failure cases, and practice. The new short field note gives a learner three entry points: prerequisite knowledge, the central invariant, and a small question with an on-page answer. The directory groups the 24 lessons into six themes and supports keyword search over themes, lesson titles, and descriptions. This keeps the advanced material useful as both a sequential course and a reference.

## Remaining editorial work

The original lectures contain many broad claims and long passages. The corrections above address concrete issues found during this pass. A rigorous publication review should verify proofs, numerical examples, pseudocode, alt text, and exercise solvability one lecture at a time. For direct skill transfer, the next curriculum layer should add executable traces and worked solutions to selected practice problems, with tests against edge cases.
