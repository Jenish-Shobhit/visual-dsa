# Reading notes: *Code*, second edition

Charles Petzold, *Code: The Hidden Language of Computer Hardware and Software*, second edition (2022). Source in this workspace: `Computer-Science/books/petzold-code-the-hidden-language-2nd-ed-2022.epub`.

## Coverage and limits

I read the extracted **main body text of all 28 chapters**, in order, from the EPUB. The extraction has 28 chapter entries (`OEBPS/ch01.xhtml` through `OEBPS/ch28.xhtml`), totaling about 115,000 words. It omits the visual contents of figures and compresses some equations and tables into running text, so the notes below are a synthesis of the prose and described mechanisms, not a claim to have inspected every diagram. The preface, index, and publisher matter are outside this chapter audit. These notes paraphrase; the lessons use new examples and diagrams.

The book's central teaching move is to start with a need, build the smallest mechanism that serves it, find where it fails, and add one capability. The site can use the same causal sequence without reproducing the book's stories, circuits, or diagrams. In particular, each lesson should give a learner a state to predict, let them advance a trace, explain one state change at a time, name the model's limit, and ask a new transfer question.

## Chapter notes and course decisions

| Chapter | Mechanism and connection in the book | Decision for this course |
| --- | --- | --- |
| 1. Best Friends | A communication problem makes an agreed code necessary. Two distinct signals can encode choices; timing and pauses mark boundaries. | Begin the course with a small, original message problem where the learner sees that meaning is agreed, not inherent in a bit. |
| 2. Codes and Combinations | Each extra binary choice doubles the number of fixed-length patterns; a branching decode tree makes the count concrete. | Let learners enumerate two- and three-choice possibilities before showing (2^n). A tree is a reading procedure, not decoration. |
| 3. Braille and Binary Codes | Six raised/flat positions yield 64 patterns. Context, shift markers, and escape markers can change what a pattern means; redundancy helps with errors. | When teaching representation, specify the interpretation rule and prior state. A bare bit pattern does not identify its own type. |
| 4. Anatomy of a Flashlight | A closed path and a switch give an observable two-state physical signal. The chapter distinguishes voltage, current, resistance, and limits of analogy. | If the first lesson uses a switch, show the physical event that carries the symbol and avoid treating electricity as a mystical source of meaning. |
| 5. Communicating Around Corners | Wires carry the same signal beyond sight; shared conductors reduce wiring, but distance adds resistance. | Show an abstraction retaining the signal contract while a physical implementation changes; do not imply arbitrary distance is free. |
| 6. Logic with Switches | Series and parallel switches implement AND and OR; a truth table accounts for every input pair. | Make a condition a question with specific inputs, then enumerate its outcomes before introducing a Boolean name. |
| 7. Telegraphs and Relays | A relay uses an input current to control a separate output circuit. Cascading lets a weak incoming signal cause a new strong signal. | Explain each arrow in a diagram as a causal action, especially when one device controls another. |
| 8. Relays and Gates | Electrically controlled switches become composable gates. Gate symbols hide relay details while preserving the input/output behavior. | Introduce diagram symbols only after the learner has seen one concrete implementation and its behavior. |
| 9. Our Ten Digits | Place value and zero explain why written digits can encode arbitrarily large values; the base-ten choice is contingent. | Say what a position means before teaching array positions or binary positions. Distinguish symbol from value. |
| 10. Alternative 10s | Octal, base four, binary, and hexadecimal all follow the same positional rule. Binary's small addition table enables circuits. | Use a small number with place-value labels; avoid conversion drills unless they reveal a later data representation. |
| 11. Bit by Bit by Bit | A bit is a choice between two agreed meanings. More bits increase possibilities; unused patterns can improve error tolerance. UPC and QR add framing/checking. | Include a deliberate "what does 01 mean?" question that cannot be answered without a code agreement or context. |
| 12. Bytes and Hexadecimal | Eight bits form a byte; hex maps each four-bit group to one digit and makes byte contents readable. | If showing raw memory, label the byte width and say why the compact notation exists. |
| 13. From ASCII to Unicode | Text requires a character encoding, and UTF-8 requires rules for variable-length byte sequences. A mismatch produces visible gibberish. | Use decoding as a model of interpretation: bytes plus rules produce characters, just as values plus language rules produce program behavior. |
| 14. Adding with Logic Gates | XOR yields the sum bit, AND the carry; half adders become full adders, then a multi-bit adder. Named boxes preserve a known contract while hiding detail. | Teach an abstraction after building and testing the smaller behavior it packages. For functions, show inputs, return, and side effects as the contract. |
| 15. Is This for Real? | Relays, tubes, transistors, and integrated circuits can embody the same logic, with different speed and reliability. Stored programs put code and data in memory. | Mark a program-state diagram as a behavior model; the underlying hardware may implement it in many ways. |
| 16. But What About Subtraction? | Two's complement turns fixed-width subtraction into addition. The same bits can be signed or unsigned; overflow depends on interpretation. | State width and representation whenever a trace depends on them. Do not make a bit pattern speak for itself. |
| 17. Feedback and Flip-Flops | Feedback creates state: identical present inputs can have different outputs because of history. D latches hold a bit; edge triggering makes the accumulating adder stable. | Chapter 2 should start with a value that must survive to a later instruction. The diagram's key job is to show before/after state, not simulate a physical RAM cell. |
| 18. Let's Build a Clock! | Counters compose into a time display; binary-coded decimal interprets bit groups as decimal digits, and decoding drives display hardware. | Continue the same program across examples, and make each later device solve a visible limitation of the earlier one. |
| 19. An Assemblage of Memory | Write, address, and read select a stored bit or byte. A decoder selects where to write; a selector chooses what to read. RAM is volatile. | Clarify the gap between a variable name in source code and an addressed memory location. The name/value/object diagram predicts JavaScript behavior; it is not a literal RAM map. |
| 20. Automating Arithmetic | A counter steps through memory, a latch accumulates, and control signals coordinate operations. Instruction bytes become a flexible alternative to fixed wiring. | For each line of source, expose read → compute → write. Show why saved state and order matter to the result. |
| 21. The Arithmetic Logic Unit | An ALU selects arithmetic or logic operations and saves flags. A carry bridges byte operations; comparison produces useful flags without storing a subtraction result. | Treat a decision as a test with an observable result that controls the next step. |
| 22. Registers and Busses | Registers temporarily hold values; a data bus moves bytes, an address bus selects locations. An accumulator is a particular register with a role. | When a function runs, distinguish its local names from the caller's; avoid claiming every source variable resides in a separate hardware register or stack slot. |
| 23. CPU Control Signals | Fetch and execute consist of ordered transfers: enable a source on a bus, latch a destination, then move on. The program counter advances through instructions. | The stepper should highlight exactly one transition and explain what is read, what is written, and what waits. |
| 24. Loops, Jumps, and Calls | Loops alter the program counter conditionally. A call saves a return address; nested calls put return addresses on a last-in-first-out stack, and returns resume the waiting code. | Chapter 5 should have a concrete call trace with the caller paused, a fresh local binding, a returned value, and the caller resuming. Later, compare a copied number with a copied reference to shared data. |
| 25. Peripherals | I/O changes information between programs and the world; display pixels, keys, sound, and files each need encoding and device work. | Make output a visible event after tracing, and distinguish a program's stored value from what a display renders. |
| 26. The Operating System | Boot code makes a blank machine usable; file systems name stored data; APIs let applications request shared services without knowing device details. | Treat a function interface as a promise about use and result; explain that an implementation can change under that promise. |
| 27. Coding | Assemblers translate mnemonics, compilers and interpreters handle higher-level source. JavaScript variables use assignment, loops update state, arrays collect values, and floating point has finite precision. | Use actual JavaScript syntax consistently. Explain `=` as evaluate-right-then-bind-left, not mathematical equality. Label unusual numeric behavior as a representation limit. |
| 28. The World Brain | The narrative widens to linked documents and networks: packets, addresses, routing, protocols, browsers, and shared knowledge. | Keep optional links as references after the core lesson. A learner should be able to finish one coherent path without choosing among parallel introductions. |

## Direct guidance for the revised lessons

### Memory and variables

Start with a small count needed later. Ask the learner to predict two names after a three-line program. Trace the right-hand read before the left-hand write. Then replace the copied number with a shared collection and ask a prediction **before** explaining aliasing. The representation boundary is essential: JavaScript number assignment copies a number value; array assignment copies a reference value, so the arrays are shared until a name is rebound. A diagram of names and arrows describes observable language behavior. Actual RAM stores bits at addressed locations; a compiler or engine can change the physical layout.

### Functions and references

Give a task that the same program needs twice. Predict output before tracing the call. Show caller paused, argument evaluated, a new local parameter bound, body run, return value delivered, and caller resumed. Then reuse the same call mechanism with a reference value. Explain the difference between editing the one collection and assigning a new collection to the local name. Finally let the learner change the operation order and predict which object changes. The book's call-stack treatment concerns machine return addresses; our JavaScript frames are a behavior model and should not claim a particular engine puts each local in a physical stack slot.

## Audit observations

- The extracted chapter text reliably provides the narrative and verbal description of each mechanism. It does **not** preserve most figures as inspectable images. A few mathematical displays are flattened (for example, superscripts in powers of two), so numerical relationships above were checked against the accompanying explanation.
- The relevant lesson connection is a progression, not a direct transplant of Petzold's 8080 CPU: physical signals → binary interpretation → circuits that retain state → addressed memory → ordered instructions → calls and returns → source-level variables and functions.
- Original examples, prompts, and diagrams should carry that progression. Long passages, tables, figures, and circuits from the book should not be copied into the site.
