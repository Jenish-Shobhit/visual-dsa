What happens when code runs?

A program is a sequence of instructions. Watch a tiny machine fetch one instruction, decode its two bytes, and change state. Then try a branch that sends the program counter backward.

1. Fetch

Use the program counter to copy the next instruction into an instruction register.

2. Decode

3. Execute

Update the accumulator, data memory, output, or program counter.

    What the bytes mean here

    Every instruction has an opcode byte and an operand byte. The program counter in this teaching machine counts instructions, so the next instruction is PC + 1 even though its encoding uses two bytes. These indices are not physical byte addresses. For example, hexadecimal 20 05 (binary 00100000 00000101) means ADD #5 in this model. # means a literal value; M0 means a data memory cell. A branch changes PC, which is why a loop repeats instructions.

    The accumulator and each data cell hold only 0–255. An arithmetic result outside that range wraps modulo 256. The wrap indicator describes the most recent arithmetic operation; loads and stores leave it unchanged. The program stops at HALT or at a 192-instruction teaching limit.

    How this relates to a real computer

    Real processors also represent instructions as bits and repeatedly fetch, decode, and execute them. Their instruction sets, registers, memory systems, pipelines, and operating systems are much more involved. These opcodes are invented for this lesson; they are not x86, ARM, JavaScript bytecode, or a description of how one JavaScript source line maps to hardware.
