Bits, bytes & memory

Everything a computer holds is a row of switches in numbered boxes. Learn to read them as numbers, letters, colours and variables.

  • 18 min
  • Beginner
  • Needs: lesson 01

The problem

A program keeps a score, a letter grade, a temperature, a name and a colour. The machine underneath has none of those things. It has one long row of tiny boxes, and each box holds eight on/off switches.

Below are the sixteen boxes where that program keeps its data, written the way programmers write raw memory. Can you tell which box is the grade?

The byte 41 appears twice. In one place it is part of the number 65; in the other it is the letter A. Nothing inside the box says which. This lesson shows how switches become numbers, how numbers become letters and colours, and how a program remembers where each thing lives.

Build the intuition

Picture a street of identical lockers. Each locker has a number painted on the door and holds a panel of eight light switches. To remember something, you set the switches in some locker and write down its number.

Analogy: a street of numbered lockers

The locker number is an address. The switch panel is a byte. A name in your program, like score, is a sticky note that says “locker 256”.

Where the analogy breaks

A real locker can be empty. A byte never is: its switches are always in some position, even before your program touches it. Memory you have not written still holds leftover patterns from earlier.

Counting with switches

Definition

A bit (binary digit) is one switch: 0 for off, 1 for on. Eight bits make a byte.

In decimal, each place is worth ten times the place to its right: ones, tens, hundreds. Binary works the same way with two. Each switch is worth double its right-hand neighbour: 1, 2, 4, 8, up to 128.

To read a byte, add up the places whose switch is on. Flip the switches below and watch every reading change at once.

Try this

Set the switches to 65, which ASCII reads as A. Now flip the 32 switch. You get 97, lowercase a. Upper and lower case differ by exactly one bit.

Counting up, and the carry

Adding 1 in binary follows one rule. Find the rightmost 0, turn it into a 1, and turn every 1 to its right into a 0. Those 1s roll over like an odometer, each passing a carry to its left.

Why the average is 2

Half of all increments flip one bit, a quarter flip two, an eighth flip three, and so on. Watch the “average flips” counter settle near 2: a long carry is expensive but rare. Lesson 06 calls this idea amortised cost.

How many patterns fit in n bits?

One bit can say two things. Add a second bit and each of those two splits into two more. Every extra bit doubles the count, so n bits give 2n patterns.

Doubling grows fast. A byte holds 256 patterns, two bytes 65,536, and four bytes about 4.3 billion. That is why a program’s choice of size decides the largest number it can store.

Bytes and hexadecimal

Eight 0s and 1s are hard to read and easy to mistype. Programmers write bytes in hexadecimal, base 16, which uses the digits 0–9 and then A–F for ten to fifteen.

Hex fits bytes perfectly. Four bits make exactly 16 patterns, one hex digit. So a byte is always two hex digits, and you convert it half by half without any long arithmetic.

You will see the prefix 0x in front of hex numbers, as in 0x2A. It marks the base, just like 0b marks binary: 0b101010, 0x2A and 42 are the same number.

Meaning is an agreement

A byte holds a pattern, not a meaning. Meaning comes from an agreement between whoever writes the bytes and whoever reads them.

ASCII is one such agreement for text. It assigns a number to each character: 65 is A, 97 is a, 48 is the digit 0, and 32 is a space. Colours use another: three bytes for red, green and blue, often a fourth for opacity.

Key idea

The same bits can be a number, text or a colour. A program’s types, like int and char, are how it records which agreement to use for each location.

Negative numbers: two’s complement

With a fixed number of bits, counting eventually wraps around: add 1 to the largest pattern and you land back on zero. Two’s complement uses that wrap. It keeps the patterns just below zero, on the far side of the circle, for the negative numbers.

On the 4-bit wheel below, 1111 is one step before 0000, so it means −1. The top bit acts as a sign: patterns starting with 1 are negative.

The range is lopsided

An 8-bit signed number runs from −128 to 127, not −127 to 127. Zero takes one of the non-negative patterns, so negatives get one extra. That is why negating −128 in 8 bits gives −128 back.

Adding in binary

Binary addition is decimal column addition with a tiny table: 0+0 = 0, 0+1 = 1, and 1+1 = 10, which writes 0 and carries 1. The hardware does exactly this, one column at a time, with the same circuit for signed and unsigned numbers.

Two kinds of overflow

Unsigned overflow means a carry fell off the top: the true sum needed more bits. Signed overflow means two numbers with the same sign produced the opposite sign, like 100 + 50 = −106. The bits are identical; only the reading differs.

Memory: a street of addresses

Main memory, or RAM, is a long row of bytes. Each byte has an address, its position in the row, usually written in hex. A laptop with 16 GB of RAM has about 17 billion addresses.

“Random access” means the machine can jump straight to any address in the same time. It does not walk past the bytes before it, as a tape would. Click any byte below and race the two.

Definition

A variable is a name for an address, plus a type that says how many bytes live there and how to read them. int a means “four bytes starting at a’s address, read as a signed whole number”.

A value bigger than one byte spreads over neighbouring addresses. Most computers store the lowest byte first, an order called little-endian. So 1,000,000 = 0x000F4240 sits in memory as 40 42 0F 00.

Arrays put their elements side by side, which makes finding one pure arithmetic. If arr starts at address base and each element takes size bytes, then arr[i] starts at base + i × size. You will lean on that formula in lesson 06.

The memory lab

Write a tiny C-style program and watch memory change byte by byte. Each line reserves bytes, reads bytes or writes bytes, and the code panel shows the same program three more ways. The JavaScript and Python tabs use raw byte arrays, so every name turns into its address.

The lab understands int (4 bytes), short (2) and char (1), arrays like int arr[4] = {1, 2};, text like char s[4] = "hi!"; and pointers like int* p = &a;. Press ← and → to step, Space to play.

What happens for each line

Every statement in the lab follows the same small map. A declaration reserves bytes and binds a name to an address. Any line that stores a value evaluates the right side first, then wraps it to fit and writes the bytes. Step the lab and the path lights up here.

What it costs

In the RAM model every read or write of one memory cell costs one step, whatever its address. Fixed-size values like an int take a fixed number of bytes, so reading one is constant work too. Costs grow only when the number of bytes or bits grows.

Variations and patterns

A few bit-level ideas show up again and again, in interviews and in real systems.

Little-endian machines (most laptops and phones) store the lowest byte at the lowest address. Big-endian stores the highest byte first, and network protocols use that order. Same number, reversed bytes: data moving between the two must be swapped.

Shifting every bit one place left doubles a number, just as adding a 0 in decimal multiplies by ten. Shifting right halves it and drops the remainder. x << 3 is x × 8, as long as no 1 falls off the top.


        
A byte can hold eight yes/no flags, such as file permissions. AND with a mask tests or clears bits; OR sets them; XOR flips them. One byte replaces eight separate variables.

        
ASCII covers only 128 characters. UTF-8, the encoding of almost every web page, keeps ASCII as single bytes and spells every other character with two to four bytes. The first bits of each byte say how many bytes belong together.

History

      

        
1703binary published

        
Leibniz, Shannon, Tukey and BuchholzFrom a paper on arithmetic to the words “bit” and “byte”

        

          
Gottfried Leibniz published arithmetic using only 0 and 1 in 1703, but binary took over only after Claude Shannon showed, in his 1937 master’s thesis, that relay circuits follow Boole’s algebra of true and false. John Tukey coined the word “bit” in 1947, and Werner Buchholz coined “byte” at IBM in 1956.

          
On 21 June 1948 the Manchester “Baby” ran the first program stored in the same electronic memory as its data: 17 instructions, held as dots of charge on the face of a cathode-ray tube.
