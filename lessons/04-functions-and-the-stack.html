Functions & the call stack

A call pauses the caller, piles a new frame on the stack, and sends one value back. Watch frames come and go, and arrows from variables find their objects on the heap.

The problem: one recipe, many callers

You need the area of a kitchen, then of a hall. Writing w * h twice is easy. Writing it a thousand times is not, so you name the recipe once, as a function, and run it wherever you need it.

That creates a puzzle. The function is written in one place, but it is used from many. When it finishes, how does it know which line to go back to? Step through the figure and watch the jump.

The destination is not written inside area. Each call leaves a note saying where it came from, and return reads that note. The rest of this lesson is about where those notes live, and what else travels with them.

Build the intuition

You are reading a book on page 42 when the phone rings. Before you answer, you write “page 42” on a note. Halfway through the call, the doorbell rings, so you write “mid-sentence” on a second note and put it on top of the first.

Analogy: interruptions and a pile of notes

You always finish the newest interruption first, and the note on top tells you where to go back to. Only when the pile is empty are you back to the book.

Where the analogy breaks

Your notes are only a bookmark. A function’s note travels with more: its own private variables. Two calls to the same function each get their own copy, and that copy vanishes when the call ends.

A call, piece by piece

Five words do most of the work. Pin each to the picture below.

Definitions

A function definition writes the recipe. Nothing runs yet. Its parameters (w, h) are empty slots. A call runs it, supplying arguments (3, 4): the actual values. The return value is what comes back and replaces the call.

Key idea

Arguments are copied into parameters. The function works on its own copies, and only the return value comes back out.

The call stack remembers who is waiting

The pile of notes in the last figure is the call stack, and each note is really a whole frame: the call’s parameters, its local variables, and the place to resume.

Definitions

A frame is the private workspace of one call: its parameters, its local variables, and a return address. The call stack is the pile of frames for calls that have started but not finished. Only the top frame runs.

Here main calls hyp2, which calls square twice. Step through and count the frames. The strip on the right is a timeline: every call’s bar sits inside the bar of the call that made it.

Each square call has its own x. The second one reuses the stack space the first one left, but it is a fresh frame with a fresh variable. Calls end in the reverse order they began: last in, first out, exactly the stack of lesson 09.

Local scope: who can see what

A frame’s variables are local: only code running in that call can read them. Variables written outside every function are global and every call can read them. The region where a name works is its scope.

Why the seal is a good thing

main called double, yet double cannot read main’s x. That is why you can rename a local variable, or reuse n in a hundred functions, without one call disturbing another.

Numbers in the box, objects on the heap

A number fits inside a variable’s box in the frame. An array can be any length, so it is built in a separate region called the heap, and the variable holds only a reference: an arrow to it.

Definitions

The heap is memory for objects that outlive the call that made them. A reference is a value that says where an object is; it is drawn as a dot in the variable and an arrow to the object.

Two tiny programs make the same moves: store, copy, change, print. Predict what the right-hand one prints, then step.

Key idea

Assignment always copies what is in the box. For a number, that is the number. For an array, that is the arrow: you get a second name for the same array, which is called aliasing.

What a function can change

A call copies its arguments into parameters, the same way assignment does. So what a function can affect depends on what is in the box it was handed.

Three rules cover almost every case. A function cannot rebind its caller’s variables through its parameters. It can change an object it was handed a reference to. And the only value that always comes back is the one it returns.

“Pass by value” or “pass by reference”?

JavaScript and Python always pass a copy of the box’s contents. When that content is a reference, the copy still leads to the same object. That is why mutation is visible, yet reassignment is not.

Where frames live, and what happens when they run out

A running program gets a block of address space. The code sits at the bottom, then the globals. The heap starts above them and grows up; the stack starts at the top and grows down. Between them is free space.

The stack’s size is fixed before the program starts. Each call needs a frame, so a function that keeps calling itself uses up the stack. Watch a countdown with and without the line that tells it to stop.

Preview of recursion

A function that calls itself is recursion. It is safe when a base case stops the chain before the stack fills, which is the subject of lesson 12.

What it costs

A call is cheap: pushing and popping a frame takes a fixed number of machine steps, whatever the function does. What grows is the space the frames occupy, because every call in progress holds one.

Fun fact

The stack size is a setting, not a law. The main thread of a typical desktop program gets a few megabytes, and a few dozen bytes per frame is enough to fit tens of thousands of frames in C. JS and Python frames are far bigger than C ones, which is why their typical limits sit near ten thousand frames or lower. Deep recursion on huge inputs is where programs hit the wall.

Variations and patterns

Everything above adds up to a design habit. A pure function depends only on its arguments and changes nothing outside itself, so the same call always gives the same answer. A side effect is any change that outlives the call: mutating an argument, changing a global, printing.

Pick a function below and step through it. Watch which arrows and boxes change, and where.

Rule of thumb

Prefer returning a new value. When you must change something a caller handed you, say so in the function’s name and comment. Copy first when the caller’s data must stay safe.

History

1945the stack proposed

Alan TuringACE report, National Physical Laboratory

Early machines had no call instruction. On Cambridge’s EDSAC, David Wheeler’s trick was for a subroutine to rewrite its own last jump so it returned to whoever called it, which breaks the moment a routine calls itself. Alan Turing had already proposed the fix in 1945: file return addresses in a last-in, first-out list, using routines he named BURY and UNBURY.

In 1957 Friedrich Bauer and Klaus Samelson patented the same idea as the Kellerprinzip (“cellar principle”), and by 1960 ALGOL put every call’s local variables in a stack frame.

Sources: Turing’s ACE report (1945–46); Wilkes, Wheeler and Gill, The Preparation of Programs for an Electronic Digital Computer (1951); Bauer and Samelson’s patent application (30 March 1957); Dijkstra, “Recursive Programming”, Numerische Mathematik 2 (1960).

Practice

  1. Trace by hand
    Easy

    Draw the stack, frame by frame, for f(2) where f(x) = g(x) + g(x + 1) and g(y) = y * y. What is the deepest the stack gets, and what does f(2) return?

  2. Two names, one array
    Easy

    Given a = [1, 2]; b = a; b = b + [3] in Python, and a = [1, 2]; b = a; b.push(3) in JavaScript, what is a in each case? Draw the arrows to explain the difference.

  3. A swap that works
    Medium

    Write swap(a, i, j) that exchanges two slots of an array. Then explain, using frames, why swap(x, y) on two numbers cannot work in JavaScript or Python.

  4. How deep can you go?
    Medium

    A stack is 8 MB and each frame of your function takes 64 bytes. About how many nested calls fit? Rewrite a function that recurses n times so it uses a loop and needs only one frame.

  5. Deep copy
    Hard

    Write a function that copies a nested array such as [1, [2, 3], [4, [5]]] so that changing any level of the copy never affects the original. Why does slice() alone not do it?
