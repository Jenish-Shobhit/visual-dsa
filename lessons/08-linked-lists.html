Linked lists

Store order in pointers instead of positions. Splicing a node in costs two pointer writes; reaching the node at index 500 costs 500 hops.

The problem

A music app keeps your queue in an array. Every time you press “play next”, the new song has to go at the front, so every song already queued slides one slot to the right.

Press the button a few times and watch the two counters. The top row is the array; the bottom row stores the same songs as a linked list.

The array pays one move per song already queued, and the bill grows with the queue. The list pays two pointer writes, every time. This lesson is about that second structure: what it is, why the order of those two writes matters, and what it gives up in return.

Build the intuition

Think of a scavenger hunt. You hold one clue. It tells you where the second clue is hidden, the second tells you where the third is, and the last one says “the end”.

Analogy: clues that point to clues

The spots are scattered anywhere in the park, and the order lives only on the cards. To reach the fourth clue you must read the first three. That is exactly how a linked list trades speed of access for freedom of placement.

Where the analogy breaks

A hunt is fixed once it is hidden. In a list you can rewrite a card at any time: point it somewhere new and you have inserted or removed a stop, without moving anything else.

Memory is the park. Each node sits wherever the allocator found room, and its next field holds the address of the next node. Shuffle the nodes to new addresses: the arrows follow, the stored addresses change, and the order stays the same.

Nodes, next and null

Definitions

A node is a small record: a value plus a next pointer, the address of the following node. head is a variable holding the address of the first node. The last node, the tail, has next = null: “no next node”. An empty list is head = null.

Walking the list

An array finds index i with arithmetic: base address plus i times the element size. A list has no such formula, because the nodes’ addresses are unrelated. The address of node i is written inside node i − 1, so you have to read your way there.

Key idea

The loop curr = curr.next is the only way to move. Reading index i costs i hops, so random access is O(n) in the worst case, against for an array.

Insert: two writes, in the right order

To put a new node after a node you hold, called prev, you change two pointers: the new node’s next, and prev.next. Nothing else moves. Inserting at the front is the same idea with head playing the role of prev.next.

The two writes are not interchangeable. prev.next is the only pointer to the rest of the list, so if you overwrite it first, the rest of the list is gone. Watch it happen, then switch to the right order.

Keep your grip

Before you overwrite a pointer, make sure something else already holds the address it stored. Copy first (node.next = prev.next), redirect second (prev.next = node).

The “O(1) insert” half-truth

The two writes cost O(1) only once you hold prev. Given an index, you first walk i − 1 hops to find it, so insert-at-index is O(i), just like the array’s shifting.

Delete: bypass, then let go

To remove a node, make its predecessor skip over it: prev.next = prev.next.next. One write. The skipped node is still in memory with its arrow intact, but nothing points to it, so it is unreachable and gets reclaimed.

The head has no predecessor, so deleting it moves head instead. That special case is why the decision flowchart has two branches. Pick a case and step through: the list and the flowchart move together.

Why prev, and not curr?

In a singly linked list a node cannot see who points at it. So the walk keeps prev one step behind the candidate: when the candidate matches, prev is exactly the node whose pointer must change.

Doubly linked lists

Give every node a second pointer, prev, to the node before it. Now a node can reach both neighbours, so you can walk backwards, and you can delete a node you hold without searching for its predecessor.

The price is one more pointer per node, and twice the surgery: an insert rewires four pointers, a delete two. The order rule still applies: wire the new node first, then the neighbours, and overwrite your route last.

Reverse a list in place

Reversal is the classic pointer workout. Walk the list once with three pointers: prev (the reversed part so far), curr (the node being flipped) and next (your grip on the rest). Each step flips one arrow.

Nothing is copied and no node moves. Only arrows change, so the extra space is and the time is .

The one line you cannot drop

Without next = curr.next, the flip overwrites the only pointer to the rest of the list, and the loop has nowhere to go. It is the same “keep your grip” rule as insertion.

Two speeds: fast and slow pointers

Send two pointers down the list together, one taking a step per turn and the other two. When the fast one reaches the end, the slow one has covered half the distance: it stands on the middle node, found in one pass without knowing the length.

Now suppose a bug made the last node point back into the middle of the list. A walk would never meet null; it would circle forever. The list has the shape of the letter ρ: a tail of μ nodes leading into a loop of λ nodes.

Put a tortoise (1 step per turn) and a hare (2 steps) at the head. If there is no loop, the hare hits the end. If there is one, both end up circling it, and the hare, gaining one step per turn, must land on the tortoise. Predict first.

Why they must meet, and why phase 2 finds the entry

Once both are on the loop, say the hare is g steps behind. Each turn the tortoise adds 1 and the hare adds 2, so the gap becomes g − 1. It counts down 3, 2, 1, 0: the hare cannot jump over, because the gap never skips a number.

At the meeting the tortoise has walked μ + k steps (μ to reach the loop, k more inside it) and the hare 2(μ + k). The hare’s extra μ + k steps were whole laps. So from the meeting point, μ more steps completes a lap and lands on the entry, exactly where a walker starting μ steps away at the head arrives.

The hidden charge: cache misses

Big-O says a full scan costs O(n) for both. Real hardware disagrees. Memory arrives in 64-byte cache lines, so an array scan gets about 16 integers per fetch, while each list hop jumps to an unrelated address and often waits for main memory, about 50 times slower. A list scan is commonly 10 times slower or worse. Choose a linked list for cheap splicing of nodes you already hold, not for speed of traversal.

Variations and patterns

Real code rarely uses the bare singly linked list. These small changes remove special cases or unlock new tricks.

A dummy (or sentinel) node sits in front of the first real node and is never deleted. Every real node now has a predecessor, so deleting or inserting at the front uses the same line as anywhere else.

Compare the two runs: both delete the first value, but only one needs the head = head.next branch. Many interview solutions start with dummy = new Node(0, head) and return dummy.next.

In a circular list the tail points back to the head, so there is no null to stop at. You stop when you come back to where you started: do { visit(curr); curr = curr.next } while (curr != head).

Round-robin schedulers and music players on repeat use this shape. A doubly linked circular list with one dummy node is how many standard libraries implement their list type: no null checks anywhere.

Given only a pointer p into a singly linked list, you cannot unlink p: its predecessor is unknown. The trick is to copy the successor’s value into p, then unlink the successor instead.

It fails on the tail, which has no successor, and it quietly moves a value between nodes, so any other pointer to the old successor now dangles. A classic interview answer and a classic source of bugs.

History

1955IPL and the Logic Theorist

Allen Newell, Cliff Shaw, Herbert SimonRAND Corporation and Carnegie Tech

Linked lists were built for artificial intelligence. In 1955–56 Newell, Shaw and Simon needed data that could grow and change shape while their Logic Theorist program searched for proofs, so their language IPL joined memory cells with links, drawn, as you still see them, as boxes and arrows. Newell and Simon later shared the 1975 Turing Award.

In 1958 John McCarthy’s LISP made the two-part cell, a value and a pointer to the rest, the building block of a whole language. The tortoise-and-hare cycle test is credited to Robert Floyd by Donald Knuth, who set it as an exercise in The Art of Computer Programming; no paper by Floyd describing it is known. Richard Brent published a faster variant in 1980.

Sources: “Information Processing Language”, Wikipedia; D. E. Knuth, The Art of Computer Programming, Vol. 2, §3.1, exercise 6 (Floyd’s cycle-finding); R. Brent, “An improved Monte Carlo factorization algorithm”, BIT 20 (1980).
