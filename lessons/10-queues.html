Queues & deques

The fairest way to wait, and the trick that makes it fast: a circular buffer that reuses its own slots. Then a queue with two open ends that answers sliding-window questions in one pass.

  • 28 min
  • Beginner to intermediate
  • Needs: arrays

Who goes next?

A ticket window serves one person at a time. The fair rule is old and obvious: whoever arrived first is served first. Break that rule and someone can wait forever, which in software is a print job that never prints or a request that never gets an answer.

Run the window yourself. Add people at the back, serve the front, and watch how long the longest-waiting person has been there.

Definition

A queue is a sequence that you may only change at its two ends: enqueue adds a value at the rear, dequeue removes the value at the front. The order out is the order in: first in, first out, or FIFO.

Three ways to wait

Restricting where you may touch a sequence sounds like a loss. It is a bargain: if you promise to work only at the ends, every operation can be made constant time. Which ends you allow gives three different tools.

Where the line analogy breaks

In a real line people leave, cut in, or swap places. A queue in a program allows none of that: you can look at the front, add at the rear, and remove the front. Nothing in the middle is reachable, and that is exactly why it is cheap.

The four operations

A queue needs only four operations. Step through them below. Notice that the front and rear markers do all the work: nothing in the middle ever moves.

Underflow

Removing from an empty queue is called underflow. Every implementation must decide what it does: raise an error, return “nothing”, or wait until a value arrives. Deciding nothing means a crash or, worse, quiet garbage.

The table says “O(1)”, but that promise depends on how you store the queue. The obvious array version breaks it.

Two ways to break an array queue

Store the queue in an array of fixed size, with the front at slot 0. Enqueue writes at the rear. Dequeue removes slot 0, and now the front is empty. There are two obvious fixes, and each has a flaw. Run the same operations on both.

Shift left: slow

Each dequeue slides every remaining value one slot: about n moves. A queue of a million values does a million moves to hand out one value.

Move front: wasteful

Nothing slides, but the slots behind the front are never used again. The rear runs out of array while most of it is empty.

We want the speed of the second and the thrift of the first. The key is to let the rear wrap around into the space the front has left behind.

Bend the array into a ring

Take the same array, but treat slot C − 1 as if it were followed by slot 0. The array becomes a ring of C slots. Keep two facts: head, the slot of the front value, and size, how many values are stored.

The one formula

The value at position k of the queue (0 is the front) lives in slot (head + k) mod C. So the next value goes to (head + size) mod C. The mod is the wrap-around: when the sum runs off the end of the array it comes back at slot 0.

Drag the sliders. Watch the numbered values glide round the ring as head moves, and find a case where the sum reaches C or more.

Enqueue writes one slot and adds one to size. Dequeue reads one slot, moves head one step, and subtracts one from size. No value ever moves, so both operations are O(1) with no shifting, and freed slots are reused at once.

When the buffer is full, something has to give. Systems reject the new value (a bounded queue), block the producer until there is room, overwrite the oldest value (audio, sensor data, logs), or grow the array by doubling it. Try Overwrite oldest in the lab.

A queue made of nodes

A linked list can play the same role, with no fixed size. Keep a head pointer at the front node and a tail pointer at the rear node. Enqueue links a new node after the tail; dequeue moves the head one node along.

The classic bug

When the last node is dequeued, head becomes null, and tail must become null too. If you forget, tail keeps pointing at a node that left the queue, and the next enqueue links to a ghost. Choose Drain to empty to see the moment.

Deque: both ends open

A deque (say “deck”, short for double-ended queue) allows insert and remove at both ends. Used at one end it is a stack; pushing at the back and popping at the front makes it a queue. A ring buffer supports it directly: the front moves backwards when you push at the front.

The negative-modulo trap

Moving head backwards needs (head − 1 + C) mod C. In many languages (−1) mod C is −1, not C − 1, and the index falls off the array. The + C is the whole fix.

Same arrivals, different service

A stack and a queue accept values the same way. They differ only in which value they hand back. Feed both the same arrivals and the same service calls, then compare who waited how long.

Starvation

With a steady flow of arrivals, a stack keeps serving the newest value and the oldest sits at the bottom forever. That is starvation. A queue rules it out: nobody waits behind a value that arrived after them.

Sliding window maximum

Given a list of numbers, report the largest value in every window of k consecutive numbers. Scanning each window costs about n · k. A deque does it in one pass, by remembering only the values that could still become a maximum.

The trick

Keep indices in a deque, ordered so their values decrease from front to back. The front is always the window maximum. When index i arrives: drop the front if it has left the window, pop from the back every value that is not larger than nums[i] (it can never win again), then push i.

Why it is O(n)

Each index is pushed once and popped at most once, from one end or the other. Over the whole scan that is at most n pushes and n pops, so at most about 2n comparisons, however large k is.

Variations and patterns

A queue built from two stacks

If all you have are stacks, you can still build a queue. Push every enqueue on an inbox. To dequeue, pop from an outbox; when it is empty, pour the whole inbox into it. Pouring reverses the order, which puts the oldest value on top.

One dequeue can move many values. But each value crosses over at most once, so any run of n operations does O(n) work in total: amortized O(1) per operation.

A queue feeding a flood fill

Breadth-first search explores a maze or a graph outward, one ring of distance at a time. Its engine is a queue: cells leave in the order they were found, so all the cells at distance d are expanded before any at d + 1. You will meet it in full in Unit 6; here is the queue at work. So a queue’s O(1) is real for a circular buffer and a linked list, and false for the naive shifting array. Each stored value is touched a constant number of times on its way through.

The window lab has its own cost story: the deque never does more than 2n comparisons, while checking every window costs about n · k.

Why does dequeue on a shifting array cost n?

The front value is read, and every one of the other n − 1 values is copied one slot to the left to close the gap: n − 1 writes plus one read. A circular buffer never copies: it moves the head index instead, which is one addition and one remainder, however many values are stored.

Why is the two-stack queue O(1) amortized?

A value is pushed on the inbox once, popped from it once, pushed on the outbox once, and popped from it once: four stack operations in its whole life, whatever the queue length. A single dequeue can pour many values, but each value is poured at most once. So n operations cost at most 4n stack operations, and the average per operation is a constant.

History

1909the first queueing theory

Agner Erlang“The Theory of Probabilities and Telephone Conversations”

Queueing theory began in a telephone exchange. In 1909 the Danish engineer Agner Erlang worked out how calls that arrive at random pile up waiting for a free line, the first paper on the mathematics of waiting.

In the 1960s Kristen Nygaard and Ole-Johan Dahl met the difference between a queue and a stack head-on. Their SIMULA simulations needed customers to leave a queue in the order they joined, which ALGOL’s stack could not do. Dahl moved the data to a heap, and the idea of objects was born. The word “deque” is credited by Knuth to E. J. Schweppe. And on 20 July 1969 the Apollo 11 computer, overloaded during the landing, raised its 1201 and 1202 alarms and shed low-priority jobs: a priority queue at work, on the flight software led by Margaret Hamilton.

Sources: A. K. Erlang, Nyt Tidsskrift for Matematik B 20 (1909); R. C. Martin, We, Programmers (2025), ch. 7 and cast of characters; D. E. Knuth, The Art of Computer Programming, Vol. 1, §2.2.1.

  1. Design a circular queue
    Medium

    Implement MyCircularQueue(k) on a fixed array with enQueue, deQueue, Front, Rear, isEmpty and isFull, all in O(1). State which fields you keep, and argue that full and empty can never be confused.

  2. Queue using two stacks
    Easy

    Implement push, pop, peek and empty of a FIFO queue using only two stacks. Prove that pop is O(1) amortized even though a single call can take O(n).

  3. Number of recent calls
    Easy

    Write ping(t), called with strictly increasing times in milliseconds, that returns how many pings happened in the last 3000 ms (including this one). Which end of your queue do old pings leave from?

  4. Design a circular deque
    Medium

    Add insertFront, insertLast, deleteFront and deleteLast to your circular queue. Handle the wrap when insertFront moves head below 0, and explain why (head − 1) % k is not enough in many languages.

  5. Sliding window maximum
    Hard

    Given an array and a window size k, return the maximum of every window in O(n). Prove that the deque’s values are strictly decreasing at every step, and change the pop rule to < instead of ≤: what changes, and is the answer still correct?
