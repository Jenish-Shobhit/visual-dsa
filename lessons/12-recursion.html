Recursion

A function that solves a problem by trusting a smaller copy of itself. Watch the calls pile up, hit a base case, and hand their answers back.

  • 20 min
  • Beginner to intermediate
  • Needs lesson 04: functions and the stack

The problem: folders inside folders

Your laptop wants to show how many files live under a folder. The folder holds files, and also folders, which hold files and more folders. You don’t know how deep it goes, so no fixed number of loops can do the job.

One rule works at every level: a folder’s total is its own files plus the total of each subfolder. The rule uses itself. Before you step through it, try the question under the figure.

Notice the order. home/ was the first folder asked and the last to answer. The deepest folders answer first, and their totals travel back to whoever asked. Last asked, first answered: that order is the heart of recursion.

Build the intuition

You sit in a dark cinema and want to know your row number. You can’t see enough to count the rows, but you can whisper to the person in front of you.

Analogy: which row am I in?

Ask the person in front which row they are in, then add one to their answer. They do exactly the same thing. The person in the front row doesn’t need to ask anyone: the screen is right there.

Where the analogy breaks

In the cinema each question goes to a different person. In a program there is one function: every call runs the same code with its own arguments, in its own frame. And the machine has a limited number of seats for waiting calls. You will hit that limit later in this lesson.

Two parts: a base case and a smaller self

Every recursive function has the same two parts. Take factorial: 4! means 4 × 3 × 2 × 1. The part after the 4 is 3!, the same kind of problem, only smaller.

Definitions

A base case is an input the function answers directly, without calling itself: fact(0) = 1. The recursive case answers every other input from a smaller one: fact(n) = n × fact(n − 1).

You can run that definition by hand. Replace each call with its definition until no calls are left, then multiply. Step through the rewriting and count the multiplications that have to wait.

Key idea

Two obligations make a recursion correct. Every call must move closer to a base case, and the answer from the smaller call must be enough to build the current answer.

The call stack remembers who is waiting

The rewriting above hides a question: where does the waiting 4 × … live while fact(3) runs? The machine keeps it in a frame, and piles frames on the call stack.

Definitions

A frame holds one call’s arguments, its local variables and the line to resume at. The call stack is the pile of frames for calls that have started but not finished. Only the top frame runs.

Step through fact(4). A frame drops onto the stack when a call begins. A return marks it done, lifts it off, and hands its value to the frame below. The chart traces the stack’s height over time.

Each frame has its own n. When fact(4) calls fact(3), its n does not become 3. A new frame appears with a new n, and the old one waits underneath, unchanged.

Why a stack?

The last call to start is always the first to finish, so the frame that runs next is always on top. Last in, first out: exactly the stack from lesson 09.

The leap of faith

Tracing every frame works for fact(4). It does not work for a folder tree ten levels deep. Experienced programmers reason differently: they assume the smaller call already works, and only check that one level is right.

Drag the slider to open the boxes. Closed, a box is a promise: total(rest) returns the right sum. Open, it holds the same one-line rule, all the way down to the base case. The arithmetic at the top never changes.

This is induction

If the base case is right, and each level is right whenever the level below it is right, then every level is right. That argument, mathematical induction, is why you may trust the box without opening it.

Writing a recursive function

Every recursive function you write follows one recipe. The flowchart is wired to the lab: step the lab and the current box lights up. Look for the arrow from “call f on a smaller input” back to the top. That loop is the recursion.

When you write one, work in this order:

  1. Find the smallest inputs and answer them directly.
  2. For any other input, pick a smaller input of the same kind.
  3. Assume the call on it works, and build your answer from its answer.
  4. Check that every path shrinks toward a base case.

When a call branches: recursion trees

Factorial calls itself once, so its calls form a single chain. Fibonacci calls itself twice: fib(n) = fib(n − 1) + fib(n − 2), with fib(0) = 0 and fib(1) = 1. Draw each call under the call that made it and you get a tree.

Definition

A recursion tree has one node per call and an edge from each call to the calls it makes. At any moment the call stack is one path in it, from the root down to the running call.

Drag n up and watch the tree explode. Colour marks the argument: every fib(3) has the same colour, and each one redoes the same work. Press a colour chip to light up every copy.

Now switch on remember answers. Each fib(k) is computed once and stored; every later request is a lookup, drawn as a hollow ring. The tree collapses to a chain with short spurs: 2n − 1 calls instead of millions.

Memoization, a preview

Storing answers so that repeated subproblems cost nothing is called memoization. It is the first step toward dynamic programming in lesson 34.

Tower of Hanoi

Three pegs hold a tower of discs on the first. Move the whole tower to the last peg. Only one disc moves at a time, and a larger disc may never sit on a smaller one.

It looks hard until you think recursively. To move n discs from A to C: move the top n − 1 to B, out of the way. Move the biggest disc to C. Then move the n − 1 from B onto it. Moving n − 1 discs is the same puzzle, smaller.

Why exactly 2ⁿ − 1 moves?

Moving n discs costs two moves of n − 1 discs plus one: M(n) = 2·M(n − 1) + 1, with M(1) = 1. That gives 1, 3, 7, 15, 31, … = 2ⁿ − 1. No method does better: the largest disc must move at least once, and before it can, every other disc must be off it and off the target peg.

The end of the world

Édouard Lucas sold the puzzle in 1883 with a legend: priests move a tower of 64 golden discs, and the world ends when they finish. At one move per second, 2⁶⁴ − 1 moves take about 585 billion years, more than 40 times the age of the universe.

When the base case is missing

Delete the base case and nothing tells the function to stop. Each call makes another, every frame waits for one that never returns, and the stack fills up. This toy stack holds 8 frames.

Real stacks are bigger, but never infinite. Python stops at 1,000 nested calls by default. Browsers allow thousands to tens of thousands for a small function, depending on the engine and the size of each frame.

Two ways to overflow

A missing base case, or a step that never reaches it: countdown(n + 1) moves away from 0, and fact(−1) skips past n == 0 forever. Check that every path strictly shrinks toward a base case.

Recursion or a loop?

Anything recursion computes, a loop with a stack can compute too, and the reverse. The difference is memory and clarity. Plain recursion keeps one frame per pending call; a loop keeps one frame.

The middle lane is a tail call: the recursive call is the very last thing the function does, so nothing is left pending. The running product travels in an extra argument, acc. A compiler can then reuse the frame instead of stacking a new one.

Don’t count on frame reuse

Scheme guarantees it for every tail call. Python never does it, and among the major JavaScript engines only Safari’s does. In most languages you use, a deep tail recursion still overflows: write the loop.

So when should you recurse? Walk the decision tree: press the answer that fits your problem.

Recursion you can see

Recursion also draws. A tree is a trunk with two smaller trees on top; each of those is a trunk with two smaller trees; stop at some depth. That sentence is the whole program.

Each extra level doubles the newest branches, so depth d draws 2d+1 − 1 segments. That is Hanoi’s count again, for the same reason: every call makes two more.

What it costs

Two numbers describe a recursion’s cost. Time grows with the number of calls: every node of the recursion tree. Space grows with the deepest the stack gets: the tree’s height, because only one root-to-leaf path is on the stack at a time.

The shape decides the growth. A chain grows linearly, halving grows logarithmically, and two calls per call grow exponentially. Switch the chart to the log scale to see all five at once.

Hidden cost: slicing

The lab’s total(a[1:]) copies the rest of the list at every call: n + (n − 1) + … + 1 copied items, which is O(n²) time. Pass an index instead, total(a, i) with the base case i == len(a), and the work drops to O(n).

Why does naive fib make about 1.6ⁿ calls?

calls(n) = calls(n − 1) + calls(n − 2) + 1. That is the Fibonacci recurrence itself (plus one), so the call count grows like fib(n), by a factor of φ ≈ 1.618 per step. Exactly: calls(n) = 2·fib(n + 1) − 1, so fib(30) makes 2,692,537 calls.

Why is the space only O(n) when the time is exponential?

A frame is popped as soon as its call returns, and its memory is reused by the next call. The stack only ever holds the calls on one path from the root, and the longest path in fib’s tree is fib(n), fib(n − 1), …, fib(1): n frames.

Variations and patterns

The same shape, a base case plus a smaller self, shows up across strings, arrays and whole algorithm families.

A string is a palindrome when its first and last characters match and the inside is a palindrome. Empty and one-character strings are base cases, and so is a mismatch: the answer is false without another call.

History

      

        
1960ALGOL 60

        
Edsger W. Dijkstra and Jaap Zonneveldthe first ALGOL 60 compiler, Amsterdam

        

          
Recursion was controversial. Most of the ALGOL 60 committee thought it too slow to be worth having and voted it out, but the report’s wording was ambiguous enough to let it in. Dijkstra, who had argued for it with John McCarthy, implemented it anyway with Jaap Zonneveld, giving every call its own frame on a stack: the design you traced in this lesson.

          
The examples are older. Fibonacci’s rabbit puzzle dates from 1202, and Édouard Lucas sold the Tower of Hanoi in 1883 under the pen name “N. Claus de Siam”.
