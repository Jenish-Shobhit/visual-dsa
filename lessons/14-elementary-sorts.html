Bubble, selection & insertion sort

Three simple ways to put values in order. Each one keeps a different promise as it runs, all three are quadratic in the worst case, and one of them is surprisingly hard to beat on nearly sorted data.

  • Beginner
  • Needs: arrays, Big-O

Why put things in order?

A shuffled list answers questions slowly. To find a name you must look at every entry; to find duplicates you must compare every pair. Sort it once, and binary search finds any name in about 20 looks out of a million, and duplicates sit side by side.

Definition

An array is sorted when every value is at most its right neighbour: a[0] ≤ a[1] ≤ … ≤ a[n − 1]. So a single out-of-order neighbour pair is proof that the array is not sorted yet.

Try it by hand. You may only swap two neighbours. Red buttons sit between neighbours that are out of order; the array is sorted when none are left.

Every sorting algorithm in this lesson does what you just did, but by a fixed rule. To compare them we count two operations: comparisons (“is a[j] > a[j + 1]?”) and moves (swaps or shifts that write values into the array).

The cost model

We measure a sort by how many comparisons and moves it makes on an array of n values, and how that number grows with n. Time on a real machine tracks these counts roughly (caches and branch prediction matter too).

Three ways people sort

You already know all three algorithms. Each one is a habit people use without thinking: let big things rise, keep picking the smallest, or slide each new item into place.

Where the analogies break

A person sees the whole row at once and jumps a card straight to its slot. An algorithm sees only the two values it is comparing. It learns the order one comparison at a time, and that limit is what the cost counts.

Bubble sort: neighbours trade places

Walk left to right comparing each pair of neighbours, and swap when the left one is larger. The largest value never loses a comparison, so it is carried right and one pass parks it at the end.

Invariant

After pass k, the last k positions hold the k largest values in their final places: no later swap will ever touch them. So each pass can stop one position earlier than the last.

Pick Sorted input in the figure. The first pass finds no pair out of order, and a pass with no swaps proves the array is sorted. This early exit turns bubble sort’s best case into n − 1 comparisons.

Selection sort: pick the smallest

Scan the whole unsorted part and remember where its smallest value is. Then make one swap to put that value at the front of the unsorted part. The front grows by one final value per pass.

Invariant

After pass k, the first k positions hold the k smallest values in their final places. The rest is untouched except for the one value each swap sent away.

Few swaps, many comparisons

Selection sort makes at most one swap per pass, so at most n − 1 swaps in total. But it cannot know a value is the smallest without looking at every other one, so it always makes n(n − 1)/2 comparisons, even on sorted input.

Insertion sort: slide into place

Treat the left part as a sorted hand of cards. Lift the next value, the key, out of the array, leaving a hole. Shift every larger value in the hand one slot right, then drop the key into the hole.

Invariant

After round k, the first k + 1 values are sorted among themselves. They are not final: a small key still to come will push them all one slot right. That is why the prefix is purple, not green.

Adaptive

A key stops as soon as it meets a value no larger than itself. On sorted input every key stops at once, so insertion sort makes only n − 1 comparisons. Pick Sorted input to watch it. A sort whose cost shrinks when the input is already partly ordered is called adaptive.

Key idea

An invariant is the promise a loop keeps after every round. Bubble sort promises a final suffix, selection sort a final prefix, and insertion sort only a sorted prefix. When the loop ends, each promise covers the whole array, and that is the proof the sort is correct.

Stability: equal keys keep their order

Often you sort records by one field while they carry others, such as cards by rank while each has a suit. If two cards share a rank, should their order survive the sort? A stable sort promises that it does.

Definitions

A sort is stable if values with equal keys come out in the same order they went in. A sort is in place if it needs only a constant amount of extra memory, or at most a small recursion stack (quick sort, in lesson 16, uses O(log n)); all three sorts here are.

Selection sort’s swap sends a[i] on a long jump to wherever the minimum was, and that jump can carry it past an equal card. Bubble and insertion sort only ever move a value past a strictly larger or smaller neighbour, so equal cards never cross.

Inversions: a measure of disorder

How unsorted is an array? Count the pairs that are in the wrong order. A sorted array has none; a reversed array of n values has all n(n − 1)/2 of them.

Definition

An inversion is a pair of positions i < j with a[i] > a[j]. In the figure, each inversion is an arc joining the two values.

Why shifts equal inversions

Moving a value past one neighbour changes the order of exactly that one pair. When the pair was inverted, the move fixes it and touches no other pair. So insertion sort makes exactly one shift per inversion, and bubble sort exactly one swap per inversion. Insertion sort costs about n + (number of inversions), which is why it flies on nearly sorted data.

So all three are in the worst case: on a reversed array of 1,000 values, each makes 499,500 comparisons. Insertion sort’s cost is really O(n + inversions), which is why real libraries use it for short or nearly sorted runs.

Where does n(n − 1)/2 come from?

Bubble sort’s first pass compares n − 1 pairs, the next n − 2, and so on down to 1. Selection sort’s passes scan n − 1, n − 2, …, 1 values. Both add up to 1 + 2 + … + (n − 1) = n(n − 1)/2, the number of pairs among n values.

Why is the average about n²/4 for insertion sort?

Each of the n(n − 1)/2 pairs is inverted with probability 1/2 in a random order, so a random array has about n(n − 1)/4 inversions on average. Insertion sort makes one shift per inversion and about one comparison per shift.

Variations and patterns

Small changes to these loops show up everywhere, from library sorts to interview questions.

Remember where the last swap happened. Everything after it is already in order, so the next pass can stop there, and a pass with no swap at all ends the sort. The same one-pass check is the cheapest way to test “is this array sorted?”.


        
Bubble sort moves a large value to the end in one pass, but a small value near the end creeps left only one step per pass. Sweeping right and then left fixes both ends. It is still quadratic in the worst case.

        
The prefix is sorted, so binary search can find the key’s slot with far fewer comparisons. The shifts stay the same, so the sort is still quadratic, but it helps when comparisons are expensive, such as long strings.

        
Insertion sort is slow when a value is far from home, because it moves one slot per shift. Shell sort runs insertion sort on values a large gap apart first, then smaller gaps, and finally gap 1. Donald Shell published it in 1959.

        
Selection sort’s prefix is final after every pass, so stopping after k passes gives the k smallest values in order, for about k · n comparisons. For small k this beats sorting everything.

History

      

        
1956“sorting by exchange”

        
Edward Friend and Kenneth IversonJACM survey (1956) · A Programming Language (1962)

        

          
Bubble sort was analysed in 1956 by Edward Friend as “sorting by exchange”, in one of the first surveys of sorting on electronic computers. It got its catchy name from Kenneth Iverson’s 1962 book. Donald Knuth later judged that it has little to recommend it beyond that name and some interesting theory.

          
In 2007 Google’s Eric Schmidt asked presidential candidate Barack Obama for the most efficient way to sort a million 32-bit integers. Obama answered that “the bubble sort would be the wrong way to go”. Insertion sort lives on inside fast library sorts, and in 1959 Donald Shell turned it into Shellsort by inserting over long distances first.

        

        
Sources: E. H. Friend, “Sorting on Electronic Computer Systems”, JACM 3(3), 1956; O. Astrachan, “Bubble Sort: An Archaeological Algorithmic Analysis” (SIGCSE 2003); D. E. Knuth, The Art of Computer Programming, Vol. 3, §5.2.2; D. L. Shell, CACM 2(7), 1959.
