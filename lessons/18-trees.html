Trees & traversals

A tree is a hierarchy with one root and no loops. Four different walks visit every node, and each one is the right tool for a different job.

  • 22 min
  • Intermediate
  • Needs: recursion, stacks, queues

The problem: real data nests

An array or a linked list is a line: every item has one item before it and one after. But a lot of real information is not a line. A project has folders inside folders. A company has managers with teams, and those teams have leads with teams of their own. A web page has tags inside tags.

Pick one of the three below, then click any node that has something under it. It folds away, and a badge tells you how much is hidden.

All three have the same shape: one item at the top, every other item hangs under exactly one parent, and following parents upward always ends at the top. Nothing ever loops back. That shape is a tree, and it is the most common structure in computing after the array.

Build the intuition: a list that may branch

Analogy: a linked list with more than one “next”

In a linked list, each node points to one next node. In a tree, each node may point to several. You can also think of a family tree turned upside down: one ancestor at the top, each person under their one parent line.

Definition

A tree is a set of nodes joined by edges so that there is exactly one path between any two nodes. Equivalently: one chosen root, every other node has exactly one parent, and there are no loops. A tree with n nodes has exactly n − 1 edges.

Upside down

Computer scientists draw trees with the root at the top and the leaves at the bottom. It reads like an org chart and like a page of text: start at the top, go down.

The words, on a tree you can click

Trees come with a small vocabulary. Each term below is easier to see than to define, so click nodes in the figure and switch the highlight.

Family words

The root is the top node. Every other node has one parent (the node directly above it) and any number of children (directly below). Nodes with the same parent are siblings. A node with no children is a leaf. The ancestors of a node are its parent, its parent’s parent, and so on up to the root; its descendants are everything below it.

Number words

The subtree of a node is that node with all its descendants: a smaller tree of its own. The depth of a node is the number of edges from the root down to it. Its height is the number of edges on the longest path down to a leaf. A level is all the nodes at the same depth. The height of the whole tree is the height of its root.

Shapes, and the numbers that go with them

Most trees in this lesson are binary: each node has at most two children, a left and a right. Four shapes come up all the time, because they set how tall the tree is for a given number of nodes.

The shape decides the height. Level 0 holds one node, level 1 at most two, level 2 at most four, level d at most 2d. So a tree of height h holds at most 2h+1 − 1 nodes, and n nodes need a height of at least ⌊log₂ n⌋. At the other extreme, one node per level gives height n − 1.

Two ways to store a tree

The usual way is a node object with a value and links to its children. A complete tree has a second, pointer-free option: number the nodes level by level, left to right, and store them in an array in that order.


      
Because a complete tree has no gaps, the position in the array tells you the family. The children of index i sit at 2i + 1 and 2i + 2, and the parent sits at ⌊(i − 1) / 2⌋. Drag the slider to add nodes and click any node or cell.

      
      

    


    
    

      
One walk around the tree, three orders

      
To traverse a tree is to visit every node exactly once. Depth-first means going all the way down one branch before starting the next. There are three depth-first orders, and they all come from one idea: walk around the outside of the tree, keeping it on your left.

      
On that walk you touch every node three times: on the way down into it (left dot), when you come back up from its left side (bottom dot), and when you leave it for good (right dot). Press play and watch the three rows fill.

      
      

        
Key idea

        
Preorder counts a node at its left dot: node, then left, then right. Inorder counts it at the bottom dot: left, then node, then right. Postorder counts it at the right dot: left, then right, then node. Same walk, three different moments.

Expression trees: the shape is the meaning

      
A tree can hold arithmetic. Leaves are numbers, and every other node is an operator that combines its two children. Brackets disappear: the shape says what happens first. To get the value, each operator has to wait for both of its operands, which is a postorder walk.

      
Step through it. Then compare the three ways of reading the same tree out loud: prefix, infix and postfix are just preorder, inorder and postorder. Try the second and third expressions: the same digits and signs with different trees give different answers.

      
    


    
    

      
Answers that flow upward

      
The same pattern computes a lot of things. Ask every node a question about its subtree. Each node asks its children first and combines their answers. The height of a node is 1 plus the taller child. The size of a subtree is 1 plus the sizes of its children. The size of a folder is its files plus its subfolders.

      
Switch between the three and watch the chips fill from the leaves upward. The call stack on the right always holds one path from the root down to the node being asked.

      
      

        
Children before parent

        
Whenever a node’s answer depends on its children’s answers, you need postorder. Whenever a node has to hand something down to its children first (a path so far, a copy of itself), you need preorder. This one question decides most tree code you will write.

What it costs

      
Every traversal visits each node once and walks each edge twice, once down and once back up. That is 2(n − 1) edge walks and 3n dots on the Euler tour, so the time is O(n) for all four orders, whatever the shape.

        Why exactly n and not n log n?
        
Each node is entered once and left once, and the work in between is a fixed amount: a couple of comparisons and one write. Every edge is used twice (down, then up). Add it up: about 3n small steps. Nothing is ever visited a second time, so no branch of the tree is re-explored.

      

      

        Why is O(h) “good” or “bad”?
        
It depends on the tree. A complete tree of a million nodes has height 19, so the stack never holds more than 20 frames. A chain of a million nodes has height 999,999, and a recursive walk needs a million frames. That is why balanced trees, the topic of the next lessons, matter so much.

To print a tree row by row, use level order with one change. At the start of each round, note how many nodes are in the queue: exactly that many belong to the current level. Process just those, and their children form the next round.

        
To save a tree as text, write a preorder walk and put a # for every empty child. For this tree the text is . The markers make the text unambiguous: reading it back with the same recursion rebuilds exactly the same tree.

        
One order alone does not pin down a tree, but preorder plus inorder does (when values are distinct). Preorder starts with the root. In the inorder, everything before the root is the left subtree, everything after is the right. Recurse on each half.

        
Recursive depth equals the height plus one. For a bushy tree that is tiny, but for a chain of a million nodes it is a million frames, and Python (by default about a thousand frames) or a JavaScript engine (roughly ten thousand) will stop you long before.
The explicit-stack version keeps the same list of unfinished work on the heap, where a million entries are fine. The lab’s “Explicit stack” mode shows exactly that: same output, no recursion.

History

      

        
1857trees named

        
Arthur Cayley; Gustav KirchhoffKirchhoff, 1847; Cayley, 1857

        

          
Arthur Cayley named “trees” in 1857, while working on a problem about differential operators, and later counted how many labelled trees exist on n points: nn−2. Ten years earlier, Gustav Kirchhoff had already used spanning trees to analyse electrical circuits.

          
Chemists used trees to count possible molecules long before programmers held data in them. In computing, trees arrived in the 1950s: in code trees such as Huffman’s (1952) and in the first search trees. Donald Knuth’s Fundamental Algorithms (1968) made tree traversal and representation standard textbook material.

        

        
Sources: A. Cayley, “On the theory of the analytical forms called trees”, Philosophical Magazine 13 (1857); G. Kirchhoff, 1847; D. E. Knuth, The Art of Computer Programming, Vol. 1, §2.3.
