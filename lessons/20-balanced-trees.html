Balanced trees: AVL & red-black

A binary search tree is only fast while it stays short. Self-balancing trees fix their own shape after every insert and delete, with a few local rotations, so no input order can make them tall.

  • Intermediate
  • Needs: binary search trees

The problem: a tree that leans

A binary search tree finds a key by walking one path from the root, so a search costs as many comparisons as the tree is tall. That is wonderful when the tree is bushy: 15 keys fit in height 3. It is a disaster when the keys arrive already sorted, because every key then hangs off the end of one long branch.

Sorted input is not exotic. Timestamps, auto-numbered ids and the output of an earlier sort all arrive in order. Watch the same 15 keys go into a plain tree and into a tree that repairs itself, then search for the last key in both.

The fix cannot be “rebuild the tree when it gets tall”: that costs O(n) per repair. It has to be a small local change after each update, and it has to keep the sorted order intact. That change is the rotation.

Build the intuition: a rotation

Analogy: a hanging mobile

Add a weight to one arm of a mobile and it tips. You do not rebuild the mobile: you swing two neighbouring arms around each other and re-hang one dangling piece. Everything else keeps hanging exactly as before.

A rotation does exactly that to two neighbouring nodes. In the picture below, x and y are keys and A, B, C stand for whole subtrees of any size. Press a rotate button, or click x or y.

Key idea

A rotation lifts one node and lowers its neighbour, changes the parent of one subtree, and leaves the in-order sequence untouched. So a rotation can never break the binary search tree rule. It can only change the height. It takes O(1) time: three links change.

Now use rotations for real. This tree is a stick of seven keys. Click a node to rotate it up over its parent, and get the height down to 2. The badges are balance factors (you will meet them in a moment).

AVL trees: keep every node within one level

Definitions

The height of a node is the number of links on its longest path down to a leaf. A leaf has height 0 and an empty subtree has height −1. The balance factor of a node is height(left) − height(right). An AVL tree is a search tree in which every node’s balance factor is −1, 0 or +1.

Click any node. Its left subtree turns cyan and its right subtree amber, and the caption does the subtraction.

This tree has been given one insert too many on its left. Several nodes on the way up have a balance factor of +2, because a tall spot makes every ancestor tall too. Rebalancing starts at the lowest one.

Four cases, two kinds of fix

When a node reaches balance factor ±2, look at the path from it toward the heavy side: down one link, then down one more. That path either runs straight or bends. A straight path (left-left or right-right) is cured by one rotation. A bend (left-right or right-left) needs two, because one rotation would only move the bend from one side to the other.

Why the height stays logarithmic

How tall can an AVL tree with n keys get? Turn the question around: what is the fewest nodes an AVL tree of height h can have? The thinnest tree lets one side be exactly one level shorter at every node. So it is a root, plus the thinnest tree of height h − 1, plus the thinnest tree of height h − 2.

The node counts 1, 2, 4, 7, 12, 20 follow N(h) = N(h − 1) + N(h − 2) + 1, which is a Fibonacci number minus one. Fibonacci numbers grow like φh with φ ≈ 1.618, so n ≥ about φh and the height is at most about 1.44 log₂ n. In the worst case an AVL tree is 44% taller than a perfect one, and no more.

Red-black trees: a looser balance, cheaper repairs

AVL trees keep a strict rule and pay for it with more rotations, especially on delete. A red-black tree allows more slack: it only promises that the longest root-to-leaf path is at most twice the shortest. It gets there by colouring every node red or black and obeying five rules.

The five rules

  1. Every node is red or black.
  2. The root is black.
  3. Every empty child (a NIL leaf) counts as black.
  4. A red node never has a red child.
  5. Every path from a node down to a NIL has the same number of black nodes: the node’s black height.

Step through every root-to-NIL path of this valid tree. Each one has the same number of black nodes (2), even though the paths differ in length. That is rule 5 made visible, and it is what forces the tree to stay bushy.

Why height ≤ 2 log₂(n + 1)?

Suppose the black height is b. By rule 5 every path has b black nodes, so the top b levels are full: at least 2b − 1 nodes. So b ≤ log₂(n + 1). By rule 4 no path can have two reds in a row, so red nodes are at most as many as black ones on any path: the height is at most 2b. Put together: h ≤ 2 log₂(n + 1).

Now watch the repair. A new node is always red, which cannot change any black count but may put two reds in a row. The rule panel lights the rule that is broken, and the fix is either a recolouring (when the uncle is red) or one or two rotations (when the uncle is black).

The red-black lab

A red-black insert needs at most two rotations, and often none. That is the point of the looser rule: the repair stays cheap, and the worst-case height, 2 log₂(n + 1), is still logarithmic.

Wide nodes for disks: 2-3 trees and B-trees

A binary tree with a million keys is about 20 levels tall, and on a disk each level can cost a slow read. A B-tree packs many keys into one node, so it is far shorter. A node holding k keys has k + 1 children, and all leaves stay at the same depth.

It stays balanced without rotations. A key goes into a leaf. If the leaf overflows, it splits around its middle key, and that key is promoted into the parent. Only when the root splits does the tree grow taller, and it grows at the top. Switch between a 2-3 tree (at most 2 keys per node) and a wider B-tree (at most 3).

Same keys, three trees

Why can a delete need many rotations in an AVL tree?

A rotation after an insert always restores the subtree to the height it had before, so nothing above it changes and one repair is enough. After a delete, the rotation can leave the subtree one level shorter than it was, which may unbalance the parent, and so on up to the root. That is up to log n rotations, each O(1), so a delete is still O(log n) overall. Red-black deletes use a smarter fix-up that stops after at most three rotations.

So which one should I use?

If lookups dominate, AVL wins slightly: it is shorter (at most 1.44 log₂ n against 2 log₂ n). If inserts and deletes are frequent, red-black wins slightly: fewer rotations. Both are O(log n) for everything, and in practice the difference is small. Libraries pick red-black more often, and databases and file systems pick B-trees.

Pull every red node up to sit beside its black parent and a red-black tree turns into a 2-3-4 tree: nodes with 1, 2 or 3 keys, all leaves at the same depth. Rule 5 (equal black height) says exactly that all leaves are at the same depth. A recolouring is a node split, and the “uncle is red” case is the 2-3-4 tree promoting a key. That is why the two are taught together.

Rotations are one way to stay balanced; there are others. Treaps give each key a random priority and rotate to keep priorities in heap order, so the shape is random and balanced in expectation. Splay trees rotate every accessed node to the root, so recently used keys stay near the top: balanced only on average, but wonderful for skewed access. Skip lists replace the tree with layers of linked lists. Weight-balanced trees balance subtree sizes instead of heights.

History

1962the first self-balancing tree

Georgy Adelson-Velsky and Evgenii LandisMoscow, 1962; red-black trees in 1978

The first self-balancing tree came from Moscow in 1962. Georgy Adelson-Velsky and Evgenii Landis kept every node’s two subtrees within one level of each other, and published the idea in Doklady Akademii Nauk SSSR. Their initials name the AVL tree.

Rudolf Bayer and Edward McCreight invented B-trees at Boeing in 1970; Bayer also described “symmetric binary B-trees” in 1972. Leonidas Guibas and Robert Sedgewick reworked that idea into red-black trees in 1978. Red was reportedly the colour that looked best on their Xerox PARC laser printer.

Sources: G. M. Adelson-Velsky and E. M. Landis, “An algorithm for the organization of information”, Doklady Akademii Nauk SSSR 146, 1962; R. Bayer and E. McCreight, “Organization and maintenance of large ordered indices”, Acta Informatica 1, 1972; L. J. Guibas and R. Sedgewick, “A dichromatic framework for balanced trees”, FOCS 1978.

Practice

  1. Balance factors after a rotation
    Easy

    Insert 30, 20, 10 into an empty AVL tree. Write the balance factor of every node before and after the rotation, and say which case it was.

  2. Is it an AVL tree?
    Medium

    Given the root of a binary tree, return whether it is height-balanced (every node’s subtrees differ in height by at most 1) in O(n) time. Then explain why computing the height of both subtrees at every node separately would be O(n²) on a stick.

  3. Sorted array to balanced tree
    Easy

    Build a height-balanced binary search tree from a sorted array in O(n). Which element goes at the root, and why does the recursion keep the tree balanced without any rotation?

  4. The fewest nodes
    Medium

    Use the recurrence N(h) = N(h − 1) + N(h − 2) + 1 to find the smallest AVL tree of height 7, and the tallest AVL tree that can hold 100 nodes. Check your answer against 1.44 log₂ n.

  5. Red-black by hand
    Hard

    Insert 1 through 7 in order into an empty red-black tree. For each insert say whether the fix-up was a recolouring or a rotation, and draw the final tree with its colours. What is its black height?
