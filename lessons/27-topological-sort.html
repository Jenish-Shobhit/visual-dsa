Topological sort & cycles

Some things must happen before others. A topological order lines everything up so every prerequisite comes first, and when no such line exists, you have found a cycle.

  • Intermediate
  • Needs: BFS & DFS, queues

The problem

You are planning a computer-science degree. Some courses need others first: Data Structures needs an intro programming course, and Algorithms needs both Data Structures and Discrete Math. An arrow from a to b means “take a before b”.

Key to the labels: CS1 intro programming, MATH calculus, DISC discrete math, DS data structures, ALG algorithms, OS operating systems, DB databases, NET networks, ML machine learning.

The drawing is a tangle, and you cannot simply read a schedule off it. What you want is a line-up of all nine courses in which every arrow points forward. That line-up is a topological order, and building one is topological sorting.

The same problem is everywhere a task waits for other tasks.

Build the intuition

You already sort by dependency every morning. Socks go on before shoes, a shirt before a tie. Nothing says whether you put on socks or a shirt first, only that each item comes after the things it needs.

Definition

A directed acyclic graph (DAG) is a set of vertices joined by one-way arrows, with no way to start at a vertex, follow arrows, and return to it. A topological order exists exactly when the graph is a DAG.

Play with that definition. Add tasks and arrows below. As long as you avoid a loop, the graph stays a DAG and an order exists. Close a loop and it disappears.

Where the analogy breaks

You never dress in a loop, but real dependency lists contain mistakes: task A waits for B, and B waits for A. No line-up can satisfy that, so a good algorithm must notice, not loop forever. Spotting the loop is half of this lesson.

Kahn’s algorithm: peel off what is ready

Where do you start? With a course that waits for nothing. Count the arrows pointing into each vertex: its in-degree. A vertex with in-degree 0 has no prerequisites, so it is safe to place first.

Once you place it, its outgoing arrows are used up: every course it pointed at now waits for one thing fewer. Watch that happen to Algorithms, which waits for two courses: Discrete math and Data structures. (To keep the picture small, the courses those two need are left out.)

Key idea

Kahn’s algorithm: keep a ready set of vertices with in-degree 0. Place one, delete its arrows, and add every vertex whose in-degree just hit 0. Repeat until nothing is ready.

Now run it yourself. Pick which ready vertex to take (each rule gives a different, equally valid order), type your own dependencies, or load a preset. At the end the graph redraws itself in layers, and every arrow points right. Try the “Ring” preset to see what a cycle does.

The lab: Kahn’s algorithm

Why the order is always valid

A vertex is placed only when its in-degree is 0, and in-degree only drops when a prerequisite is placed. So by the time a vertex goes into the order, every course it depends on is already in front of it. No arrow can ever point backwards.

Because every ready vertex is a safe choice, you are free to pick any of them, which is why the same graph has many valid orders. It is also why Kahn’s algorithm is the tool of choice when you want a tie-break rule, or every wave of ready tasks to run in parallel.

Many valid orders

There is no single “the” topological order. Nothing forces CS1 before Math, so either can go first. The order below is a line of nine courses, with an arch for each prerequisite. An arrow that points right arches over the line. One that points left is a broken promise, and it hangs below in red.

Out of 362,880 ways to line up nine courses, only a small fraction are valid. Each prerequisite you add removes some of them. Add enough and the order becomes forced, with exactly one valid line-up. The chart in the cost section shows this shrinking freedom.

When there is no order

Now add a mistake. Suppose a new rule says Data Structures needs Machine Learning first, while Machine Learning already needs Algorithms, which needs Data Structures. Each course on that loop waits for the next.

Run Kahn’s algorithm and watch it fail in a useful way: the ready set runs dry while courses are still unplaced. Their badges never reach 0.

Kahn’s leftover count is a cycle detector

If Kahn places fewer vertices than the graph has, there is a cycle. The unplaced vertices are on a cycle or depend on one. You do not need extra code: “order shorter than the vertex count” is the check.

The second way: DFS and finish time

Kahn builds the order from the front. Depth-first search builds it from the back. Run a DFS along the arrows, and every time a vertex finishes (everything it points to is done), put it at the front of the answer. A course that finishes last has nothing after it that is still unfinished, so it can safely come first.

DFS gives each vertex one of three colours, and the colours also expose cycles.

Step through it. An arrow from a vertex to a grey one closes a loop, because grey vertices are exactly the ones on the current route. Load the “Ring” or “Cycle behind a start” preset and see the alarm go off.

Why reverse finish order works

Take any arrow u → v. When DFS looks along it, v is either white (so it will start and finish inside u, before u finishes) or black (already finished). It cannot be grey unless the graph has a cycle. Either way v finishes before u, so v lands behind u in the answer.

Different answer, same validity

DFS and Kahn usually give different orders for the same graph, and both are right. Change the order in which DFS scans the names and you get yet another. Only the guarantee, every arrow points forward, is fixed.

When cycles are allowed: strongly connected components

Sometimes cycles are real, not mistakes: pages that link to each other, functions that call each other, tasks that genuinely feed each other. You cannot order the vertices on a cycle, but you can still find them and treat each group as one unit.

Definition

Two vertices are in the same strongly connected component (SCC) if each can reach the other by following arrows. Every vertex is in exactly one component. A vertex on no cycle is a component of its own.

Kosaraju’s algorithm finds them with two DFS passes. Pass 1 records the finish order. Then reverse every arrow and run DFS again, always starting from the vertex that finished last. Each walk on the reversed graph collects exactly one component.

The condensation is always a DAG

Squash each component into one vertex and keep an arrow between two components if any arrow went between their members. The result can never have a cycle: a cycle would merge its components into one. So every graph, cycles and all, has a DAG hiding inside it, and you can topologically sort that.

Why does the reversed walk stay inside one component?

The vertex with the latest finish time lies in a component that no other component points into. Reversing the arrows makes it a component that nothing points out of. So the walk can reach its own component but cannot leak into another. Then the next-latest unassigned vertex is in the next such component, and so on.

What about Tarjan’s algorithm?

Tarjan’s algorithm finds the same components with a single DFS. It tracks for each vertex the earliest discovery time it can reach (its low-link) on a stack; when a vertex’s low-link equals its own discovery time, it is the root of a component and everything above it on the stack belongs to it. Same O(V + E), one pass, a little harder to see.

Which tool should you use?

You now have three related tools. Answer the questions in order to see which one fits.

Beyond ordering: the critical path

Give every course a duration. Now a different question appears: what is the fastest the whole plan can finish, if you can take unrelated courses at the same time? The answer is the length of the longest path through the DAG, the critical path.

A topological order makes it easy. Visit the vertices in order, so each vertex’s prerequisites are already done, and compute its earliest finish time.


      
Longest paths are hard in a general graph, but on a DAG they take O(V + E). This is the idea behind the critical path method of the 1950s, the origin of the whole topic (see the history below).

What it costs

      
Count two operations: handling a vertex and handling an arrow. Kahn reads every arrow once to count in-degrees, takes every vertex once, and removes every arrow once. DFS enters every vertex once and examines every arrow once. Both are linear in the size of the graph.

The number of orders is a different story. Nothing here is linear: with no arrows, n tasks have n! orders, and each arrow you add cuts that number down.

      
      

        Why is a cyclic graph not more expensive?
        
Kahn simply stops early, when the ready set runs dry, and DFS stops at the first grey vertex. Detecting the cycle costs no more than sorting would have.

History

      

        
1962Kahn’s algorithm

        
Arthur B. KahnWestinghouse · CACM, November 1962

        

          
Topological sorting grew out of project management. Networks of tasks that must wait for other tasks, such as PERT for the Navy’s Polaris missile and the critical path method used in industry in 1957 and 1958, needed an order that respects every dependency.

          
In 1962 Arthur Kahn of Westinghouse published the rule you traced above: repeatedly remove a task with no remaining prerequisites. He reported ordering a 30,000-activity network in under an hour on an IBM 7090. Robert Tarjan’s one-pass SCC algorithm followed in 1972, and Kosaraju’s two-pass method was published by Sharir in 1981.

        

        
Sources: A. B. Kahn, “Topological Sorting of Large Networks”, Communications of the ACM 5(11), 1962; R. Tarjan, “Depth-first search and linear graph algorithms”, SIAM J. Computing 1(2), 1972; M. Sharir (1981).
