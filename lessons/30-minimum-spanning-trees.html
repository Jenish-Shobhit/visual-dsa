Minimum spanning trees

Join every town with the least total road. One rule does it: keep adding the cheapest edge that crosses a cut, and never look back.

The problem

Six towns want to share one water network. Each line is a pipe you could lay, and its number is the cost. You must lay enough pipes that every town is connected, directly or through others, and you want the total cost as low as you can make it.

Try it. Click a road to build it, click again to remove it.

Two things happen as you play. Once everything is connected, extra pipes only add cost, and you learn to spot the wasteful ones. Yet finding the cheapest set by hand is harder than it looks, because a cheap pipe in one place can force an expensive one somewhere else. Or can it?

The same question hides in many places: laying cable between offices, wiring a circuit board with the least copper, or grouping similar data points.

Spanning trees

Definitions

A spanning tree of a connected graph uses some of its edges to connect every vertex with no cycle. A minimum spanning tree (MST) is a spanning tree whose edge weights add up to the least possible.

A graph with V vertices needs at least V − 1 edges to be connected, and any more than V − 1 edges must close a cycle. So every spanning tree has exactly V − 1 edges.

A graph has many spanning trees, and their weights differ. Flip through them: the cheapest is a needle in a haystack.

Checking them all does not scale: a graph on 50 vertices can have more spanning trees than there are atoms in the Earth. We need a rule that walks straight to the cheapest one.

The cut property

Definition

A cut splits the vertices into two non-empty groups. An edge crosses the cut if its two ends are in different groups.

Drag the ends of the line across the map. Every road that crosses it turns amber, and the lightest one turns green. Turn on “Show the MST” to check where the true tree runs.

Cut property

For any cut, the lightest edge that crosses it belongs to a minimum spanning tree (to the MST, if weights are distinct). Kruskal and Prim differ only in which cuts they look at.

Why can you trust it? Suppose some spanning tree T does not use the lightest crossing edge e. Add e to T. That creates a cycle, and the cycle must cross the cut a second time, at some heavier edge f. Swap f for e: the tree stays connected and gets cheaper. So a tree without e was never the cheapest.

Kruskal: sort, then sweep

Kruskal sorts every edge from lightest to heaviest and walks down the list. For each edge it asks one question: are the two ends already connected? If not, the edge is kept. If so, it is skipped, because keeping it would close a cycle.

That question is exactly what a union-find structure answers, and it is where the colours come from: each colour is one component. Try the test yourself on a half-built network.

Why keeping the lightest joining edge is right

When Kruskal reaches an edge that joins two different components, take the cut that puts one component on its own side. No lighter edge crosses that cut: a lighter edge leaving the component would already have been processed, and it would have merged the component with another one. So the edge is the lightest crossing edge: the cut property says keep it.

Prim: grow one tree

Prim starts from a single vertex and grows one tree. Every round it looks at all edges that leave the tree and takes the cheapest. Those edges are exactly the edges that cross the cut between the tree and everything else, so the cut property says the cheapest one is safe.

To find that cheapest edge fast, Prim keeps them in a priority queue (a min-heap, lesson 21). When a vertex joins, its new edges are pushed. Some queue entries go stale when their far end joins the tree by another route; Prim discards them when they reach the top.

Same tree, different order

Kruskal and Prim look at the graph in very different ways. Kruskal jumps around the map picking the cheapest safe edge anywhere. Prim crawls outward from a start. Step them together and compare the order in which they commit edges.

Same destination

With distinct weights the MST is unique, so both algorithms must end with the same edges. The order differs because Kruskal’s cuts are chosen by weight, while Prim’s cut is always “the tree versus the rest”.

The cycle property

The cut property has a twin. In any cycle, the heaviest edge is not needed: the other edges still connect the same vertices, at lower cost. Kruskal’s “skip” is this rule in action.

Run it as an algorithm. Find a cycle, drop its heaviest edge, and repeat until no cycle is left. What remains has to be a tree, and it is the minimum one.

The cycle property needs a cycle

The heaviest edge of a cycle is safe to delete, but the heaviest edge of the graph is not always deletable. A bridge, an edge on no cycle, must stay however heavy it is, or the graph falls apart.

MST clustering

The MST has a surprising second job. Treat data points as vertices, and the distance between two points as an edge weight. The MST links each point to its nearest neighbours. Delete the k − 1 heaviest MST edges and the tree falls into k clusters.

This is the same as running Kruskal and stopping when k components are left: the long edges are exactly the ones Kruskal would add last. Slide k and watch the longest links snap.

What it costs

Both algorithms take about O(E log V) time. Kruskal spends it sorting the edges; the union-find work afterwards is almost free. Prim spends it on heap pushes and pops. What differs is how they behave when the graph is sparse or dense.

The chart below is not a formula. It counts the real comparisons and pointer hops that the three implementations make on random connected graphs.

Kruskalsort + union-findO(E log E)sparse graph, edges given as a list, edges already sorted

PrimFibonacci heapO(E + V log V)the best bound in theory; rarely worth the code

Why are O(E log E) and O(E log V) the same? A simple graph has E ≤ V², so log E ≤ 2 log V. Kruskal’s bound can be written either way. Space is O(V + E) for both.

Where does the O(V²) version come from?

Keep an array key[v] with the cheapest known edge from the tree to each outside vertex. Each of the V rounds scans the array for the smallest key (V steps) and then updates the neighbours. That is V × V plus E, and it never needs a heap. On a complete graph E is about V²/2, so a heap would only add a log factor to more work.

Variations and patterns

The same idea, bent a few ways. Each tab has a picture.

When weights repeat, the MST need not be unique. This square has four minimum spanning trees, all of weight 6, one for each side you leave out. Kruskal picks among them by the order of equal edges, so a different tie-break gives a different tree.

The weight of the MST is always unique. Distinct weights are a sufficient condition for a unique tree, not a necessary one.

An MST minimises the total, not the distance between any two vertices. In the six-town graph the direct road A–B costs 6, but the MST reaches B through A–C–D–B for 10.

If you need cheap routes from one source, that is a shortest-path tree (Dijkstra, lesson 28), a different tree.

Borůvka’s algorithm (1926) is the oldest. In each round every component grabs its own cheapest outgoing edge, and all the grabbed edges are added at once. Each round at least halves the number of components, so it needs at most log V rounds.

It runs well in parallel, and it is the first step of some of the fastest known MST algorithms.

To connect everything with the most total weight, run Kruskal with the sort reversed, or negate every weight. Negative weights are fine: the cut and cycle properties only compare weights.

Not fine: a graph that is not connected. Then no spanning tree exists, and the algorithms return a spanning forest, one tree per component.

Kruskal or Prim?

Both are correct, so the choice is about shape and convenience. Answer the questions to see which one fits.

History

1926first published

Otakar Borůvkathen Jarník 1930, Kruskal 1956, Prim 1957

The first minimum spanning tree algorithm was written for a power company. In 1926 Otakar Borůvka, asked by a friend how to connect the towns of Moravia to the electric grid with the least cable, published a method that merges the cheapest links in rounds. Jarník, Kruskal and Prim followed, and Dijkstra used his version to save copper wire in the back panel of the X1 computer.

Sources: O. Borůvka, “O jistém problému minimálním” (1926); J. Kruskal, Proc. AMS 7 (1956); R. Prim, Bell System Technical Journal 36 (1957); Graham & Hell, On the history of the minimum spanning tree problem (1985).

Practice

  1. Min cost to connect all points
    Medium

    Given points in the plane, connect them all with the least total Manhattan distance. There are about n²/2 possible edges: which algorithm and which data structure keep this near O(n²)?

  2. Redundant connection
    Easy

    A tree with n vertices had one extra edge added. Find the edge that can be removed to make it a tree again. Which half of Kruskal is this?

  3. Second-best spanning tree
    Hard

    Find the cheapest spanning tree that differs from the MST by exactly one edge. Hint: add a non-tree edge, then remove the heaviest edge on the cycle it creates.

  4. Critical and pseudo-critical edges
    Hard

    Call an edge critical if deleting it raises the MST weight, and pseudo-critical if some MST uses it but not every MST does. Classify every edge, using ties as the guide.

  5. Bottleneck path
    Medium

    Among all paths from s to t, find the one whose heaviest edge is as small as possible. Show that the path between s and t inside the MST is such a path.
