Backtracking

Make a choice, explore where it leads, and take it back when it fails. Rejecting a bad branch early turns an impossible search into a quick one.

  • 20 min
  • Intermediate
  • Needs: Recursion

The problem

Place n queens on an n×n chessboard so that no two attack each other. A queen attacks along her row, her column and both diagonals. On a 6×6 board, try it yourself.

You probably placed a queen, saw a clash coming, and moved an earlier queen instead of starting over. That habit is the algorithm. A program cannot rely on intuition, so it needs a systematic way to try, fail and undo.

Brute force would test every way to put 8 queens on 64 squares: 4,426,165,368 boards. Backtracking solves the same puzzle by looking at a couple of thousand partial boards.

Build the intuition

Picture a maze made only of forks. You carry chalk and follow one rule: go as deep as you can, and when you are stuck, walk back to the last fork that still has an untried corridor.

Analogy: chalk in a maze

Every fork is a decision, every corridor is a choice, and the chalk marks are the search remembering what failed. You never walk the same dead end twice.

Where the analogy breaks

In a real maze you walk back physically. A program must undo its change to shared state, exactly, or the next branch starts from a corrupted position. That undo step is the heart of backtracking.

Every partial solution is a node

Fill the board one row at a time. Each way of placing the first few queens is a partial solution, and each is a node in a tree whose children add one more queen.

Definition

The state-space tree has one node per partial solution. Its root is the empty solution, its children extend a node by one choice, and its leaves are complete solutions or dead ends.

This is the whole tree for four queens. Click any node to see its board. The red leaves are squares that were rejected; the number on each is how many brute-force nodes would have hung beneath it.

Key idea

Pruning means refusing to build the subtree under a node that already breaks a rule. Nothing below it can be a solution, so the search never looks.

Choose, explore, unchoose

Every backtracking program repeats three moves. Choose one option and update the state. Explore by recursing on what is left. Unchoose by restoring the state exactly as it was.

The third move is what makes the next option start from a clean position. Without it, choices leak from one branch into the next.

Why the recursion stack is enough

The call stack already remembers where each fork was. The state only has to change by one choice on the way down and be put back on the way up.

Checking a square in one lookup

To test a square you must know if any queen attacks it. Scanning all queens works, but three sets make it one lookup each: the used columns, and the used diagonals, named by row + col for “/” and row − col for “\”.

Every square on one “/” diagonal shares the same row + col; every square on one “\” diagonal shares the same row − col. Click a square in rows 3 to 5.

Lab: a Sudoku solver

Sudoku is backtracking with a much bigger board. Faint digits are candidates: the digits not yet used in a cell’s row, column or box. The solver picks a cell, tries each candidate, recurses, and erases the digit if it leads nowhere.

Which cell to pick next matters enormously. Switch between reading order and most constrained first (the empty cell with the fewest candidates) and compare the counters.

How big is the difference? Both orders run to completion (or to a limit of one million placements) on the same puzzle.

Lab: word search on a grid

Backtracking is not only for boards you fill. To find a word as a path of neighbouring letters, walk from a start cell, extend the path while the letters match, and unchoose a cell when none of its neighbours can continue.

What it costs

Backtracking has no magic worst case: if nothing can be pruned, it walks the whole tree. Its power is that constraints usually cut most of it away. Compare the two trees for four queens.

Four queens is tiny. Here is how the work grows as the board does, on a logarithmic axis where each gridline is ten times the last.

Extra space is only the recursion depth plus the current state, for these problems, because only one root-to-node path exists at any moment.

Pruning is not a guarantee

Backtracking can still be exponential, and it is only as fast as your pruning is early. The word-search worst case above (all A’s, word ends in B) prunes nothing until the very last letter.

A bound is a cheap test that a branch cannot possibly succeed, like “too few items left” or “the sum already exceeds the target”. Branch and bound is this idea applied to optimisation: cut a branch when its best possible score cannot beat the best found so far.

        
With repeated items, plain search records the same result more than once. Sort the input, and skip an item equal to the previous one at the same level.

      

      

        
Backtracking or dynamic programming?

        
If different branches keep reaching the same sub-problem, remember its answer (lesson 34). If every branch is genuinely different, as in N-Queens, backtracking with good pruning is the tool.

History

      

        
1848eight queens posed

        
Max Bezzel · D. H. Lehmer · Niklaus WirthBerliner Schachzeitung, 1848; “backtrack” in the 1950s; stepwise refinement, 1971

        

          
Chess composer Max Bezzel published the eight queens puzzle in 1848, and Franz Nauck listed all 92 solutions in 1850. You may read that Gauss solved it; he only made a brief, incomplete attempt, and the story comes from a later mix-up.

          
D. H. Lehmer named the method “backtracking” in the 1950s, and eight queens became its standard example after Wirth and Dijkstra used it around 1970.

        

        
Sources: J. W. L. Glaisher (1874); Campbell, Historia Mathematica 4 (1977); Golomb and Baumert, JACM 12(4) (1965); N. Wirth, CACM 14(4) (1971).
