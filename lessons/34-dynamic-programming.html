Dynamic programming I

When a recursion keeps asking the same questions, answer each one once and write it down. A tree of millions of calls shrinks to a short row of cells.

  • Intermediate
  • Needs: Recursion

The problem

You stand at the bottom of a staircase. Each move climbs 1 stair or 2. How many different ways are there to reach the top?

Drag the slider and watch every way play out. Each chip is one sequence of hops.

Look at the two groups. Every way ends with one last hop: a 1 from stair n − 1, or a 2 from stair n − 2. So the number of ways to reach n is the ways to reach n − 1 plus the ways to reach n − 2.

That rule turns straight into a recursion: ways(n) = ways(n − 1) + ways(n − 2), with ways(0) = ways(1) = 1. It is the Fibonacci rule again, and it hides a trap. Push the slider below to see how many calls the plain recursion makes.

At 50 stairs the plain recursion makes about 40 billion calls, yet there are only 51 different questions: ways(0) to ways(50). This lesson is about the gap between those two numbers.

Build the intuition

Someone writes 1 + 1 + 1 + 1 + 1 + 1 + 1 + 1 and asks for the total. You count: 8. They write one more “+ 1” in front and ask again. You say 9 at once, because you remember the 8.

Analogy: keep a notebook

Before you work anything out, check your notebook. If the answer is there, read it. If not, work it out and write it down. Dynamic programming is that habit, applied to the smaller questions inside a big one.

Two conditions

Overlapping subproblems: the same smaller question comes up many times, like the magenta repeats on the left. Optimal substructure: the answer to a big question is built from the answers to smaller ones, like ways(n) from ways(n − 1) and ways(n − 2).

Where the analogy breaks

A notebook only pays when questions repeat. Merge sort (right) splits a list into halves that never overlap, so every question is new and a notebook would stay empty. That is divide and conquer, not dynamic programming.

The same question, over and over

Step through plain recursion for fib(5). Each circle is one call and its number is the argument. The row underneath counts how many times each question has been asked.

The counts in the row are Fibonacci numbers too: fib(1) is asked 5 times and fib(2) 3 times for fib(5), and the waste grows exponentially with n. Now switch the figure to With a memo.

Definition

A memo is a table that stores the answer to each question the first time it is computed. Memoization is recursion plus a memo: check the memo first, and store each new answer before returning it. A lookup that finds the answer is a memo hit.

Key idea

With a memo, the work is the number of different questions, not the number of ways to reach them. fib(n) has n + 1 different questions, so memoized fib makes 2n − 1 calls instead of a number that grows like 1.6n.

The tree is really a row

Plain recursion draws a tree because it cannot tell that two calls ask the same thing. Glue together every call with the same argument, and see what is left.

The arrows that survive say which cells each cell reads: cell k reads cells k − 1 and k − 2. Every arrow points left to right, so filling the cells left to right always finds the inputs ready. Filling a table in such an order is called tabulation.

Definition

A DAG (directed acyclic graph) is a set of arrows with no cycles: you can never follow arrows back to where you started. Every DAG has a topological order, a line-up in which every arrow points forward. Every dynamic program is a DAG of subproblems.

Five decisions make a DP

Fibonacci, spell checkers and route planners all follow the same five decisions. The figure marks each one on a single table: the fewest coins from {1, 3, 4} that make each amount up to 6.

A sixth step is optional but common: store which choice won in each cell, then walk those choices back from the answer to rebuild the solution itself (here, 3 + 3), not only its size.

Why it is correct

Take the best way to pay 6. Its last coin is some c, and the rest pays 6 − c. If the rest were not the best way to pay 6 − c, swapping in a better one would improve the whole, a contradiction. So trying every last coin cannot miss the optimum.

Top-down or bottom-up

You can follow the recipe in two directions. Top-down keeps the recursion and adds a memo, so the recursion discovers the order for you. Bottom-up writes the loop yourself, from the smallest state up.

DP is a shortest path in a DAG

Draw each state as a circle and each choice as an arrow. For fewest coins with {1, 3, 4}, an arrow from amount a to a + c means “add one coin c”. Every path from 0 to 6 is a way to pay 6, so the fewest coins is the shortest path.

Before you step the figure, try the click check below it.

Why no priority queue?

Dijkstra’s algorithm needs a priority queue because it does not know which node is safe to finish next. Here every arrow points to a larger amount, so increasing order is a topological order: each amount is final before anything reads it. One pass, one relaxation per arrow.

Keep only what you still need

The Fibonacci recurrence reads only the last two cells. Once a cell falls two places behind, nothing will read it again, so it can go.

The same trick works whenever a cell reads only a few recent cells or rows. House robber needs two numbers; coin combinations needs one row. The price: without the full table you lose the stored choices, so keep the table when you must rebuild the answer.

What it costs

      
A DP costs (number of states) × (work per state). Fibonacci has n + 1 states and one addition each. Plain recursion instead pays once for every path through the tree.

For coins, A is the amount and k the number of coin types. For LIS, a cleverer method with binary search runs in , but the O(n²) table is the one to understand first.

      

        Why is O(A·k) called “pseudo-polynomial”?
        
The running time grows with the value of A, not with how many digits it takes to write it. Paying a million needs a million cells, but “1000000” is only seven digits. Add three digits and the table grows a thousandfold. Coin change is still fast for everyday amounts.

      

      

        Where does 2·fib(n + 1) − 1 come from?
        
Let C(n) be the calls for fib(n). C(0) = C(1) = 1, and C(n) = 1 + C(n − 1) + C(n − 2): the call itself plus its two subtrees. Adding 1 to both sides gives C(n) + 1 = (C(n − 1) + 1) + (C(n − 2) + 1), the Fibonacci rule, starting from 2 and 2. So C(n) + 1 = 2·fib(n + 1).

      

    


    
    

      
Variations and patterns

      
Most DP problems are the recipe with one knob turned. Four knobs come up again and again.

      

        

          
          
          
          
        

        

          

          

            
Same arrows, different ways to combine them. With coins {3, 4} each amount reads a − 3 and a − 4. Take the min plus one for the fewest coins, the sum for the number of coin sequences, and or for “can it be paid at all”. Change the combiner, not the table.

            

          

        

        

          

          

            
With a single row, the loop direction decides which values a cell reads. Adding an item of weight 2 left to right, dp[6] reads dp[4], which already includes the item, so the item can be used again (unlimited supply). Right to left, dp[4] still holds the old value, so each item is used at most once (0/1 knapsack).

            

          

        

        

          

          

            
A table of numbers says how good the best answer is, not what it is. Store the winning choice in each cell, then start at the answer and follow the choices back. Here: 10 = 3 + 3 + 4, found by stepping back 3, 3 and 4.

            

          

        

        

          

          

            
House robber’s state is “best of the first i houses”, so the answer is the last cell. LIS’s state is “longest run ending at i”, so the answer is the largest cell, wherever it is. Read your own state definition to know which.

History

      

        
1950snamed at RAND

        
Richard BellmanDynamic Programming, Princeton University Press, 1957

        

          
Richard Bellman named dynamic programming at the RAND Corporation in the early 1950s, and by his own account chose the name to hide what he was doing. The Secretary of Defense, he wrote, could not stand the word “research”; “programming” meant planning, and nobody could use “dynamic” as an insult.

          
Historians point out that the dates do not quite line up: Charles Wilson became Secretary of Defense in January 1953, after Bellman was already using the term. Enjoy the story as Bellman told it. The idea itself is older: Fibonacci’s 1202 rabbit problem is the same recurrence you tabulated above.

        

        
Sources: R. Bellman, Eye of the Hurricane (1984); S. Dreyfus, “Richard Bellman on the Birth of Dynamic Programming”, Operations Research 50(1), 2002.
