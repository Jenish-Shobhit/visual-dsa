String matching

Find a short pattern inside a long text. The obvious way re-reads the same characters again and again; three clever ways (KMP, Rabin–Karp and the Z-algorithm) read each character about once.

  • Intermediate
  • Needs: strings, arrays

Finding a needle in a haystack of letters

Every time you press Ctrl + F, an editor finds every place where a short pattern occurs inside a long text. Genome tools search for a gene inside billions of letters, and plagiarism checkers look for copied phrases. The text has n characters and the pattern has m, and the question is how many comparisons it takes.

Try the obvious method by hand. Slide the pattern along the text. At each alignment, compare left to right until the first mismatch. Green means the characters agree, red means they do not.

With ordinary text, most alignments die on the first character. With repetitive input, such as a text of all a’s and a pattern like aaab, every alignment matches almost all the way before it fails. That is the trap: in the worst case naive search makes about n × m comparisons.

A mismatch is also information

When the pattern fails after matching five characters, you did not just learn that this alignment is wrong. You also learned what the last five text characters are: they equal the start of the pattern. Naive search throws that away. KMP uses it.

Reading a name aloud

You are scanning a page for “ABABAC”. You have read “ABABA” and the next letter is “B”, not “C”. You do not go back to the second letter and start over: you already know the last three letters were “ABA”, which is the start of your pattern, so you carry on as if you had just read those three.

Where the analogy breaks

A person notices “ABA” by eye. A program must know it in advance, and it cannot look at the text to find out. So all the knowledge has to come from the pattern alone, computed once before the search starts. That precomputed knowledge is the failure table.

The failure table: what survives a failure

The table is built from borders. Slide the length below and watch which start of the pattern is also an end of the same prefix.

Definition

A border of a string is a proper prefix that is also a suffix. aba is a border of ababa because the string both starts and ends with it. The failure table π stores, for each prefix of the pattern, the length of its longest border.

Why the table is the jump distance

If the pattern fails after matching j characters, the text holds the first j pattern letters. Any smaller alignment that could still match must line the pattern's start up with a suffix of those letters, and that is a border. The longest border is the smallest slide that could work, so no alignment is skipped that could have matched.

How do you fill the table quickly? Compare the pattern against itself. That is the KMP idea applied to the pattern, and it costs at most 2m comparisons.

Building the table, step by step

The top row is the pattern as text, the lower row is a second copy. Each step asks whether the border can grow by one letter. When it cannot, the lower copy falls back to the next-longest border, which is already in the table. Type your own pattern and watch the table fill.

Amortised, not nested

The inner “fall back” loop looks like it could make this quadratic. It cannot: k goes up by at most one per letter, and every fall-back makes it smaller, so the falls can never outnumber the rises. Total work: at most 2m comparisons.

Rabin–Karp: compare numbers, not letters

A different idea: give every window of the text a hash, a single small number, and compare that with the pattern's hash. Read letters as digits (a = 1, b = 2, …) in base B, so the window abc is the number 1·100 + 2·10 + 3 = 123. Work modulo a prime q to keep it small.

The trick is the rolling hash: when the window slides one letter, you do not recompute. You subtract the leading letter’s value times Bm−1, multiply by the base to shift every digit up one place, and add the trailing letter. Three small operations replace m.

Equal hashes are not equal strings

There are far more strings than small numbers, so different strings can share a hash: a spurious hit. Rabin–Karp therefore always verifies a hit character by character. Pick the tiny modulus 7 above and spurious hits appear often; a large modulus makes them rare. Different hashes, on the other hand, always prove the strings differ.

Because a hash test is a plain number comparison, the same loop can look for many patterns of equal length at once: keep their hashes in a set and test each window against it.

The Z-algorithm: how far does the start repeat?

A third route measures matches with the start of the string directly. For a string s, Z[i] is the length of the longest stretch starting at i that equals the beginning of s. To search, glue the pattern and the text together as s = pattern + "#" + text: any position with Z[i] = m is a match.

The speed comes from the Z-box [l, r): the stretch found so far that reaches furthest right, which equals a piece of the prefix. A new position inside the box can copy the answer from its mirror position, and only characters beyond r are ever compared.

Same trick as KMP, seen from the other side

r never moves left and every comparison either extends r or is the one failing comparison of that position. So there are at most about 2n comparisons in total. KMP remembers borders of the pattern; the Z-algorithm remembers the last box.

Race them on the worst input

Same text, same pattern, three lanes, one clock. One tick pays for one character comparison, or for one rolling-hash update. The aaa…ab input is the naive method's nightmare: every alignment matches until the last letter.

Why is KMP's search at most 2n comparisons?

Every comparison ends in one of two ways. A match moves i right, which can happen at most n times. A mismatch with j > 0 makes j smaller, and j only ever grows by matches, so mismatches cannot outnumber matches. A mismatch with j = 0 moves i right, which is also at most n times in all. Together: fewer than 2n comparisons.

How likely is a spurious hit?

If the hash behaves like a random number modulo q, a window that differs from the pattern collides with probability about 1 / q. With q around a billion, the expected number of false alarms in a million-letter text is about a thousandth. Real implementations use a large prime, or a random base, so that no fixed input can force collisions.

Variations and patterns

The same ideas show up in tools you use every day.

Boyer–Moore compares the pattern right to left. A mismatch on a letter that does not occur in the pattern lets the whole pattern jump past it, so on ordinary text it often skips most of the characters without reading them. This figure shows the bad-character rule only.

To look for a whole dictionary, keep the hashes of all patterns of the same length in a set, and test every rolling window against it. This is how plagiarism checkers fingerprint documents. For patterns of different lengths, the Aho–Corasick automaton combines a trie (lesson 22) with KMP-style failure links and finds every pattern in one pass over the text.

  • Editors and terminals. Find-in-page uses a fast library search, often a Boyer–Moore variant. GNU grep uses Boyer–Moore-style skipping; the original grep came from Thompson’s regex search in ed.
  • Genomes. A four-letter alphabet with huge texts. Exact search is the base, and index structures such as suffix arrays answer repeated queries.
  • Detecting repeats and periods. The failure table tells you a string's shortest repeating period: n − π[n − 1] when it divides n.
  • Competitive programming. KMP and Z are the standard tools for counting borders, prefixes that reappear, and rotations.

History

1969found in a text editor

James Morris, Donald Knuth and Vaughan PrattSIAM Journal on Computing 6(2), 1977

James Morris found the idea in summer 1969 while writing a text editor for Berkeley's CDC 6400. His code was so subtle that other programmers, not understanding it, damaged it with well-meant “fixes” within months. Knuth found the same algorithm independently in 1970, by working backwards from a theorem about automata that Stephen Cook had proved. Vaughan Pratt removed its dependence on the alphabet, and the three published together in 1977.

Boyer and Moore's method, which reads the pattern backwards and can skip most of the text, appeared in the same year, and Rabin and Karp's rolling hash in 1987. Ken Thompson's 1968 regular-expression search, in the editor ed, is where the tool grep comes from.

Sources: D. E. Knuth, J. H. Morris and V. R. Pratt, “Fast Pattern Matching in Strings”, SIAM J. Comput. 6(2), 1977; R. S. Boyer and J. S. Moore, CACM 20(10), 1977; R. M. Karp and M. O. Rabin, IBM J. Res. Dev. 31(2), 1987; K. Thompson, CACM 11(6), 1968.

Practice

  1. Count overlapping occurrences
    Easy

    Return how many times a pattern occurs in a text, counting overlaps (aa occurs three times in aaaa). Write it with KMP and check it on inputs where naive search is slow.

  2. Longest happy prefix
    Easy

    Find the longest non-empty proper prefix of a string that is also a suffix of it. Which array from this lesson already contains the answer?

  3. Repeated substring pattern
    Medium

    Decide whether a string is made by repeating a shorter string several times. Use π[n − 1] and the length n to answer in linear time, and explain why the trick works.

  4. Is it a rotation?
    Medium

    Two strings have the same length. Show that one is a rotation of the other exactly when it occurs inside the other written twice, and give a linear-time check.

  5. Shortest palindrome by prepending
    Hard

    You may add characters only to the front of a string. Find the shortest palindrome you can make. Hint: build s + "#" + reverse(s) and look at the last entry of its failure table.
