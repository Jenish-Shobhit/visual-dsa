A later negative edge can improve a vertex already finalized by Dijkstra.

Ask a maps app for the fastest route across a country and it searches a graph of perhaps twenty million road segments. The number of distinct routes is astronomical — more than atoms in your body — yet the answer returns in a blink. It does so without ever enumerating a path. It keeps one number per intersection, an over-estimate of the distance, and lowers it by a single rule applied over and over. That rule is relaxation, and it is the whole of this lecture. Dijkstra, Bellman–Ford, and the linear-time DAG method are not three algorithms. They are one primitive performed in three different orders.

A number to unsettle you. Take the greedy method — Dijkstra — that powers most of that routing. It is provably optimal, and it is fast. Now change a single edge weight to a negative number: a refund along one leg, a tailwind, a currency gaining value. On the four-vertex graph in §08 Dijkstra confidently returns a distance of 2 to a vertex whose true shortest distance is 1 — and reports it as final. No crash, no warning. Just a wrong answer, delivered with total confidence.

One negative number silently breaks a correct algorithm. The discipline of this lecture is to know exactly which assumption each method rests on — non-negativity, acyclicity, the absence of a negative cycle — so that you reach for the right tool and never ship the confident lie.

01 separate the operation from the engine

What “shortest path” really asks

I begin, as always, by stripping the problem to its formal skeleton — the inputs, the output, the transformation — and setting aside the dressing of roads or routers. The input is a weighted directed graph G = (V, E) with a weight function w : E → ℝ assigning a real number to each edge, together with a distinguished source vertex s. The output is, for every vertex v, the shortest-path distance δ(s, v) — the minimum total weight over all directed paths from s to v — and, implicitly, a path achieving it.

This is the single-source shortest-paths problem (SSSP). “Single source” because we fix one starting vertex and ask about all destinations at once; it is no harder, asymptotically, to find every distance from s than to find one. The next lecture lifts this to all sources.

Why not simply enumerate paths and take the minimum? Because the count is exponential — a graph on n vertices can have on the order of n! simple paths between two of them. Enumeration is a non-starter. The entire art is to find the optimum without ever building a path, by exploiting a structural property the problem happens to possess. We will mechanise the search into the repeated lowering of one number per vertex.

the formal lensHold the contract fixed — minimum-weight paths from s — and vary only the order in which we examine edges. Every algorithm in this lecture computes the same function. They differ solely in the schedule of a single primitive, and each schedule is licensed by a different assumption about the weights.
02 objectives & prerequisites

What you will be able to do

  • State the relaxation primitive and the two invariants it preserves — the upper-bound property (d[v] ≥ δ(s,v) always) and the triangle inequality — and explain why d only ever decreases.
  • Prove the path-relaxation lemma: relaxing the edges of any shortest path in order makes its endpoint's estimate exact — the single fact behind every correctness proof here.
  • Execute Dijkstra's algorithm by hand with a min-priority queue, and justify the greedy step from non-negativity: the closest unfinished vertex's estimate is already final.
  • Execute Bellman–Ford, argue why V−1 passes suffice, and use one extra pass to detect a negative cycle.
  • Diagnose the negative-weight boundary: why a negative edge breaks Dijkstra, why a reachable negative cycle makes δ = −∞, and why a DAG escapes both.
  • Solve a DAG's shortest (or longest) paths in Θ(V+E) by relaxing in topological order — the order the acyclicity hands you for free.

Prerequisites

Three ideas, each a short phrase you should already hold. They are taught on the linked pages.

03 the single primitive

The relaxation atom

Every method here maintains the same three pieces of state. For each vertex v:

  • d[v] — a tentative distance: an upper bound on δ(s,v) that we lower as we learn more. Initialised d[s]=0 and d[v]=∞ for all others.
  • π[v] — the predecessor on the best path found so far, so we can reconstruct the route by walking pointers back from v to s. Initialised nil.

And one operation acts on them — the atom from which everything is built. To relax an edge (u, v) of weight w(u,v) is to ask a single question: does routing through u beat what I currently believe about v?

relax(u, v, w)
if  d[u]+w(u,v) < d[v]   then   d[v]←d[u]+w(u,v) , π[v]←u

That is the entire mechanism. Relaxation never makes d worse — it only assigns when the new value is strictly smaller — so the estimates form a monotonically decreasing sequence, bounded below by the true distance. Two invariants hold from the first instruction to the last, no matter the order:

the law relaxation enforces — triangle inequality
δ(s,v) ≤ δ(s,u)+w(u,v)

Upper-bound property. At all times d[v] ≥ δ(s,v), and once d[v] reaches δ(s,v) it never changes again. Why: every finite d[v] is the length of some real path s → ··· → v (the one traced by π), so it cannot dip below the minimum over all such paths; and relaxation only assigns smaller values, so it cannot rise. The estimate is a true distance squeezed downward toward the optimum — never past it.

04 the master lemma

Why relaxing in the right order is enough

Two facts make the problem tractable. The first is structural; the second turns it into an algorithm.

Optimal substructure. Subpaths of shortest paths are themselves shortest paths. If p = s → ··· → u → ··· → v is a shortest path, then its prefix s → ··· → u is a shortest path to u. The proof is cut-and-paste: if a strictly cheaper route to u existed, splicing it in would yield a strictly cheaper p — contradiction. This is the property that lets a greedy or dynamic-programming attack succeed; without it the problem would resist all of this.

the recurrence optimal substructure gives
δ(s,v)= min(u,v)∈E {δ(s,u)+w(u,v)}

The path-relaxation lemma. Let p = ⟨v₀, v₁, …, vₖ⟩ be a shortest path from s = v₀ to v = vₖ. Suppose that, in the course of the algorithm, the edges of p are relaxed in the order (v₀,v₁), (v₁,v₂), …, (vₖ₋₁,vₖ) — possibly with other relaxations interleaved between them. Then afterward d[vₖ] = δ(s,vₖ).

Proof, by induction on the index i. Claim: after edge (vᵢ₋₁, vᵢ) is relaxed, d[vᵢ] = δ(s, vᵢ). Base: d[v₀] = d[s] = 0 = δ(s,s) from initialisation. Step: assume d[vᵢ₋₁] = δ(s, vᵢ₋₁) holds when we relax (vᵢ₋₁, vᵢ) (it does, by the inductive hypothesis, and once exact it stays exact by the upper-bound property). The relaxation sets d[vᵢ] ≤ δ(s,vᵢ₋₁) + w(vᵢ₋₁, vᵢ), which equals δ(s,vᵢ) because p is a shortest path and its prefix to vᵢ is too (optimal substructure). Combined with the upper bound d[vᵢ] ≥ δ(s,vᵢ), equality follows. □

This lemma is the engine of every proof below. To show an algorithm correct, you need only show that, for each vertex, it relaxes the edges of some shortest path to that vertex in order. The three algorithms are precisely three guarantees that this happens — achieved by three different scheduling disciplines.

Every shortest-path algorithm is the same atom, relax an edge, performed in a different order. The order is the algorithm.
05 the greedy schedule

Dijkstra — closest-first, when weights are non-negative

Suppose every weight satisfies w(u,v) ≥ 0. Then a beautiful greedy fact holds: among all vertices whose distance is not yet final, the one with the smallest estimate d already has d = δ. Its estimate cannot improve, so we may “finalise” it and never look back.

Why non-negativity is the whole reason. Let u be the unfinished vertex of minimum d[u], and suppose for contradiction its true shortest path is cheaper. That path leaves the finalised set somewhere, crossing into the unfinished region at some first vertex y. By the convergence of the finalised frontier, d[y] = δ(s,y) ≤ δ(s,u) < d[u] — because the remaining edges from y to u add only non-negative weight. But then y, not u, was the unfinished vertex of minimum estimate. Contradiction. Flip even one edge negative and the step “remaining edges add only non-negative weight” collapses — and with it Dijkstra's correctness.

The schedule writes itself. Keep a min-priority queue of vertices keyed by d. Repeatedly extract the minimum (finalise it), then relax its outgoing edges, which may decrease-key its neighbours. Each vertex is extracted once; each edge is relaxed once.

def dijkstra(adj, s):           # adj[u] = list of (v, w), all w >= 0
    d = {v: INF for v in adj}; d[s] = 0; pi = {}
    pq = [(0, s)]                  # binary min-heap of (dist, vertex)
    done = set()
    while pq:
        du, u = heappop(pq)
        if u in done: continue     # skip a stale (lazy-deleted) entry
        done.add(u)                # d[u] is now final = delta(s,u)
        for v, w in adj[u]:
            if du + w < d[v]:        # RELAX (u, v, w)
                d[v] = du + w; pi[v] = u
                heappush(pq, (d[v], v))   # lazy decrease-key
    return d, pi

I use the lazy heap idiom: rather than implement decrease-key, push a fresh (d[v], v) each time v improves and discard any entry that pops after v is already done. It is simpler and, on a binary heap, asymptotically identical.

The Fibonacci heap trades the per-edge log for amortised O(1), reaching O(E + V\,log V) — theoretically sharper, rarely worth the constant factors in practice.

07 when you cannot trust the order

Bellman–Ford — relax every edge, V−1 times

Dijkstra's greed depends on non-negativity. Remove that assumption — allow negative edges — and we lose the ability to know which vertex to finalise next. Bellman–Ford answers with brute honesty: if I do not know the right order, I will relax every edge, and repeat enough times that any shortest path's edges are guaranteed to have been relaxed in order.

Why V−1 passes. If no negative cycle is reachable, every shortest path is simple — it repeats no vertex — so it uses at most V−1 edges. Order the passes 1, 2, …, V−1. By the path-relaxation lemma, after pass i, every vertex whose shortest path uses at most i edges has its exact distance: pass 1 fixes all 1-edge destinations, pass 2 all 2-edge destinations, and so on. (Each full pass relaxes all edges, so in particular it relaxes the i-th edge of every shortest path, in order, across successive passes.) After V−1 passes, every simple shortest path — hence every shortest path — is accounted for.

def bellman_ford(V, edges, s):     # edges = list of (u, v, w), any sign
    d = {v: INF for v in V}; d[s] = 0; pi = {}
    for _ in range(len(V) - 1):       # V-1 passes
        changed = False
        for u, v, w in edges:
            if d[u] != INF and d[u] + w < d[v]:   # RELAX
                d[v] = d[u] + w; pi[v] = u; changed = True
        if not changed: break          # early exit: a fixed point is reached
    for u, v, w in edges:                 # one extra pass = the detector
        if d[u] != INF and d[u] + w < d[v]:
            raise NegativeCycle(v)        # still improvable => reachable neg cycle
    return d, pi

The cost is Θ(V·E) — V−1 passes over all E edges — markedly slower than Dijkstra, the price of dropping the non-negativity assumption. The changed flag lets a graph that converges early stop early; the worst case still needs all V−1 passes (a path graph whose edges are relaxed back-to-front advances exactly one vertex per pass).

the formal lensDijkstra chooses the relaxation order with a priority queue and pays log V for the privilege. Bellman–Ford refuses to choose and pays a full factor of V instead. Same atom; the cost gap is exactly the value of the information non-negativity provides.

the confident lieRun Dijkstra on this exact graph. It extracts t at 6 and finalises it, then later finalises z at 2 through that stale t. It reports d[z]=2. The truth is δ(s,z) = −2. The negative edge x→t=−2 arrives too late to rescue a vertex Dijkstra has already declared done. No error is raised — only a wrong number.

To distil the failure to its essence, here is the minimal counterexample — four vertices, one negative edge — and a destination whose error is undeniable.

09 the boundary of well-posedness

Negative cycles, and how to detect them

A negative edge is survivable; a negative cycle is not. If some cycle reachable from s has total weight below zero, then for any vertex v on or after it, there is no shortest path at all: each extra lap around the cycle lowers the cost without bound, so δ(s,v) = −∞. The question “what is the cheapest simple path?” remains meaningful, but it is NP-hard — it contains the longest-path and Hamiltonian-path problems. So we do not ask it. We instead detect the negative cycle and report that distances are undefined.

The detector. Run the V−1 Bellman–Ford passes, then do one more. If any edge (u,v) still satisfies d[u] + w(u,v) < d[v], a negative cycle is reachable from s. The logic is airtight: with no negative cycle, V−1 passes reach the exact distances (§07), after which no relaxation can fire; so a relaxation that does fire certifies a cycle. To recover the cycle itself, follow π back V times from the offending vertex (guaranteeing you land on the cycle), then walk the predecessor pointers around until you repeat a vertex.

a reach subtletyBellman–Ford only sees cycles reachable from s. To detect a negative cycle anywhere in the graph, add a virtual source with a zero-weight edge to every vertex (or initialise all d[v]=0); now every cycle is reachable and the same one-extra-pass test finds it. This is the trick behind currency-arbitrage detection in §13.
10 order handed to you for free

DAGs — shortest paths in linear time

There is a case that beats even Dijkstra and tolerates negative weights without fear: the directed acyclic graph. A DAG has no cycles, so it certainly has no negative cycle — negative weights are perfectly safe. And acyclicity grants something precious: a topological order, a linear arrangement of the vertices in which every edge points forward. Relax the vertices in that order and each vertex's estimate is final the moment we reach it, because all of its predecessors — the only vertices that can improve it — have already been processed.

def dag_shortest_paths(V, adj, s):
    order = topological_sort(V, adj)     # O(V + E), e.g. Kahn or DFS
    d = {v: INF for v in V}; d[s] = 0
    for u in order:                     # vertices in topological order
        if d[u] == INF: continue        # u not reachable from s
        for v, w in adj[u]:            # relax each out-edge of u
            if d[u] + w < d[v]:
                d[v] = d[u] + w
    return d

No priority queue, no repeated passes — one sweep. The cost is Θ(V+E), dominated by the topological sort and the single relaxation of every edge. Each edge is relaxed exactly once, in an order that is provably correct by the path-relaxation lemma: a shortest path's edges appear left-to-right in the topological order, so they are relaxed in order automatically.

This DAG case is not a curiosity. Negate the weights (or relax for the maximum) and the same sweep yields the longest path — the critical path of a task network, the bound on how fast a project with dependencies can finish. Practice problem 4 is exactly this.

11 the ledger

Choosing the right tool

The same atom, three schedules, three contracts. The table is the decision procedure: read the weights, read the structure, pick the row.

One sharp way to remember the gap: Dijkstra spends log V per edge to buy the right order; Bellman–Ford spends a factor of V because it refuses to choose one; the DAG pays nothing because acyclicity donates the order. The next lecture's Johnson's algorithm exploits exactly this ranking — it runs Bellman–Ford once to reweight every edge non-negative, then runs the cheap Dijkstra from every source.

12 where it breaks

Failure modes & common mistakes

The atom is simple; the ways to misapply it are many. Here is what I see go wrong, in rough order of how often it bites.

1 · Dijkstra on a graph with a negative edge

The cardinal sin (§08). It may even return correct answers on some negative-weight inputs, which is worse than always failing — it lulls you. The assumption is w ≥ 0, full stop. If a single edge can be negative, use Bellman–Ford, or reweight to non-negative first (Johnson, next lecture).

2 · Confusing a negative edge with a negative cycle

Negative edges are fine for Bellman–Ford and DAGs; a reachable negative cycle makes the problem ill-posed (δ=−∞). Do not try to “compute” through one — detect it with the extra pass and report it. And remember: an undirected edge of negative weight is a negative 2-cycle (walk back and forth), so undirected graphs with any negative edge are immediately ill-posed for this machinery.

3 · The off-by-one on passes

Bellman–Ford needs V−1 passes for the answer and one more for detection — not V for the answer. Run V passes for the answer and you have done a useless extra sweep; conflate the detector pass with the answer passes and you may misreport. Keep them distinct.

4 · Stale heap entries in lazy Dijkstra

With the push-duplicates idiom you must skip an entry whose vertex is already finalised (the if u in done: continue guard). Forget it and you reprocess vertices — at best wasted work, at worst, combined with other bugs, wrong output. Equivalent fix: skip when the popped du > d[u].

5 · Integer overflow at the sentinel

If d[u] = ∞ is encoded as INT_MAX, then d[u] + w overflows and wraps to a negative number, which then “relaxes” everything to garbage. Guard with if d[u] != INF before adding, or use a sentinel comfortably below the type's max (e.g. 10**18 for 64-bit).

6 · Treating unreachable as a bug

A vertex with no path from s correctly keeps d=∞. That is the answer, not an error — δ(s,v)=∞. Problems like “time for all nodes to receive the signal” expect you to return −1 precisely when some d stays ∞.

7 · Forgetting that Dijkstra solves a constrained problem wrongly

Add a side constraint — “at most k edges,” “exactly even length,” “collect these tolls” — and pure Dijkstra's greedy finalisation is no longer valid, because a vertex's best distance is no longer a sufficient summary of its state. The fix is to expand the state (e.g. (vertex, edges-used)) or fall back to a bounded Bellman–Ford. Practice problem 2 is the canonical trap.

13 practice

Problems

1

Network delay time

plain Dijkstra · non-negative weights · LeetCode 743

You are given times[i] = (u, v, w), directed travel times (w ≥ 0) on a network of n nodes labelled 1…n, and a source k. A signal starts at k. Return the minimum time for all n nodes to receive it, or −1 if some node never does. Recognise this as single-source shortest paths: compute δ(k,v) for every v; the answer is the maximum of those distances (the last node to hear), and −1 exactly when some δ is ∞. Constraints: 1 ≤ n ≤ 100, up to 6000 edges. Target O(E log V) with a binary-heap Dijkstra; state why “max, not sum” and handle the unreachable case.

2

Cheapest flights within K stops

bounded Bellman–Ford · state = (node, hops) · LeetCode 787

Given n cities and flights (u, v, price), find the cheapest fare from src to dst using at most K stops (so at most K+1 edges), or −1. The hop limit breaks Dijkstra's greedy optimality — a pricier path with fewer hops can beat a cheaper one that uses too many. Use Bellman–Ford relaxed exactly K+1 times. The subtle, decisive detail: each round must relax against a snapshot of the previous round's distances (copy the array), or a single round will chain several new hops and silently exceed the limit. Examples: n=3, flights=[[0,1,100],[1,2,100],[0,2,500]], src=0, dst=2; K=1→200, K=0→500. Give the O(K·E) algorithm and explain the copy.

3

Currency arbitrage detection

negative-cycle detection · the log reduction · classic

Given an n×n matrix rate where rate[i][j] is how many units of currency j you get per unit of i, determine whether an arbitrage exists: a cycle of conversions returning more than one unit of the starting currency. Find the reduction yourself: a product of rates around a cycle exceeds 1 if and only if the sum of −log(rate) around it is negative — i.e. iff the graph with edge weights w(i,j) = −log\,rate[i][j] has a negative cycle. Use Bellman–Ford with a virtual source (so every cycle is reachable) and the one-extra-pass detector. State the complexity in terms of n, and name two numerical pitfalls of working in floating-point logs.

4

Parallel courses III — the critical path

DAG longest path in topological order · LeetCode 2050

You have n courses (a DAG of prerequisite relations (prev, next)), where course i takes time[i] months. A course may begin only after all its prerequisites finish, and independent courses run in parallel. Return the minimum number of months to complete all courses. Recognise this as the longest path in a DAG (the critical path): finish[v] = time[v] + max over prereqs u of finish[u]. Process vertices in topological order (Kahn's indegree sweep) so every prerequisite is final before v; the answer is max_v finish[v]. Explain why the longest path is well-defined here but would be ill-posed (and NP-hard) on a general graph, and give the O(V+E) bound.

14 recap & next

The one thing to remember

Shortest paths are computed by one primitive — relax an edge — and the algorithm is nothing but the order in which you apply it. Relaxation keeps each estimate an honest, falling upper bound on the truth; the path-relaxation lemma says that relaxing any shortest path's edges in order makes its endpoint exact. Dijkstra buys the perfect order with a heap when weights are non-negative (O(E log V)); Bellman–Ford refuses to choose and relaxes everything V−1 times, surviving negative edges and detecting negative cycles on one extra pass (O(VE)); a DAG donates the order through its topological sort and solves it — negatives and all — in linear O(V+E). Match the row to your graph and never run greedy past the assumption that licenses it.
