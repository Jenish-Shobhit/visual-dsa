Last lecture answered one source: stand at a vertex, learn the distance to everyone. But the questions that bite want the whole matrix — the distance between every ordered pair. The diameter of a network (its longest shortest path). A routing table. The closeness of every node to every other. You can get all of it by running a single-source algorithm n times — or you can compute the entire n × n table with three nested loops and five lines. This lecture builds that loop from first principles (Floyd–Warshall, Θ(n³) for any weights), then sharpens it for sparse graphs by reshaping the weights themselves (Johnson’s reweighting).

A number to fix the stakes. Take a dense graph with n = 1000 vertices and possibly-negative edge weights, and ask for all 10⁶ pairwise distances. The honest baseline — run Bellman–Ford from each source because Dijkstra cannot survive a negative edge — costs Θ(n·nm)=Θ(n³m); on a dense graph that is Θ(n⁴) ≈ 10¹² elementary steps, roughly quarter of an hour.

Floyd–Warshall computes the same matrix, negative edges and all, in Θ(n³)=10⁹ steps — about one second. A 1000× gap, and the faster program is shorter. One idea buys it: grow the set of vertices a path is allowed to pass through, one vertex at a time.

01 the shape of the question

From one row to the whole table

A single-source shortest-path algorithm hands you one row of an answer: from a fixed source s, the distance δ(s,v) to every v. The all-pairs shortest paths (APSP) problem asks for the entire n × n matrix at once:

the object we must produce
D[i][j] = δ(i,j) = weight of the shortest directed path  i⇝j , for all ordered pairs  (i,j).

The input is a weighted directed graph G=(V,E) with n=|V| vertices, m=|E| edges, and a weight w(u,v) on each edge — weights may be negative, but (for the answer to exist) there must be no negative-weight cycle reachable along the paths we measure, else some distances are −∞. The output is the matrix D, and usually a companion structure that lets us reconstruct the actual paths.

The first instinct is correct and worth pricing out: solve APSP by solving SSSP once per vertex. The catch is the weights.

A non-negative weights

Run Dijkstra n times. One source costs O(m + n log n) with a binary heap.

All pairs: O(nm + n² log n). On a sparse graph that is O(n² log n) — excellent. But Dijkstra is wrong the instant one edge is negative.

B negative weights allowed

Run Bellman–Ford n times. One source costs O(nm).

All pairs: O(n²m). On a dense graph (m=Θ(n²)) that is O(n⁴) — the slow baseline the hero quoted.

So the landscape has two pressures. Negative edges forbid the cheap algorithm (Dijkstra); density makes the safe one (Bellman–Ford×n) cost n⁴. Floyd–Warshall escapes both at once: it tolerates negative edges and runs in Θ(n³) no matter the density — a single flat cost that beats n⁴ and asks nothing of the sign of the weights. Then Johnson’s algorithm wins the sparse case back, getting Dijkstra’s n² log n even when the graph has negative edges, by first making them non-negative without disturbing which paths are shortest.

why a matrix, not n separate runsThe deep reason Floyd–Warshall beats n separate searches is that the pairs share work. The shortest path from i to j and the shortest from i' to j' may both route through the same vertex k; computing “best route through k” once, for the whole matrix, is cheaper than rediscovering it inside every source’s independent search.

02 objectives & prerequisites

What you will be able to do

  • State the APSP problem and price its two SSSP-repetition baselines (n×Dijkstra, n×Bellman–Ford), knowing exactly which one each weight regime permits.
  • Derive the Floyd–Warshall recurrence over permitted intermediate vertices d⁽ₒ⁾(i,j)=min(d⁽ₒ⁻¹⁾(i,j), d⁽ₒ⁻¹⁾(i,k)+d⁽ₒ⁻¹⁾(k,j)) and prove it correct by induction on k.
  • Implement it in Θ(n³) time and Θ(n²) space, justify the in-place collapse of the k-index, reconstruct paths via a successor matrix, and detect negative cycles on the diagonal.
  • Derive Johnson’s reweighting: why a potential h(v) makes every reduced weight ŵ(u,v)=w(u,v)+h(u)−h(v) ≥ 0 while preserving every shortest path, and why Bellman–Ford from a super-source yields a valid h.
  • Choose between Floyd–Warshall and Johnson from the graph’s density, locating the crossover where O(nm + n² log n) overtakes Θ(n³).
  • Diagnose the classic disasters: the loop-order trap, the ∞+∞ overflow, undirected negative edges, the forgotten un-reduction in Johnson, and silent negative cycles.

Prerequisites

This lecture stands on the single-source machinery and a little algebra of recurrences. Where a prerequisite has its own page in this syllabus, it is linked.

Two facts you must hold firmly from Lecture 13. First, relaxation: an edge (u,v) is relaxed by testing whether going to v via u beats the best known route — if d[u]+w(u,v) < d[v]: d[v]=d[u]+w(u,v). Every shortest-path algorithm is a discipline for ordering relaxations. Second, a shortest path in a graph with no negative cycle is simple — it repeats no vertex — because excising any repeated stretch (a cycle of weight ≥ 0) never makes the path longer. That simplicity is the hinge of today’s correctness proof.

03 grow the permitted set, one vertex at a time

The Floyd–Warshall idea: a dimension nobody thinks to add

Here is the move that makes the whole thing mechanical. Number the vertices 1, 2, …, n. For a path from i to j, call its intermediate vertices everything strictly between the endpoints — the vertices it passes through, not i or j themselves. Now define a family of restricted distances indexed by an integer k:

the subproblem — a third index k bounding the permitted intermediates
d(k) (i,j) = length of the shortest i⇝j  path whose intermediate vertices all lie in  {1,2,…,k}.

Read the two ends of that ladder. At k=0 no vertex may be used as an intermediate, so the only legal i⇝j path is the direct edge: d⁽⁰⁾(i,j)=w(i,j) (with 0 on the diagonal and ∞ where no edge exists). At k=n every vertex is permitted, so the restriction is no restriction at all: d⁽ⁿ⁾(i,j)=δ(i,j), the true answer. The plan writes itself: start at the trivial layer d⁽⁰⁾ and climb to d⁽ⁿ⁾, admitting one more vertex into the permitted set at each step.

The climb — from layer k−1 to layer k — is a single binary choice. We are about to let paths use vertex k as an intermediate, on top of everything in {1,…,k−1} they could already use. For a given pair (i,j), the best path permitted at layer k either ignores the new option or seizes it:

  • It does not pass through k. Then its intermediates already lie in {1,…,k−1}, and its length is exactly d⁽ₒ⁻¹⁾(i,j) — nothing changed.
  • It passes through k. Because the path is simple (no negative cycle), it visits k exactly once. Split it there: i ⇝ k then k ⇝ j. Neither half uses k as an interior vertex, so each half’s intermediates lie in {1,…,k−1}, and each half is itself shortest under that restriction. The length is d⁽ₒ⁻¹⁾(i,k) + d⁽ₒ⁻¹⁾(k,j).

Take the smaller. That single line is the entire algorithm:

the Floyd–Warshall recurrence
d(k)(i,j) = min( d(k−1)⏟don’t use k (i,j) , d(k−1)(i,k)+d(k−1)(k,j)⏟route through k )

Look at what just happened. A two-dimensional question (a matrix of distances) became a three-dimensional table (the same matrix, indexed also by how many vertices it may use). The extra index is pure bookkeeping — it never appears in the input or the output — yet it converts a global optimisation over exponentially many paths into n sweeps of a trivial local choice. That is the signature of a dynamic program, and the next lecture will name it as such. For now, watch the decision drawn out:

# Floyd–Warshall — all-pairs shortest paths. O(n^3) time, O(n^2) space.
def floyd_warshall(W):            # W[i][j] = w(i,j), or INF if no edge; W[i][i] = 0
    n = len(W)
    D = [row[:] for row in W]      # D starts as layer 0: the raw weight matrix
    for k in range(n):             # OUTERMOST: k = highest permitted intermediate
        for i in range(n):
            dik = D[i][k]
            if dik == INF: continue      # no i..k path yet: nothing to route through k
            for j in range(n):
                if dik + D[k][j] < D[i][j]:    # relax (i,j) through k
                    D[i][j] = dik + D[k][j]
    return D
A two-dimensional problem solved by adding a third dimension nobody asked for — the count of vertices a path is allowed to remember.
04 why it is right, and why it fits in one matrix

Correctness, and the in-place collapse

Two things deserve proof, because both are load-bearing and both look like sleight of hand: that the recurrence computes δ, and that we may overwrite a single n×n matrix in place rather than keep n+1 separate layers.

Proof — the recurrence is correct (induction on k)

Claim. After the recurrence has processed layer k, the entry holds d⁽ₒ⁾(i,j) = the shortest i⇝j distance using intermediates only in {1,…,k}.

Base (k=0). With no permitted intermediates, the only candidate path is the single edge i→j (or the empty path when i=j). So d⁽⁰⁾(i,j)=w(i,j), which is exactly the initial matrix. ✓

Step. Assume the entries equal d⁽ₒ⁻¹⁾ before we process k. Fix (i,j) and let P be a shortest i⇝j path with intermediates in {1,…,k}. Either k is not an interior vertex of P — then P’s intermediates lie in {1,…,k−1} and w(P) ≥ d⁽ₒ⁻¹⁾(i,j) — or k is interior. In the latter case, since there is no negative cycle a shortest path is simple, so k appears once; the prefix i⇝k and suffix k⇝j each have interior vertices in {1,…,k−1} and must each be shortest under that restriction (else swap in a shorter sub-path and shorten P, a contradiction). Hence w(P)=d⁽ₒ⁻¹⁾(i,k)+d⁽ₒ⁻¹⁾(k,j). The minimum of the two cases is precisely the recurrence, and conversely both cases are achievable, so the minimum is attained. ✓

Now the space trick. The recurrence as written references three layers’ worth of values, suggesting an (n+1)×n×n table. In practice everyone runs it on one matrix D, overwriting entries as they go. Is that legal? When we compute layer k we read D[i][k] and D[k][j] — entries from row k and column k — but those reads happen while we are mutating D. We need them to still hold their layer-(k−1) values. They do, and here is the one-line reason:

row k and column k are frozen during pass k
d(k)(i,k) = min(d(k−1)(i,k), d(k−1)(i,k) + d(k−1)(k,k)⏟=0 ) = d(k−1)(i,k).

Because d⁽ₒ⁻¹⁾(k,k)=0 (no negative cycle through k), routing i⇝k “through k” adds nothing, so the column-k entry cannot improve during pass k; the symmetric argument freezes row k. The values we read are therefore exactly the layer-(k−1) values, whether or not they have already been “updated” — the update is a no-op. One matrix suffices. Θ(n²) space, Θ(n³) time, and the inner two lines are branch-free.

the one ordering that must holdk is the outermost loop — not i, not j. The induction is over layers: every pair must finish absorbing vertex k−1 before any pair is allowed to use vertex k. Swap the loops so i or j is outermost and you let some pairs race ahead to later waypoints before earlier ones are settled — the matrix fills with confident, wrong numbers. §09 shows the exact failure.

06 the route, and the certificate of doom

Reconstructing paths & detecting negative cycles

A distance is rarely enough; you usually want the path. Carry a second matrix alongside D. The cleanest is a successor matrix nxt[i][j] = the first vertex after i on a shortest i⇝j path. Initialise nxt[i][j]=j whenever the edge (i,j) exists. Every time a relaxation rewrites D[i][j] through k, the new path begins by heading toward k — so copy i’s successor toward k:

# inside the triple loop, when we relax (i,j) through k:
if dik + D[k][j] < D[i][j]:
    D[i][j]   = dik + D[k][j]
    nxt[i][j] = nxt[i][k]          # first step toward j is the first step toward k

def path(i, j, nxt):                 # O(length) reconstruction
    if nxt[i][j] is None: return []   # i cannot reach j
    route = [i]
    while i != j:
        i = nxt[i][j]
        route.append(i)
    return route

The other companion question is whether the answer exists at all. A negative cycle — a directed cycle of negative total weight — lets a path loop forever to drive its cost to −∞, so shortest distances along it are undefined. Floyd–Warshall does not announce this; it just returns finite-looking nonsense. The detector is one line, and it sits on the diagonal:

the diagonal is the alarmAfter the run, if any D[i][i] < 0, then vertex i lies on a negative cycle: the algorithm found an i⇝i closed walk of negative weight. In a clean graph every D[i][i] stays exactly 0. Always scan the diagonal before trusting the matrix — and if you intend to read off finite distances near a negative cycle, remember they are meaningless, not merely small.

One subtlety the formalist must flag: a single negative edge in an undirected graph is already a negative cycle, because the edge can be traversed back and forth (u→v→u = 2w < 0). APSP with negative weights is therefore a directed story. Undirected graphs with negative edges need different machinery (matching-based), well outside today’s scope.

07 bend the weights, not the graph

Johnson’s algorithm: reweighting for sparse graphs

Floyd–Warshall is Θ(n³) whether the graph is a dense web or a thin tree — it never looks at m. On a sparse graph (m = O(n)) that is wasteful: n runs of Dijkstra would cost only O(n² log n), far below n³. The single obstacle is that Dijkstra dies on negative edges. Johnson’s algorithm removes the obstacle: it transforms the weights so that all become non-negative, without changing which path between any two vertices is shortest — then runs n Dijkstras and corrects the answers back.

The reweighting trick

Assign each vertex a number h(v) — a potential, or “height.” Replace every edge weight by its reduced weight:

the reduced weight — a height difference added to each edge
w^(u,v) = w(u,v) +h(u) −h(v).

Why this exact form? Sum it along any path p = v₀→v₁→…→vₗ and the interior potentials telescope: each h(vᵢ) is added once (as the head’s +h(u)) and subtracted once (as the tail’s −h(v)), so everything cancels except the endpoints.

telescoping — every path’s length shifts by the same endpoint constant
w^(p) = ∑t=1ℓ [w(vt−1,vt)+h(vt−1)−h(vt)] = w(p)+h(v0)−h(vℓ).

This is the whole point. Every s⇝t path — long, short, all of them — has its reduced length shifted by the same constant h(s)−h(t), which depends only on the endpoints. Adding a constant to every candidate cannot change which one is smallest, so the shortest path is preserved exactly; only its recorded number changes, and we undo that at the end: δ(s,t)=δ̂(s,t)−h(s)+h(t).

Choosing h so every reduced weight is non-negative

We need ŵ(u,v)=w(u,v)+h(u)−h(v) ≥ 0, i.e. h(v) ≤ h(u)+w(u,v) for every edge. That inequality is exactly the triangle inequality satisfied by shortest-path distances. So pick any source q that can reach all vertices and set h(v)=δ(q,v); the relaxation-stable condition δ(q,v) ≤ δ(q,u)+w(u,v) then holds by definition. To guarantee q reaches everything, invent a super-source: add a new vertex q with a 0-weight edge to every original vertex. It has no incoming edges, so it creates no new cycle and disturbs no existing distance. Compute h(v)=δ(q,v) with one Bellman–Ford run — which doubles as the negative-cycle test.

# Johnson — APSP for sparse graphs. O(n*m + n^2 log n).
def johnson(n, edges):                 # edges: list of (u, v, w), vertices 0..n-1
    g = [[] for _ in range(n + 1)]    # 1. add super-source q = n
    for (u, v, w) in edges: g[u].append((v, w))
    for v in range(n): g[n].append((v, 0))   # q -> v, weight 0, for every v

    h = bellman_ford(n + 1, g, src=n)     # 2. potentials h[v] = dist(q, v)
    if h is None: raise NegativeCycle()   #    Bellman-Ford also detects -ve cycles

    gh = [[(v, w + h[u] - h[v]) for (v, w) in g[u]]   # 3. reweight: w_hat >= 0
          for u in range(n)]
    D = [[INF] * n for _ in range(n)]
    for u in range(n):                    # 4. Dijkstra from each real source
        dist = dijkstra(n, gh, src=u)
        for v in range(n):
            if dist[v] < INF:
                D[u][v] = dist[v] - h[u] + h[v]   # 5. un-reduce to true distance
    return D

The accounting: building the super-source and Bellman–Ford is O(nm); reweighting is O(m); the n Dijkstras dominate at O(n(m + n log n)) = O(nm + n² log n); un-reducing is O(n²). The headline is O(nm + n² log n). Bellman–Ford pays its O(nm) once, not once per source — that is the saving over the naive “Bellman–Ford from every vertex.”

08 the density crossover

Which one, and when

The choice is governed by one variable: the edge count m, relative to n². Floyd–Warshall is flat at Θ(n³) — insensitive to m. Johnson is O(nm + n² log n) — it rides up with density. They meet where nm ≈ n³, i.e. m ≈ n²/\!\log n.

09 where it breaks

Failure modes & common mistakes

These algorithms are short, so their bugs are quiet — they hand back a full matrix of plausible numbers, just wrong ones. Here is the catalogue I have watched trip up everyone, including me.

1 · the loop-order trapk must be the outermost loop. The recurrence is an induction on permitted-intermediate layers; routing through k is only valid once every pair has fully absorbed {1,…,k−1}. Put i or j outside k and you let a pair use a waypoint whose own best distances are not settled, producing too-large entries that never get a second chance. The code looks identical bar the loop order; the answers are wrong. Mnemonic: k, then from, then to.
2 · ∞ + ∞ overflowCoding ∞ as INT_MAX and then evaluating D[i][k]+D[k][j] overflows to a large negative number, which beats the real distance and corrupts the cell. Guard it: skip the relax when either operand is ∞ (the if dik == INF: continue in §03), or use a soft sentinel like INF = 10¹⁸ with 64-bit math so two of them can sum without wrapping.
3 · silent negative cyclesIf a reachable negative cycle exists, true distances are −∞ and the matrix is meaningless. Floyd–Warshall will not raise — you must scan the diagonal for D[i][i] < 0 afterward. In Johnson, the Bellman–Ford stage detects it; if you skip that check (or replace Bellman–Ford with something that does not detect cycles) the reduced weights can be negative and Dijkstra silently misbehaves.
4 · running Dijkstra n times on negative edgesThe seductive shortcut: “just run n Dijkstras, it’s faster.” Dijkstra is simply incorrect with even one negative edge — it finalises a vertex too early and never revisits it. This is the entire reason Johnson exists: reweight first, then Dijkstra. Never feed raw negative weights to Dijkstra.
5 · Johnson without the un-reductionReturning δ̂(u,v) instead of δ̂(u,v) − h(u) + h(v) gives distances that are off by an endpoint-dependent constant — frequently positive, so they look reasonable and pass small tests. Equally fatal: using a real vertex as the potential source instead of a super-source. If that vertex cannot reach some w, then h(w)=∞ and the reduced weights around w are garbage.
6 · undirected graphs with negative edgesAn undirected negative edge is a 2-cycle of negative weight, so the problem is ill-posed before any algorithm runs. If your graph is undirected and all weights are ≥ 0, fine — orient each edge both ways and proceed. With a negative undirected edge, stop: APSP is undefined.
7 · reconstruction that forgets the k-updateIf you keep a successor (or predecessor) matrix but forget to update it on the very relaxations that improve D inside the k-loop, D is right while the path matrix points along stale, longer routes. Update both in the same if, every time — nxt[i][j]=nxt[i][k] rides along with the distance write.

Find the City With the Smallest Number of Reachable Neighbors

There are n cities numbered 0…n−1 and a list of bidirectional weighted edges[i]=[u,v,w]. For a given distanceThreshold, find the city with the fewest other cities reachable within total distance ≤ distanceThreshold; on a tie, return the city with the largest index.

Signature: int findTheCity(int n, int[][] edges, int distanceThreshold)

Constraints: 2 ≤ n ≤ 100; 1 ≤ w ≤ 10⁴; weights non-negative. Example: n=4, edges=[[0,1,3],[1,2,1],[1,3,4],[2,3,1]], threshold=4 → city 3.

Hint lens: n ≤ 100 screams Floyd–Warshall (10⁶ ops). Build the full distance matrix, then count per row how many entries are ≤ threshold.

2

All-Pairs Distances with Path Recovery & Cycle Guard

Given an n×n weight matrix W of a directed graph (W[i][j]=∞ for no edge, W[i][i]=0, weights possibly negative), implement an APSP engine. Support dist(u,v) and path(u,v) (the actual vertex sequence, or empty if unreachable). If the graph contains a negative cycle, build() must report it instead of returning distances.

Signature: class APSP { APSP(long[][] W); boolean hasNegativeCycle(); long dist(int u,int v); List<Integer> path(int u,int v); }

Constraints: 1 ≤ n ≤ 400; |w| ≤ 10⁹ (use 64-bit, sentinel INF=10¹⁸). Example: a 4-node graph from §05 returns dist(2,1)=7 and path(2,1)=[2,3,4,1].

Hint lens: Floyd–Warshall with a successor matrix; nxt[i][j]=nxt[i][k] on each relax; scan the diagonal for D[i][i]<0.

3

Sum of All Finite Shortest Distances on a Sparse Graph

A directed graph has n vertices and m edges with possibly-negative weights and no negative cycle. Return the sum of δ(u,v) over all ordered pairs with a finite path (count each finite pair once). The sizes rule out an Θ(n³) solution — you must reweight.

Signature: long sumShortest(int n, int[][] edges)  with edges[i]=[u,v,w]

Constraints: 1 ≤ n ≤ 2×10⁴; 0 ≤ m ≤ 10⁵; |w| ≤ 10⁶. Note n³=8×10¹² is far too slow, but nm log n ≈ 3×10⁶ is fine.

Hint lens: Johnson — super-source, Bellman–Ford for h, reweight, n Dijkstras, un-reduce, then add only the finite results.

4

Currency Arbitrage Detection

Given c currencies and a table rate[i][j] — one unit of i buys rate[i][j] units of j — decide whether a sequence of trades can return to the start currency with more than you began (an arbitrage cycle). If none exists, also report, for every pair (i,j), the best achievable product of rates from i to j.

Signature: boolean hasArbitrage(double[][] rate)  (plus the best-rate matrix when false)

Constraints: 2 ≤ c ≤ 200; 0 < rate[i][j] ≤ 10⁶. Example: a 3-currency table where A→B→C→A multiplies to 1.02 returns true.

Hint lens: products become sums under a logarithm. Set w(i,j)=−log rate[i][j]; a profitable cycle (product > 1) becomes a negative cycle (sum < 0). Run Floyd–Warshall and watch the diagonal.

11 recap & next

The one thing to remember

Solve a two-dimensional distance matrix by adding a third index: the count of vertices a path may pass through. Grow that permitted set from ∅ to all of V, one vertex at a time, and each step is a single relaxation — route through the new vertex k, or don’t. That is Floyd–Warshall: Θ(n³), five lines, negative edges welcome, the diagonal a built-in negative-cycle alarm. When the graph is sparse, don’t pay n³ — reshape the weights with a potential so they turn non-negative without disturbing any shortest path, then let Dijkstra run n times. Floyd–Warshall and Johnson are two answers to one question, split by density.

And notice the through-line. The recurrence over permitted intermediates is not really a graph trick — it is a dynamic program, an optimisation over a layered table of subproblems where each layer is a trivial choice over the last. The next lecture pulls that pattern into the open: optimal substructure, overlapping subproblems, and the realisation that Floyd–Warshall is shortest-path-over-a-DAG-of-subproblems in disguise.
