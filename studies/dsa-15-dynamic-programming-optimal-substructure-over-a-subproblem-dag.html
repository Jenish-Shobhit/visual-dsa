02 What you will be able to do

Objectives & prerequisites

By the end of this page you should be able to look at a fresh optimisation problem and decide, in minutes, whether dynamic programming applies — and if it does, write the recurrence, the order, and the reconstruction without guessing.

After this you can…

  • Recognise optimal substructure and overlapping subproblems, and tell DP apart from divide-and-conquer and greedy.
  • Model any DP as a directed acyclic graph of subproblems — nodes are states, edges are transitions — and read the answer as a single relaxation pass in topological order.
  • Derive and implement edit distance, 0/1 knapsack, and interval DP from their recurrences, including reconstruction of the optimal object, not just its cost.
  • Re-derive the Floyd–Warshall recurrence from first principles and explain why adding a dimension (the allowed-intermediates index k) acyclifies a graph that may itself contain cycles.
  • Diagnose DP failures: an under-specified state, a wrong sweep direction, a misidentified semiring, and the pseudo-polynomial trap.

03 Build it from first principles

The tree lies; the DAG tells the truth

Strip a problem of its costume and a dynamic program is one structure: a graph of subproblems. Each node is a smaller instance of the same question; each edge is a decision that reduces one instance to another. That skeleton helps us understand familiar problems such as knapsack.

Start with the smallest honest example. The Fibonacci numbers obey F(n) = F(n−1) + F(n−2). Write that as recursion and you get a tree of calls. But look closely: F(3) is computed twice, F(2) three times, F(1) five times. The tree is fat with repetition. Now do the one move that matters — quotient the tree by equal state: glue together every node that asks the same question. The fat tree collapses into a thin graph.

The two properties that license DP

Not every problem permits this collapse. Two properties must hold, and they are worth stating precisely because their absence is the most common reason a DP is silently wrong (see §08).

Property 1 — Optimal substructure (the Bellman principle)

An optimal solution to the whole is composed of optimal solutions to its parts. Formally: the optimum at a state is a fixed combiner (min, max, sum) applied to the optima of the states it depends on, and choosing a sub-optimal answer for any part can never improve the whole. Subproblems must not interfere: solving one optimally must not spoil another.

Property 2 — Overlapping subproblems

The same subproblem is reached by many different routes. In graph terms, nodes have in-degree > 1: the recursion reconverges. This is exactly what makes caching pay — there are far fewer distinct nodes than root-to-leaf paths.

The contrast sharpens both. Divide-and-conquer (mergesort) also has optimal substructure — but its subproblems are disjoint. The recursion is a genuine tree; nothing reconverges; there is nothing to cache. Greedy (Lecture 16) goes further and claims you never even need to compare alternatives: one local choice is provably optimal. Dynamic programming is the regime in between — subproblems overlap, so you must remember; but choices interact, so you must compare. DP = remember + compare.

The formal skeleton: a weighted DAG and one relaxation pass

Here is the abstraction that holds every example in this lecture. Let the subproblems be the vertices V of a directed graph; put an edge u → v whenever the optimum at v may be built from the optimum at u by taking a decision of cost w(u,v). Because every state depends only on strictly smaller states, this graph is acyclic. The DP value of a node is:

The master recurrence — a DAG relaxation in a semiring
f(v)= ⊕u→v (f(u)⊗w(u,v)) ⊕base(v)

The pair (⊕, ⊗) is a semiring — choose it to fit the question:

  • (min, +) — shortest path / fewest edits / least cost. This is exactly the relaxation move from Lecture 13.
  • (max, +) — longest path / most value (knapsack).
  • (+, ×) — counting the number of solutions / paths.
  • (∨, ∧) — feasibility / reachability (can it be done at all?).

And the algorithm is now embarrassingly small: evaluate the nodes in topological order, relaxing each edge once. On a DAG, a single pass in topological order is exact — no Dijkstra priority queue, no Bellman–Ford iteration, because there are no back-edges to invalidate a finished node. Memoisation finds that order lazily (depth-first, fill on the way back up); tabulation commits to it eagerly (loop in increasing state size).

A dynamic program is a shortest path you forgot you were drawing.— the thesis of Lecture 15

The recipe — what can be mechanised

Designing a DP is not inspiration; it is a procedure. Five of these seven steps are fully mechanical. Two — defining the state and writing the recurrence that proves substructure — are where judgement lives, and that boundary is the real lesson.

  1. Define the state. A tuple that fully determines the rest of the decision. Test it: “if I tell you only the state, can you finish optimally without knowing how you got here?” If not, the state is missing a dimension. (This is the memoryless / Markov test.)
  2. Write the recurrence. Express f(state) from strictly smaller states plus one local choice. Name your ⊕ (combine) and ⊗ (extend).
  3. Pin the base cases. The smallest states — the source nodes of the DAG, in-degree 0.
  4. Order the states. A topological order of the DAG, usually “by increasing size” of some dimension. Verify no edge points backward.
  5. Choose memoisation or tabulation. Lazy top-down, or eager bottom-up. (Same complexity; different engineering — see below.)
  6. Reconstruct. Store the winning predecessor (argmin/argmax) at each node; walk it back from the answer to recover the actual object, not just its score.
  7. Account. Time = (#states) × (work per state). Space = (#states), often shrinkable to just the active frontier.

Memoisation vs tabulation

Memoisation is recursion plus a cache. It visits only the states the answer actually reaches, which is a gift when the reachable set is sparse or the order is awkward to write by hand. The price: recursion-stack depth and hashing overhead. Tabulation fills a table in an explicit topological sweep. It computes every state in range — sometimes wastefully — but because you control the sweep, you can throw away everything but the frontier and collapse an O(n·W) table into an O(W) array. Both are the same DAG; they differ only in who chooses the order.

# Memoisation — lazy, top-down. Visits only reachable states.
def fib(n, memo={}):
    if n < 2: return n
    if n in memo: return memo[n]   # cache hit = a reconverged DAG node
    memo[n] = fib(n-1, memo) + fib(n-2, memo)
    return memo[n]

# Tabulation — eager, bottom-up. Frontier is just two numbers, so O(1) space.
def fib_tab(n):
    a, b = 0, 1
    for _ in range(n): a, b = b, a + b
    return a

04 Worked example · fully traced

Edit distance: the grid is the DAG

The Levenshtein edit distance between two strings is the minimum number of single-character insertions, deletions, and substitutions to turn one into the other. It powers spell-checkers, DNA alignment, and diff. It is also the cleanest possible picture of a two-dimensional subproblem DAG.

Step 1 — the state

Let A and B be the strings, lengths m and n. Define dp[i][j] = the edit distance between the first i characters of A and the first j characters of B. Two integers fully determine the remaining problem — the Markov test passes. The state space is an (m+1) × (n+1) grid; that grid is the DAG.

Step 2 — the recurrence

Stand at cell (i,j) and consider the last characters. If A[i]=B[j], they cost nothing and you step diagonally. Otherwise you pay 1 and take the best of three moves: delete A[i] (step from above), insert B[j] (step from the left), or substitute (step diagonally).

Levenshtein recurrence — a (min, +) relaxation with up to three in-edges
dp[i][j]= { dp[i-1][j-1]  if A[i]=B[j] 1+min ( deletedp[i-1][j], dp[i][j-1], dp[i-1][j-1] )  otherwise

Base cases. dp[i][0]=i (delete all i characters) and dp[0][j]=j (insert all j). These are the source nodes — the top row and left column. Answer: dp[m][n], the bottom-right sink. Order: any sweep with i and j increasing (row-major works) is topological, because every edge comes from a cell with a smaller i+j.

Step 3 — fill the table for A = “horse”, B = “ros”

Now the payoff: watch the grid fill and the answer fall out as the value in the corner. Below, each cell holds dp[i][j]; the bold red line is the optimal path the reconstruction walks back.

Notice what reconstruction needs: at each cell, remember which neighbour won the min. That stored argmin is a parent pointer; the chain of parents from (m,n) back to (0,0) is a path through the DAG — and a path through this particular DAG is an alignment of the two strings. The cost and the object are the same walk.

def edit_distance(a, b):
    m, n = len(a), len(b)
    dp = [[0]*(n+1) for _ in range(m+1)]
    for i in range(m+1): dp[i][0] = i      # delete all of a[:i]
    for j in range(n+1): dp[0][j] = j      # insert all of b[:j]
    for i in range(1, m+1):
        for j in range(1, n+1):
            if a[i-1] == b[j-1]:
                dp[i][j] = dp[i-1][j-1]           # match — step diagonally, free
            else:
                dp[i][j] = 1 + min(dp[i-1][j],     # delete
                               dp[i][j-1],     # insert
                               dp[i-1][j-1])  # replace
    return dp[m][n]

Complexity: (m+1)(n+1) states, O(1) work each → O(mn) time. Because row i reads only rows i and i−1, two rows are the whole frontier → O(min(m,n)) space if you only need the number. Keep the full table only when you must reconstruct.

05 Worked example · the (max, +) twin

0/1 knapsack: take it or leave it

Given items each with a weight and a value, and a sack that holds total weight W, choose a subset of maximum value. “0/1” means each item is taken whole or not at all. Same DAG machinery as edit distance — only the semiring flips from (min,+) to (max,+).

State, recurrence, order

Let K(i, w) = the most value obtainable from the first i items within weight budget w. Facing item i you have exactly two edges: leave it (inherit K(i−1, w)) or take it (gain vi, but only if it fits, landing on K(i−1, w−wi)).

0/1 knapsack — a (max, +) longest-path over a layered DAG
K(i,w)=max ( Kleave(i-1,w) , Ktake(i-1,w-wi)+vi )

The “take” branch is allowed only when wi ≤ w. Base: K(0, w) = 0. Order the states by increasing i — each item is one topological layer; the answer is K(n, W).

The famous one-line trap

Knapsack is usually written with a rolling 1-D array. The direction of the inner sweep is not a style choice — it encodes which DAG edges exist. This is the single most common DP bug, and we will name it again in §08.

def knapsack_01(weights, values, W):
    dp = [0]*(W+1)
    for i in range(len(weights)):
        for w in range(W, weights[i]-1, -1):   # DESCENDING ⇒ 0/1: each item used once
            dp[w] = max(dp[w], dp[w-weights[i]] + values[i])
    return dp[W]
    # Flip to range(weights[i], W+1) — ASCENDING — and you have UNBOUNDED knapsack.

Complexity: n·(W+1) states, O(1) each → O(nW) time, O(W) space rolling. Hold that O(nW) — it looks polynomial, and §08 explains why that appearance is a lie.

06 The headline · re-deriving Lecture 14

Floyd–Warshall: a dimension that acyclifies the graph

You met Floyd–Warshall as an algorithm — three nested loops, all-pairs shortest paths, O(n³). But a graph can contain cycles; how can shortest paths be a DAG of subproblems? The resolution is the deepest idea in this lecture: you invent a new dimension whose growth is, by construction, acyclic.

The state that does the trick

Number the vertices 1…n. Define d(k)[i][j] = the length of the shortest path from i to j that is permitted to use intermediate vertices only from the set {1, …, k}. The index k is not a vertex on the path — it is a permission level: “how much of the graph am I allowed to route through.”

Now grow k by one. The shortest i→j path allowed to use {1…k} either ignores the newly unlocked vertex k (and is the old d(k−1)[i][j]), or it routes through k exactly once — splitting into a best i→k piece and a best k→j piece, each using only {1…k−1}:

The Floyd–Warshall recurrence — (min, +) over the permission dimension k
d(k)[i][j] =min( d(k-1)[i][j] , d(k-1)[i][k] + d(k-1)[k][j] )

Base: d(0)[i][j] = the direct edge weight (or ∞, with 0 on the diagonal). Answer: d(n). Crucially, every cell of layer k depends only on layer k−1. The subproblem graph is layered by k — and a layered graph is acyclic no matter what the input graph looks like. The added dimension is the topological order.

A useful observation — where the abstraction earns its keep

This is the general trick for “impossible” DPs: when the natural state graph has cycles, look for a monotone dimension — a quantity that only ever increases (vertices unlocked, items considered, interval length, prefix length) — and index your subproblems by it. Monotonicity is acyclicity. The art is choosing that dimension; the rest is mechanical.

07 A third state shape

Interval DP: the state is a sub-segment

Prefix DPs (edit distance, knapsack) index states by how much you have consumed from the start. But some problems have no meaningful “start” — the decision is where to split. Then the natural state is an interval [i, j], and the recurrence chooses a split point k inside it.

The interval-DP template — combine over an internal split k
f(i,j)= mini<k<j [f(i,k)+f(k,j)+cost(i,k,j)]

The topological order is by increasing interval length: every f(i,j) depends only on strictly shorter intervals, so fill all length-1 intervals, then length-2, and so on. There are O(n²) intervals and each tries O(n) splits → O(n³), the familiar interval-DP cost.

The canonical members: matrix-chain multiplication (where to parenthesise a product to minimise scalar multiplications; cost is the multiply count of merging two parenthesised blocks), optimal binary search trees, palindrome partitioning, and “burst balloons” — where the key inversion is to index the split by the last balloon burst in the interval, not the first, so the two sides become independent. You will meet burst balloons in the practice set; the entire difficulty is finding the state for which the substructure actually holds.

08 Where it breaks

Failure modes & common mistakes

DP fails quietly. A wrong DP usually returns a number, just not the right one — no crash, no exception. My own blind spot is loving an abstraction past the point where it still fits the problem; here are the six places that bites hardest.

1 · No optimal substructure — the silent killer

The most dangerous error is applying DP where the Bellman principle simply does not hold. Shortest simple path has optimal substructure; longest simple path does not. Why the asymmetry? A sub-path of a shortest path is shortest between its endpoints — but a sub-path of a longest simple path need not be longest, because the “no repeated vertex” constraint makes the pieces interfere: the best long i→k walk may reuse a vertex that the best k→j walk also needs. The subproblems are not independent, so no DP over (current vertex) is correct. (Indeed, longest simple path is NP-hard; the only honest DP is over subsets of visited vertices — Held–Karp — which is exponential.) Test before you trust: can two optimal sub-solutions always be combined without conflict?

2 · An under-specified state (failing the Markov test)

If f(state) secretly depends on how you arrived, the state is missing a dimension and the recurrence is wrong on some inputs. Symptom: it passes small tests and fails larger ones. In knapsack the state needs remaining capacity, not just the item index; in “house robber” you need whether the previous element was taken. Fix by adding the dimension that restores memorylessness — but no more, or the state space explodes.

3 · The wrong sweep direction — the 0/1-vs-unbounded bug

In the rolling-array knapsack, iterating the budget descending gives 0/1 (each item once); ascending gives unbounded (each item reused). The direction is not cosmetic — it decides whether dp[w−wi] already includes item i or not, i.e. which edges your DAG has. Tabulate in an order where a cell reads a neighbour you have already overwritten this round and you are silently solving a different problem. Always check: does my loop read each dependency before or after it is updated?

4 · The wrong semiring, and double counting

Use (max,+) when the question was “how many ways” (it wanted (+,×)), and you get a best instead of a count. Counting DPs have their own trap: the edge decomposition must partition the solution set, or paths get counted twice. When summing, also remember the modulus and watch for overflow.

5 · The pseudo-polynomial trap

Knapsack's O(nW) looks polynomial, but W is a number in the input, and a number of magnitude W takes only log W bits to write. So the runtime is exponential in the input size. This is why knapsack is NP-hard yet has a “fast” table: the table is fast in the value, not the length. As a formalist I find this the most honest humility in the subject — “polynomial” is a claim about bits, and the abstraction quietly changed units.

6 · Memory and stack blow-ups

Storing the full O(n·W) or O(mn) table when only the frontier is needed wastes memory you may not have; collapse to a rolling array once reconstruction is not required. And deep memoised recursion can overflow the call stack on large n — convert the hot recursion to bottom-up tabulation, or raise the recursion limit deliberately.

The one diagnostic that catches most of these

Before coding, draw three nodes of your DAG and ask: do all of a node's in-edges come from states I will have finished before I reach it? If yes, your order is valid. If you cannot even answer because you do not know what a “state” is here, your state is under-specified — stop and fix that first.

Five problems across the five state-shapes

01Decode WaysLeetCode 91 · 1-D counting

A message of digits is encoded by A→1, B→2, …, Z→26. Count the number of ways to decode it. A '0' cannot start a code, and only 10 and 20 are valid two-digit codes beginning with those digits.

def numDecodings(s: str) -> int

Example 1: s = "226" → 3 ("2 2 6", "22 6", "2 26") Example 2: s = "06" → 0 (leading zero is invalid) Constraints: 1 ≤ len(s) ≤ 100 ; s consists of digits

Hint to frame, not solve: this is a (+)-semiring prefix DP — f(i) = ways to decode the first i digits. The subtlety is entirely in which in-edges (one-digit, two-digit) are legal.

02Edit DistanceLeetCode 72 · 2-D grid

Given two words, return the minimum number of single-character insert / delete / replace operations to convert the first into the second. Then (beyond the LeetCode ask) reconstruct one optimal edit script.

def minDistance(word1: str, word2: str) -> int

Example 1: "horse", "ros" → 3 Example 2: "intention", "execution" → 5 Constraints: 0 ≤ len ≤ 500 ; lowercase English letters

You saw the table filled in §04. Re-derive it cold, then add parent pointers and print the operations.

03Coin ChangeLeetCode 322 · unbounded knapsack

Given coin denominations and a target amount, return the fewest coins that sum to it, or -1 if impossible. Each coin may be used unlimited times.

def coinChange(coins: List[int], amount: int) -> int

Example 1: coins = [1,2,5], amount = 11 → 3 (5 + 5 + 1) Example 2: coins = [2], amount = 3 → -1 Constraints: 1 ≤ coins.length ≤ 12 ; 0 ≤ amount ≤ 10⁴

A (min, +) DP on amount. Decide the sweep direction deliberately (recall §08·3) — and how you represent “impossible” so that min behaves.

04Burst BalloonsLeetCode 312 · interval DP

Balloons in a row carry numbers nums[i]. Bursting balloon i yields nums[left]·nums[i]·nums[right] coins, where left/right are its current neighbours (treat out-of-range as 1). After bursting, neighbours become adjacent. Maximise total coins.

def maxCoins(nums: List[int]) -> int

Example 1: nums = [3,1,5,8] → 167 Example 2: nums = [1,5] → 10 Constraints: 1 ≤ n ≤ 300 ; 0 ≤ nums[i] ≤ 100

The classic inversion: index the split by the last balloon burst in an open interval (i, j), so the two sides become independent subproblems. Topological order = increasing interval length.

05Find the City With the Smallest Number of NeighborsLeetCode 1334 · Floyd–Warshall

Given n cities and weighted edges, and a distanceThreshold, find the city reachable from the fewest other cities within that threshold; on a tie, return the city with the greatest index.

def findTheCity(n, edges, distanceThreshold) -> int

Example: n = 4, edges = [[0,1,3],[1,2,1],[1,3,4],[2,3,1]], distanceThreshold = 4 → 3 Constraints: 2 ≤ n ≤ 100 ; weights, threshold ≤ 10⁴

Compute all-pairs shortest paths with the §06 recurrence, then count, per city, how many others sit within the threshold. Watch the k loop ordering — it is the topological sweep.

10 Recap & what's next

The one thing to remember

Dynamic programming is one relaxation pass over a directed acyclic graph of subproblems. Define the state so the future depends only on it (optimal substructure); notice that states reconverge (overlapping subproblems); pick the semiring; sweep in topological order; store parents to reconstruct. Every example here — edit distance, knapsack, Floyd–Warshall, interval DP — is that single picture wearing a different costume.

If a problem resists it, the resistance is informative: either the substructure fails (your pieces interfere) or your state is too thin to be memoryless. Diagnose which, and you will know whether to add a dimension or to abandon DP for something else.
