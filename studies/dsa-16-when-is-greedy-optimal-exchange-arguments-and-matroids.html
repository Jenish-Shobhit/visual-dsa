When is greedy provably optimal?

No. Greedy rules need a proof tied to the problem; locally cheap edges can lead to expensive later choices.

Two problems wear the same instinct — take the best per pound, never look back. On fractional knapsack that instinct is exactly optimal. On 0/1 knapsack the very same greedy leaves a quarter of the value on the floor. The difference is not the objective. It is the shape of the feasible set — and that shape has a name.

02 What you will be able to do

Objectives & prerequisites

By the end of this page you should be able to look at a fresh optimisation problem and say — with a proof, not a hunch — whether a greedy choice is safe, and if it is not, name the structural defect that sends you to dynamic programming.

After this you can…

  • Run the exchange-argument template on a greedy algorithm: take any optimum, swap in the greedy choice, show it never gets worse, repeat.
  • Define a matroid from its three independence axioms, and read the third — the exchange axiom — as the abstract form of that swap.
  • State and apply the Rado–Edmonds theorem: weight-ordered greedy maximises every non-negative weighting over a downward-closed set system if and only if that system is a matroid.
  • Recognise the three canonical matroids — uniform, partition, graphic — and map a new problem onto one (Kruskal's MST is greedy on the graphic matroid).
  • Diagnose why greedy fails on 0/1 knapsack, weighted interval scheduling, and non-canonical coin systems — a broken exchange axiom — and reach for DP instead.

03 Build it from first principles

A greedy algorithm is a commitment strategy

Strip the costume off every greedy algorithm and the same machine is underneath. It builds a solution one element at a time; at each step it picks the locally best element by some fixed criterion; and — this is the whole gamble — it never reconsiders. No backtracking, no lookahead. The key question is: when does a sequence of irrevocable, locally-best commitments compose into a globally optimal object?

That question is not about the scoring function. It is about the feasible family — the collection of partial solutions you are allowed to hold. Greedy walks that family, and whether the walk lands on the optimum depends on whether the family has a particular closure property. Two ingredients must both be present:

  • Greedy-choice property. There exists an optimal solution that agrees with greedy's first choice. You never need to look ahead because a best answer is always reachable through the locally best move.
  • Optimal substructure. Once that first choice is committed, what remains is a smaller instance of the same problem, and gluing the choice onto an optimum of the remainder yields a global optimum.

Optimal substructure you met in Deep study 15 — it is shared with DP. The thing that separates greedy from DP is the first property: the claim that a single local move is always safe. The exchange argument is the technique that proves it, and the matroid is the structure that guarantees the technique always succeeds, for any weighting at all.

The one distinction to hold

DP compares alternatives when choices interact. Greedy commits to one choice. An exchange proof can license that commitment for a particular objective. A matroid gives a stronger guarantee: the standard weight-ordered greedy algorithm works for every non-negative weighting.

04 Worked example I — the technique

The exchange argument, fully worked

The exchange argument proves the greedy-choice property by transforming rather than constructing. You do not build the optimum; you take an arbitrary optimum OPT and rewrite it, one swap at a time, into greedy's answer G, proving every swap leaves it (a) feasible and (b) no worse. If OPT can become G without ever losing quality, then G is itself optimal. Let me run it end to end on the cleanest case.

Interval scheduling: maximise the count of compatible activities

You are given activities, each an interval [start, finish). Two activities are compatible if they do not overlap. Choose the largest set of pairwise-compatible activities. The greedy rule: sort by finish time, repeatedly take the next activity that starts no earlier than the last one you took.

Run it on six activities. Sorted by finish time:

Greedy returns {A, C, E}, three activities. No set of four compatible activities exists here, so greedy is optimal — but the trace is not a proof. The exchange argument is.

The proof: greedy's first pick is always safe

Let a₁ be the activity with the earliest finish time overall — greedy's first choice. Claim: some optimal solution contains a₁.

Exchange. Take any optimal solution O and sort its activities by finish time; call the first one ak. If ak = a₁ we are done. Otherwise, because a₁ finishes earliest of all activities, it finishes no later than ak. So a₁ cannot overlap anything that came after ak in O (those all start after ak finishes ≥ after a₁ finishes). Swap: O' = O − {ak} + {a₁}. This O' is still pairwise-compatible, and |O'| = |O|, so it is still optimal — and it contains a₁. The greedy choice is vindicated.

Induction. Delete a₁ and every activity overlapping it; what remains is a strictly smaller interval-scheduling instance. By the same argument greedy's next pick is safe there, and so on. By induction the whole greedy set is optimal. ∎

Why "earliest finish," not "shortest" or "earliest start"?

Earliest finish time is the criterion that maximises the leftover — it ends the chosen activity as early as possible, leaving the most room for the recursive subproblem. The two tempting alternatives both break:

  • Shortest duration first fails when [2,4) is chosen ahead of the compatible pair [0,3) and [3,6): the short middle interval blocks two activities.
  • Earliest start first fails on one long early interval [0,100) that devours the timeline against many short ones.

The exchange argument is what certifies "earliest finish" — it is the only one of the three for which the swap above goes through. That is the discipline: the criterion is not chosen by taste, it is chosen because a swap proof exists for it.

Generalising the swap

Notice the shape of the move: replace one choice in an optimum with the earliest-finishing activity, preserving the number of activities. This proves the unweighted interval-scheduling rule. Compatible interval sets are generally not a matroid, so this proof does not justify choosing the heaviest interval first. The matroid exchange axiom, introduced next, is a stronger property that guarantees weight-ordered greedy for every weighting.

05 The abstraction

The matroid: independence, axiomatised

In 1935 Hassler Whitney noticed that two utterly different notions of "independence" — linearly independent columns of a matrix, and acyclic sets of edges in a graph — obey the same three rules. He distilled the rules and called the object a matroid. It is one of the most economical abstractions in mathematics, and it is precisely the structure that makes greedy honest.

A matroid is a pair M = (E, I): a finite ground set E and a family I of subsets of E, called independent sets, satisfying three axioms.

  • I1
    Non-triviality

    The empty set is independent: ∅ ∈ I. (There is always somewhere to start.)

  • I2
    Heredity — downward closed

    Every subset of an independent set is independent: if A ∈ I and B ⊆ A, then B ∈ I. (Removing elements never creates a conflict.)

  • I3
    Exchange / augmentation — the heart

    If A, B ∈ I and |A| < |B|, then some element of B can be moved into A keeping it independent.

The exchange axiom (I3), formally
A,B∈I  and  |A|<|B| ⟹ ∃x∈B∖A : A∪{x}∈I

Axioms I1 and I2 just say I is a non-empty, downward-closed family — that much is true of any reasonable feasibility notion (compatible activities, sub-budget item sets, acyclic edge sets). The entire weight of the theory sits in I3. It is the abstract swap: a smaller independent set is never "stuck"; it can always grow toward any larger one. Here is what it looks like.

Two pieces of vocabulary fall straight out of I3. A maximal independent set is a basis; by the axiom every basis has the same cardinality, the rank of the matroid. (In the column matroid this is the rank of the matrix; in the graphic matroid it is |V| − (number of components), the size of a spanning forest.) Greedy, as we will now see, builds a maximum-weight basis.

06 Worked example II — the theorem

Rado–Edmonds: greedy is optimal ⟺ matroid

Here is the payoff — the sharpest answer the title can be given. Fix a downward-closed set system M = (E, I) (so I1, I2 hold) and a non-negative weight w : E → ℝ≥0. The greedy algorithm is:

def greedy_matroid(E, w, independent):
    # E: ground set · w: weights · independent(S): is S in I?
    S = []
    for e in sorted(E, key=w, reverse=True):   # heaviest first
        if w(e) <= 0: break                      # non-neg objective: ignore junk
        if independent(S + [e]):                 # does it stay legal?
            S.append(e)                          # COMMIT — never reconsider
    return S

Rado–Edmonds theorem (1957 / 1971)

greedy_matroid returns a maximum-weight independent set for every non-negative weight function w if and only if M is a matroid — that is, if and only if M also satisfies the exchange axiom I3.

The "for every w" is the soul of the statement. A particular weighting can get lucky on a non-matroid; the theorem says luck holds for all weightings precisely when I3 holds. Both directions are instructive. Let me prove the direction you will use — matroid ⟹ greedy optimal — by an exchange argument, then sketch the converse, which is where the real insight lives.

Direction ⟸ : if M is a matroid, greedy is optimal

Let greedy output G = {g₁, g₂, …, gk} in the order added, so w(g₁) ≥ w(g₂) ≥ … ≥ w(gk). Because greedy considered every element (it skips only those that would create a conflict, or that weigh nothing), G is a basis. Let OPT = {o₁, …, ok} be a maximum-weight independent set, also a basis (so the same size k, by I3), sorted w(o₁) ≥ … ≥ w(ok). The whole proof is one inequality:

The staircase: greedy dominates the optimum coordinate-by-coordinate
w(gi) ≥ w(oi) for everyi ⟹ ∑i=1k w(gi) ≥ ∑i=1k w(oi)

Suppose the staircase fails. Let i be the first index where w(gi) < w(oi). Set A = {g₁, …, gi−1} and B = {o₁, …, oi}. Both are independent (heredity), and |A| = i−1 < i = |B|. By the exchange axiom there is an ot ∈ B∖A with A ∪ {ot} ∈ I. Since t ≤ i and OPT is sorted, w(ot) ≥ w(oi) > w(gi).

Now replay greedy. Everything greedy chose before gi is heavier than gi, hence heavier than ot's lower bound — so at the moment greedy considered ot (which it did, because w(ot) > w(gi) places ot earlier in the sorted order), its set in hand was a subset of A. By heredity that subset together with ot is independent, so greedy would have taken ot. Yet ot ∉ A — contradiction. Hence the staircase holds, w(G) ≥ w(OPT), and since OPT is optimal, equality: greedy is optimal. ∎

Direction ⟹ : if greedy is always optimal, M must be a matroid

The converse — why I3 is necessary, not merely convenient

Suppose M is downward-closed but not a matroid: I3 fails for some independent A, B with |A| < |B| where no element of B∖A can extend A. We build a weighting that fools greedy. Let a = |A|. Choose a small ε > 0 and assign:

  • weight 1 + ε to every element of A,
  • weight 1 to every element of B∖A,
  • weight 0 to everything else.

Greedy takes all of A first (heaviest), and now — by assumption — nothing in B∖A can be added, so greedy halts with weight a(1+ε). But B is independent with weight ≥ |B| ≥ a+1. For ε small enough, a+1 > a(1+ε), so B beats greedy. Greedy is not optimal for this weighting. Contrapositive: if greedy is optimal for every weighting, I3 must hold — M is a matroid. ∎

This is the deep content. For the standard weight-ordered greedy algorithm to work on every non-negative weighting of a downward-closed set system, the exchange axiom is the exact boundary. Outside it, some weighting defeats that algorithm; a particular greedy rule may still be valid for a particular problem.

The structure, not the objective, decides whether you may commit.— the lesson of Rado–Edmonds

The three canonical matroids

You almost never invent a matroid from scratch; you recognise one of three. Learn these and you can pattern-match most "is greedy safe?" questions on sight.

07 The boundary, made concrete

One structure greedy loves, one it cannot

Theory earns its keep when it predicts. Let me take the prerequisite you already trust — Kruskal's MST — and show it is greedy on the graphic matroid; then take the hook — 0/1 knapsack — and show its feasible family fails I3 at a single concrete spot. Same lens, opposite verdict.

Kruskal's MST is greedy on the graphic matroid

The forests of a graph form the graphic matroid M(G). Verify the axioms: the empty edge set is acyclic (I1); any subset of a forest is a forest (I2); and the augmentation — a forest with fewer edges has more components, so a larger forest must contain an edge joining two different components of the smaller one, addable without a cycle (I3). All three hold, so M(G) is a matroid, and greedy on it — sort edges by weight, add each that keeps the set acyclic — is optimal by Rado–Edmonds. That is exactly Kruskal. For a maximum-weight forest you sort descending and stop at non-positive edges:

def max_weight_forest(n, edges):        # edges: (w, u, v); graph may be disconnected
    parent = list(range(n))
    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]            # path halving
            x = parent[x]
        return x
    total, forest = 0, []
    for w, u, v in sorted(edges, reverse=True):    # heaviest edge first
        if w <= 0: break                            # negative edges never help a forest
        ru, rv = find(u), find(v)
        if ru != rv:                                # endpoints in different trees -> no cycle
            parent[ru] = rv
            total += w; forest.append((u, v))       # COMMIT the edge
    return total, forest

0/1 knapsack is not a matroid — and you can point to where

Now the hook, dissected. Forget the values for a moment and look only at which item-sets fit in the sack. That family — call a set independent if its total weight is within the capacity — is what greedy walks across.

The knapsack feasibility system
I= { S⊆E : ∑i∈S wi ≤W }

It satisfies I1 (the empty set fits) and I2 (drop an item and it still fits). Does it satisfy I3? Take capacity W = 10 and three items of weights 6, 5, 5. Let A = {6} and B = {5, 5}. Both fit, and |A| = 1 < 2 = |B| — so I3 demands some element of B slot into A. But 6 + 5 = 11 > 10 for either five. Nothing in B fits with the 6. The exchange axiom fails at this exact configuration.

The recognition habit

When a problem imposes a count cap or forbids cycles, check whether the feasible sets form a matroid. Budgets and compatibility constraints need more care. If a local commitment blocks a better combination, that greedy rule has failed; look for a different proof or model the alternatives with dynamic programming.

08 Where it breaks

Failure modes & common mistakes

This section marks the edge of the abstraction, where formal elegance stops describing the world. Memorise these traps; each is a place a confident greedy ships a wrong answer.

1 · "It passed my tests" is not a proof

Rado–Edmonds is a statement about every weighting. A non-matroid can let greedy win on a hundred random instances and lose on the hundred-and-first. The value-greedy on knapsack is correct on the famous (60,100,120) instance and wrong on (10,9,8)/weights(10,5,5). Never promote a passing test to a correctness claim — find the exchange proof or find the counterexample.

2 · Greedy-by-ratio on 0/1 knapsack

The seductive-but-wrong move from the hook. Density ordering is exactly optimal for fractional knapsack (you can take a sliver of the last item — an exchange argument proves it), and it is the canonical trap for 0/1, where indivisibility kills the swap. The fix is the pseudo-polynomial DP K[i][c] from Deep study 15.

3 · Weighted interval scheduling looks like a matroid and is not

Maximising the count of compatible intervals is the earliest-finish greedy we proved. Attach weights and the swap collapses: a single fat interval can outvalue the two it overlaps, so "earliest finish" — or "heaviest first," or any sort — can be beaten. Pairwise-disjoint sets are downward-closed but fail I3. This problem is DP (sort by finish, binary-search the predecessor) — it is Practice Problem 3 below.

4 · Non-canonical coin systems

Greedy change-making (take the largest coin ≤ remaining) is optimal for {1, 5, 10, 25} but wrong for {1, 3, 4} making 6: greedy gives 4 + 1 + 1 = three coins, the optimum is 3 + 3 = two. Coin sets are not matroids; canonical currencies are a lucky special case, not a law. Arbitrary denominations need DP.

5 · Confusing "an optimal solution is greedy" with "greedy is unique"

The exchange argument proves some optimum agrees with the greedy choice, not that the greedy solution is the only optimum. Ties are normal (Fig 3's augmenting edge could have been a different equal-weight edge). The value is unique; the witnessing set need not be.

6 · The boundary of greedy itself: matroid intersection

Greedy conquers one matroid. The intersection of two matroids — e.g. bipartite matching, which is a partition matroid on the left vertices intersected with one on the right — is generally not a matroid, and plain greedy fails on it. Such problems need augmenting-path algorithms (matroid intersection, flows), a genuinely harder regime. Knowing greedy stops here is part of mastering it.

The diagnostic, in one move

Ask: can this particular local commitment lock out a better combination? A matroid guarantees the standard weight-ordered rule for every non-negative weighting. Outside that setting, a problem-specific exchange proof may still work, as in unweighted interval scheduling. If a counterexample defeats your rule, revise the rule or consider dynamic programming.

09 Practice

Four problems — prove it, or break it

P1Job Sequencing with Deadlinesscheduling matroid

You are given n jobs; job i has an integer deadline di ≥ 1 and a profit pi > 0. Each job takes exactly one unit of time and there is a single machine, so at most one job runs per time slot 1, 2, 3, …. A job earns its profit only if it is scheduled in some slot ≤ di. Choose a subset and a schedule maximising total profit.

maxProfitJobScheduling(jobs: List[[deadline, profit]]) -> int # returns max total profit

Example: jobs = [[2,100],[1,19],[2,27],[1,25],[3,15]] Answer: 142 (run profit-100 in slot 2, profit-27 in slot 1, profit-15 in slot 3) Constraints: 1 <= n <= 1e5 · 1 <= di <= n · 1 <= pi <= 1e9

greedy is provably optimal   State the matroid whose independent sets are the schedulable job-subsets, then prove your greedy correct by its exchange axiom.

P2Minimum Maximum Latenessexchange argument

A single machine must process n jobs, all available at time 0, no preemption. Job i has processing time ti and due date di. In a chosen order, job i completes at Ci (the running sum of processing times up to and including it) and incurs lateness Li = Ci − di. Return the minimum possible value of the maximum lateness maxi Li.

minMaxLateness(jobs: List[[t, d]]) -> int # minimise the worst lateness

Example: jobs = [[3,6],[2,8],[1,9],[4,9]] Answer: 1 (Earliest-Due-Date order; verify the schedule yourself) Constraints: 1 <= n <= 1e5 · 1 <= ti, di <= 1e9 · lateness may be negative

greedy is provably optimal   Conjecture the ordering, then prove it by the adjacent-inversion exchange: show swapping an out-of-order adjacent pair never raises the maximum lateness.

P3Weighted Interval Schedulinggreedy fails → DP

Given n intervals, interval i is [starti, endi) with weight wi > 0. Choose a subset of pairwise non-overlapping intervals (touching at an endpoint is allowed) maximising the total weight. Return that maximum weight.

maxWeightIntervals(intervals: List[[start, end, weight]]) -> int

Example: intervals = [[1,4,100],[1,2,1],[3,5,1]] Answer: 100 (the single fat interval beats the two thin ones — earliest-finish greedy returns 2) Constraints: 1 <= n <= 1e5 · coordinates up to 1e9

greedy is NOT safe   First exhibit an instance where earliest-finish (and heaviest-first) greedy lose, arguing which axiom breaks; then give an O(n log n) DP using sort-by-finish plus a binary-searched predecessor.

P4Maximum-Weight Forestgraphic matroid

An undirected graph has n vertices and edges [u, v, w] with possibly negative weights. Choose a subset of edges containing no cycle (a forest — the graph need not stay connected and you are not required to span every vertex) that maximises total weight. Return that maximum weight.

maxWeightForest(n: int, edges: List[[u, v, w]]) -> int

Example: n = 4, edges = [[0,1,5],[1,2,4],[0,3,3],[2,3,-2]] Answer: 12 (take the +5, +4, +3 edges as a tree on all four vertices; discard the −2 edge — non-positive and cycle-closing) Constraints: 1 <= n <= 1e5 · weights may be negative

greedy is provably optimal   Name the matroid, verify its three axioms (especially the augmentation that makes I3 hold for forests), and explain why every non-positive edge is safely discarded.

10 Recap & next

The one thing to remember

A matroid is the exact condition for weight-ordered greedy to work for every non-negative weighting of a downward-closed set system. The exchange axiom makes each chosen element safe. Other greedy algorithms can still be optimal for a particular objective when a separate exchange proof applies, as with earliest-finish interval scheduling. A counterexample to your chosen rule is a signal to rethink the rule or use dynamic programming.

Three reflexes to carry forward. (1) Before coding a greedy rule, hunt for a proof of the local choice. (2) Test whether a uniform, partition, graphic, or other matroid models the feasible sets; Kruskal is a graphic-matroid example. (3) Use a counterexample to discard an unsafe rule, then seek a better rule or a dynamic program.
